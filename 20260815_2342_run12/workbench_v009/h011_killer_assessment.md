# h-011 协议阶段线索因子实验判定

## 实验规模

- 模型：`qwen3:4b`、`qwen3:8b`、`qwen2.5:7b`
- 4 个领域 × 2 套表面命名 = 8 个任务
- 每模型 12 条件、96 个首动作单元；总计 288 个单元
- 所有模型调用成功，无解析错误

每个缺口条件都固定三个明确义务、三个写入成功回执和前两项独立读取通过；第三项真实缺失且未读。仅改变最后插入的协议事件。

## 预注册机制检验

h-011 的存活签名要求“协调摘要×当前动作绑定”显著高提交，同时无关动作摘要、当前动作审计、重复读取和普通消息接近无事件基线。结果相反：

- 当前动作审计、通用记录和普通事件消息均为 24/24 危险提交；
- 无动作绑定摘要仍为 20/24，无关动作摘要仍为 19/24；
- `NOT_READY` 的方向在三个模型间完全不一致；
- qwen3:8b 甚至把第三次、但重复同一义务的读取在 7/8 条件中当成足够进度。

因此不能把结果解释为模型理解了特定的协议阶段边界、当前动作绑定或状态极性。更弱的事实是：在当前模拟提示中，加入几乎任何非读取的工作流记录都会使模型把部分核验阶段推进到提交；这一事实没有足够组件特异性，并可能由通用最近性、进度计数或记录事件模板共同造成。

## 与先行和同 Run 历史的关系

- P076 已证明错误/成功元数据可经代理洗白并改变编排器控制流；当前结果没有提供比“元数据会控制流程”更窄且稳定的机制。
- arXiv:2608.02464 已用 `required_coverage` 确认每个必需调用是否执行，并跨真实工具、独立种子与模型验证；遗漏检测和修复不开放。
- h-003 已测试工具别名与同一工具等次数重复，未发现身份特异差分，并记录了重复多数偏置；qwen3:8b 的读取次数替代身份只在单模型出现，不能独立复活该路线。
- ToolGate 的完整前置条件门仍可机械吸收所有危险提交，不能作为新方法。

## 状态决定

`h-011 → falsified`。

直接原因：无关动作、非摘要工具和普通消息同样大量触发提交，违反预注册的协议语义特异性；重复读取的身份—次数错觉又不能跨三个模型复现。

# h-007 分页闭合 Scratch 杀手试验

## 有效执行与夹具边界

- 实现：`workbench_v005/pagination_closure_pilot.py`
- 数据：库存、工单、部署三个域；每域固定六条记录，分别测试后页存在、真正缺失和全量枚举。
- 条件：单页、每页两条的分页、分页加显式完备性提醒。
- 模型：`qwen3:4b`、`qwen3:8b`；温度 0；每条轨迹最多六次模型动作。
- 工具环境机械提供稳定快照、`has_more` 和 `next_cursor`，评价不使用语言模型裁判。

首个 `qwen3:4b` 批次 `pagination_qwen3_4b.jsonl` 因夹具只接受 JSON 空值、不接受模型输出的字符串 `"null"` 而产生非法游标；该批次在三条任务后被中止并保留，不进入科研统计。修正仅把空字符串、`null` 和 `none` 规范化为空游标，重跑结果写入新文件，未覆盖原日志。

## 结果

### qwen3:8b

- 单页准确率：1.000（9/9）。
- 普通分页准确率：1.000（9/9）。
- 分页提醒准确率：1.000（9/9）。
- 普通分页和提醒分页都在每条任务中读取三页；未穷尽游标时的全局结论提交率均为 0。

### qwen3:4b

- 单页准确率：0，模型在终页后反复调用直至步数上限，属于一般工具循环结束失败。
- 普通分页准确率：0.667；分页提醒准确率：0.222。
- 三个条件的未穷尽全局结论提交率均为 0；错误来自终页后的结束控制、目标整合或枚举，而不是当前页未找到即提前否定。

## 裁决

预注册的核心现象没有出现。较强的 `qwen3:8b` 完全不受分页边界影响，较弱的 `qwen3:4b` 也没有无证据提前闭合。提醒没有提供一致恢复，说明不能把一般小模型控制错误重命名为分页特有机制。

h-007 被 `falsified`。这次 Scratch 只杀死“清晰分页契约下存在稳定提前闭合”的主张，不否认真实 API 中截断、游标漂移、跨页重复或调用预算不足会造成完整性问题。

# v012 异步未来语义依赖路线裁决

- 日期：2026-08-13
- 科学版本：v012
- 权威：主研究者裁决；Research Subagent 报告仅为非权威输入。
- 结论：问题成立，但当前方法核在实现前发生方法级先行碰撞；不构成 Run 终局，继续正交扩张。

## 1. 成立的问题

AsyncFC（arXiv:2605.15077v1）把任务依赖图的边分为数据/状态依赖，以及“模型必须先观察一个执行结果，才能生成下一调用”的依赖；实际调度器只落实资源读写重叠、调用参数引用未决 future 和资源路径引用前序结果。

因此存在一个真实盲区：前序结果可能决定后续调用是否存在、调用哪个工具、作用于哪个对象或是否产生副作用，而后续参数本身不引用 future。保守串行物理执行也不能消除这个盲区，因为第二个调用可能已经在只见占位符时被模型决定并排队。

## 2. 被淘汰的计算核

当前拟议计算是：给同一未决 future 构造若干反事实完成值，固定既往动作并教师强制重放策略，将各分支下一调用正规化为工具、目标和效果；只有全部分支的动作签名一致时才提前发射，否则等待。

该计算的输入替换、教师强制影子重放、调用等价比较和执行/阻塞输出，与 AttriGuard（arXiv:2603.10749v2）的控制衰减观察、教师强制重放和工具调用存活门控近乎逐项同构。把干预变量从“不可信观察”改成“future 的可能完成值”，再接到 AsyncFC 前，不形成不可约的新计算。

安全执行部分也已被更强的直接基线吸收：

- PASTE 只在权威调用与推测调用匹配后提交，并把推测结果隔离在权威会话之外；
- Speculative Actions 使用语义确认、沙箱、幂等、可逆或回滚边界；
- Speculative Interaction Agents 已处理后到信息导致的调用修改、删除、级联取消和敏感调用等待；
- Cost-Aware Speculative Execution 将既非无副作用、非幂等、也不能置于提交屏障后的操作直接标为不可推测。

所以当前方案相对公平基线只剩“用多个语言模型重放，减少错误推测或不必要等待”的高成本筛选策略。它没有改变可安全提交的动作集合，且可能用固定增加的重放成本吞噬异步时延收益。

## 3. 识别性杀线

在 future 完成前，当前方案没有可审计方式得到全部可行结果类、未覆盖质量、分支概率或覆盖风险。随意生成两个结果不能支持“对所有完成值不变”；使用真实完成值又失去提前判定的时延机会；多 future 的结果类还会形成笛卡尔积。

这不是普通实现缺口。若没有新的结果空间抽象与覆盖计算，候选只能写成“AsyncFC + AttriGuard 式反事实重放 + 已知提交屏障”。因此不注册 Hypothesis，不运行 48 情形杀手实验，不启动固定 Reviewer。

## 4. 条件性窄楔子与反复活规则

唯一可能重开的对象不是反事实重放门，而是独立的“工具输出抽象商空间编译”：从可执行输出模式、错误码、历史真实输出与状态约束形成有限抽象域，显式估计未覆盖风险，并以三值 `ALLOW / WAIT / UNKNOWN` 计算所有可行结果类上的必然动作不变性。

该对象只有同时满足以下条件才允许重新审计：

1. 结果类不由同一语言模型任意生成，也不读取真实 future、任务答案或隐藏终局；
2. 对未见合法结果类有保守 `UNKNOWN` 或可验证风险界；
3. 与同结果集合、同重放预算的 `AsyncFC + AttriGuard-port` 相比改变接受集合或成本—正确性前沿；
4. 对不可逆或外部可观察操作仍遵守隔离、暂存或不推测边界；
5. 在隐藏结果类和公开异步工具环境上，净时延/成本优于同步等待与安全推测强基线。

在这些条件出现前，不得以“语义 future 依赖”“控制依赖证书”“多分支不变性”或新的中间件载体复活当前路线。

# v009 查询答案韧性到证据停止的机制迁移审计

## 审计结论

- `transfer_id`: TR-v009-001
- `verdict`: `reframe-keep-for-killer-experiment`
- `shallow_analogy_risk`: 高

迁移在一个受限层面结构同构：若把已经抽取出的证据—子主张图视为单调查询的 lineage，那么“删除最少多少个独立证据根会使当前答案失去全部完整见证”就是数据库查询答案 resilience 的直接实例。该计算不能被称为新的图算法。

可暂存的新问题不是 min-cut 本身，而是把它变成开放式搜索智能体的在线控制量：当前证据图若只有单点脆弱见证，不允许因答案形态完整而停止；下一次检索选择应增加互不相交的完整见证，或找到能击穿当前见证的反证。是否足以构成新方法，必须由最近先行与最小实验共同反证。

## Source pattern

- `source_pattern`: 数据库查询答案韧性、因果责任与 how-provenance。
- `source_failure_structure`: 一个查询答案可能由少数输入元组脆弱地支撑；删除某个小集合即可让答案消失。只报告答案或任一 witness 不刻画这种脆弱性。
- `source_changed_computation`: 不是计算答案置信度，而是对 query lineage 做反事实删除，求使答案失效的最小输入集合；等价地衡量答案对源元组删除的韧性。
- 一级来源：Freire 等《A Characterization of the Complexity of Resilience and Responsibility for Self-join-free Conjunctive Queries》（PVLDB 2015，arXiv:1507.00674）把 resilience 定义为删除最少输入元组使布尔查询为假，并给出复杂度分类；查询 provenance、删除传播和因果责任形成其方法谱系。

## Target intervention

- `target_failure_structure`: 深度研究智能体检索到一个直接给出答案的错误总结后提前停止；这个答案通常只有一个脆弱的“断言见证”，而真实答案需要完成一个或多个底层记录链。DRNoise 的配对实验显示，错误总结使 GPT-5.4 平均搜索次数由 7.1 降到 4.5，完整真实路线由 45% 降到 16%。
- `target_intervention`: 把问题、候选答案、原子子主张、证据片段、推导关系和来源根组成支持超图；折叠明确复制或共同上游后，对每个候选答案计算根韧性 `rho(a)`：删除最少多少个独立证据根会破坏其所有完整支持见证。只有必要子主张闭合、`rho(a) > b` 且没有同韧性竞争答案时才停止；否则检索使当前最小割增大或检索能区分竞争答案的缺失原子。
- `changed_computation_preserved`: 是。在固定且正确的支持图上，目标计算仍是对 lineage 做最小删除反事实，而不是把来源数、置信度或语言模型主观充分性当代理。

## 结构对应

| 数据库 resilience | 证据停止 |
|---|---|
| 输入元组 | 证据根或经来源折叠后的记录单元 |
| 合取查询原子 | 问题所需的原子子主张/连接条件 |
| 一个 query witness | 一条从证据根到候选答案的完整支持推导 |
| how-provenance | 证据支持超图/布尔 lineage |
| 删除元组使答案为假 | 删除证据根使候选答案失去全部完整支持 |
| resilience | 根韧性停止量 |

结构匹配只对“已抽取图上的支持”成立；它不自动等于世界真值。

## 必需假设

1. 问题可被分解为有限、可观察的必要原子与连接关系。
2. 支持边的方向和蕴含关系足够准确；语言模型不能把重复断言误标为底层记录。
3. 显式来源、引用或相似性至少能识别一部分复制/共同上游；未知依赖不能被当成已证明独立。
4. 当前任务的正确答案存在可达的多个互不相交见证，或系统允许在韧性不足时弃权。
5. 攻击预算 `b` 是声明的鲁棒性边界，不是世界错误上界。
6. 检索动作能够按缺失原子或割集目标形成有效查询，而非只增加同源重复页面。

## 最近先行风险

- Argus 已维护支持/反驳证据图、检查缺失项和未解冲突、定向派发搜索并基于完成图合成答案。
- S2G-RAG 已在每轮判断证据是否足够，不足时输出结构化 gap 并转为下一检索查询。
- CaRR 已把问题拆成可验证单跳 rubric，并要求到答案的完整证据链。
- GAVEL 已要求原子子主张绑定细粒度证据，机械检查引用标识和文本跨度，再选择充分证据集。
- SURE-RAG 已把证据充分性作为集合性质，聚合覆盖、关系强度、分歧、冲突和检索不确定性作三值裁决。
- CounterRefine 已从草稿答案出发检索支持与冲突证据，再做 KEEP/REVISE。
- 经典 truth discovery 已处理来源可靠性、复制依赖与预算化来源选择。
- 数据库 resilience 已占据最小删除、lineage 与复杂度本身。

因此，候选只有在“最小独立根割作为停止/查询目标”改变了 Argus/S2G/SURE-RAG 的接受集合，并在非攻击泄漏条件下降低单文档诱导错误时才可能存活。

## 最小反证实验

构造独立于方法生成器的静态搜索环境，至少包含：

- 一个直接错误总结；
- 两条互不相交的真实记录链；
- 同源改写与独立来源对照；
- 单一真实权威记录的负对照，检验过度拒绝；
- 无足够证据的弃权对照。

同一个本地语言模型、同一 BM25/向量检索接口和相同检索次数下比较：

1. 普通 ReAct；
2. 通用验证提示；
3. 两引用规则；
4. S2G 式充分性/gap judge；
5. CounterRefine 式答案条件化反证检索；
6. 不折叠来源的文档计数/韧性；
7. 独立根韧性控制器。

评价用生成时固定、运行时不可见的记录级终局：答案准确率、条件服从率、正确任务覆盖率、弃权率、额外检索数、错误答案被单一证据根支配的比例。必须分别报告干净与诱导条件，不能只报告总体提升。

## 失效条件

出现任一情况即 kill：

1. 最近先行已经在自然语言证据图上计算最小来源删除割，并用它控制智能体停止与下一查询。
2. 实现中的 `rho` 只是引用数、域名数、语言模型置信度或人工 route 标签。
3. 不使用真实/人工 route 标签时无法构图，收益来自基准泄漏。
4. 同预算 S2G/Argus/CounterRefine 或简单两引用规则达到同样接受集合与终局表现。
5. 来源折叠不能优于不折叠文档计数，或把同源改写稳定误当独立支持。
6. 单一真实权威记录导致大规模不必要弃权，且无法通过风险条件化边界修复。
7. 迁移后的唯一新意仍是数据库 resilience 改名，没有新的在线推断、动作选择或可验证性质。

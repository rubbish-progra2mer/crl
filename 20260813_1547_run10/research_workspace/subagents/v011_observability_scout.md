## 核心结论

**建议杀死当前候选，而且杀伤范围是方法核，不只是当前实现。置信度：高。**

候选的核心计算可精确约化为已有的“离散函数求值决策树”或“等价类判定”：

1. 当前轨迹下仍可能的隐藏世界是候选假设集合；
2. 拟执行动作在每个世界中的 `ALLOW/DENY` 判定是待求值的离散函数；
3. 每个只读工具查询是一个带成本、按隐藏世界返回结果的测试；
4. “存在两个观察等价、动作判定相反的世界”恰好等价于该函数在当前版本空间上尚非常数；
5. “选择最小成本查询序列，直到所有剩余世界判定一致”恰好是最优决策树、等价类判定或带感知动作的条件规划终止条件。

因此，`可能世界 -> 相反决策对 -> 最小区分查询 -> 一致后放行` 不是新的计算。把“诊断/决策树/部分可观测规划”接到“工具调用拦截器”上，也已被 ToolGate、PolicyGuard、求解器辅助策略验证、PCAS、SAGE-Agent 等智能体工作覆盖了大部分接口。当前尚未出现能与这些谱系分离的智能体专属新算子。

唯一可能的研究难点是：从开放式自然语言任务、工具契约、策略文本和轨迹中，**自动且可靠地编译出完备的可能世界、动作判定函数和查询结果模型**。但这不是当前候选已给出的新计算；它又会立即撞上动作/观测模型学习、策略编译和形式化规范抽取，并且若没有外部独立标注，所谓“证书”只能证明自生成模型内的性质，不能证明真实工具世界中的安全或正确。

## 候选的精确定义与一行约化

令：

- $H_t$：与任务、轨迹、工具返回和契约一致的当前可能世界集合；
- $d_a(h)\in\{\mathrm{ALLOW},\mathrm{DENY}\}$：在世界 $h$ 中执行动作 $a$ 的正确判定；
- $q\in Q$：只读查询，结果为 $q(h)$，成本为 $c(q)$；
- $V(o_{1:k})=\{h\in H_t: q_i(h)=o_i,\ i=1,\ldots,k\}$：执行查询后的版本空间。

候选策略在且仅在 $d_a$ 在 $V$ 上为常数时终止；若常数为 `ALLOW` 则执行，否则阻断。若不是常数，则选择后续查询以最小化期望或最坏查询成本。

把未知输入设为 $h$，把待求离散函数设为 $f(h)=d_a(h)$，把可查询变量设为 $q(h)$，就得到标准的**离散函数求值决策树**。候选要求的“相反决策世界对”就是决策树文献中仍未被测试分开的异类样本对。若给世界先验并允许噪声，则得到**等价类判定**；若查询可改变可达状态、存在非确定效应或需要多步到达可观测位置，则得到**部分可观测条件规划/强规划**。

这不是“概念相似”，而是输入、状态更新、停止条件与输出策略的逐项同构。

## 经典与相邻理论：输入—计算—输出碰撞

### 1. Cicalese、Laber、Saettler：离散函数求值决策树

- 一手来源：[Decision Trees for Function Evaluation — Simultaneous Optimization of Worst and Expected Cost](https://arxiv.org/abs/1309.2796)，以及 [Trading off Worst and Expected Cost in Decision Tree Problems](https://arxiv.org/abs/1406.3655)。
- 输入：有限个可能变量赋值、目标离散函数、可读取变量及读取成本，可选先验。
- 计算：自适应读取变量，直到已读值唯一确定目标函数值；优化最坏成本或期望成本。
- 输出：一棵条件决策树。
- 碰撞：**exact collision**。世界对应变量赋值，动作安全/正确性对应目标函数，工具查询对应变量读取。无先验、要求最坏情形安全，仍被其最坏成本目标直接覆盖。

### 2. Golovin、Krause、Ray：等价类判定与 EC²

- 一手来源：[Near-Optimal Bayesian Active Learning with Noisy Observations](https://arxiv.org/abs/1010.3091)，NeurIPS 2010。
- 输入：带先验的假设集合、带成本测试及其结果模型，把假设划分成若干决策等价类。
- 计算：维护与观察一致的版本空间；只切分属于不同等价类的假设对；以成本归一化的跨类边切除收益选择下一测试；当版本空间落入同一类时停止。
- 输出：近似最小期望成本的自适应测试策略及决策类。
- 碰撞：**exact collision**。将世界按 $d_a(h)$ 分成 `ALLOW` 和 `DENY` 两类后，候选的停止条件与 EC² 完全一致。论文还明确覆盖非均匀测试成本、噪声与相关噪声，因此仅增加“工具返回不可靠”也不能形成楔子。

### 3. Bertoli 等：部分可观测强规划

- 一手来源：[Strong Planning under Partial Observability](https://doi.org/10.1016/j.artint.2006.01.004)，Artificial Intelligence 2006；另见 [Computing Contingent Plans via Fully Observable Non-Deterministic Planning](https://doi.org/10.1609/aaai.v28i1.9049)，AAAI 2014。
- 输入：多个可能初始状态、非确定动作效应、部分观察与目标集合。
- 计算：在信念状态/可能世界集合上做 AND-OR 或符号搜索，感知结果产生条件分支；要求所有分支成功。
- 输出：无论真实隐藏状态和非确定结果如何均达成目标的条件计划。
- 碰撞：**exact superset / method-level collision**。候选是只有“只读感知动作 + 一个终止动作判定”的退化条件规划实例；若查询之间存在状态依赖，强规划反而更完整。

### 4. Huang 等：强计划的观察约简

- 一手来源：[Observation Reduction for Strong Plans](https://www.ijcai.org/Proceedings/07/Papers/311.pdf)，IJCAI 2007。
- 输入：全可观测强计划（状态—动作表）、观察变量集合和观察函数。
- 计算：删除不能区分下一动作的观察变量，并在每一步只保留选择正确动作所需的观察。
- 输出：近似最小观察集合及基于这些观察分支的条件计划。
- 碰撞：**exact component collision**。其关键判据是：若当前信念集合中的所有状态选择同一动作，就无需继续观测；这正是候选的“决策一致性”停止条件。

### 5. 可观测性/主动监测合成

- 一手来源：[Symbolic Synthesis of Observability Requirements for Diagnosability](https://doi.org/10.1609/aaai.v26i1.8225)；[Sensor Synthesis for POMDPs with Reachability Objectives](https://doi.org/10.1609/icaps.v28i1.13875)；[Active Monitoring with RTLola](https://finkbeiner.groups.cispa.de/publications/2025-active-monitoring-with-rtlola-a-specification-guided-scheduling-approach/)。
- 输入：部分可观测系统、诊断/可达/监测规范、候选观察及成本或带宽。
- 计算：符号模型检查、SAT 或规范驱动调度，合成足以诊断/达成目标/尽早发现违反的观察配置。
- 输出：最小或低成本观察集合、传感器配置或主动采样计划。
- 碰撞：**partial/component collision**。这些工作不是大语言模型智能体，但已占据“规范条件化、成本约束的主动可观测性合成”算子。

## 智能体最近工作：输入—计算—输出碰撞

### 6. ToolGate

- 一手来源：[ToolGate: Contract-Grounded and Verified Tool Execution for LLMs](https://arxiv.org/abs/2601.04688)，2026。
- 输入：受信任的类型化符号状态、候选工具、每个工具的 Hoare 风格前置/后置条件。
- 计算：先按前置条件过滤可调用工具，执行后按后置条件验证结果，只有验证通过才提交符号状态。
- 输出：允许的工具调用、接受/拒绝结果和验证后的状态。
- 碰撞：**partial method collision**。它没有在“不知道前置条件真假”时合成最小查询，但已经覆盖候选的工具契约、执行前门控、验证后提交与可信状态维护。

### 7. PolicyGuard

- 一手来源：[PolicyGuard: A Dialogue-Grounded Sub-Agent Verifier for Policy Adherence in LLM Agents](https://arxiv.org/abs/2606.29225)，2026。
- 输入：待执行的变更型工具调用、完整对话、原始业务策略、按工具生成的检查清单。
- 计算：逐条判断前置要求是否满足；数据验证要求会指向应当已经调用的具体只读工具，程序性要求会检查是否已经取得确认；阻断时生成“缺失前置条件/下一问题”的对话特定补救。
- 输出：`Pass` 或 `Block + remediation`。
- 碰撞：**strong partial collision / nearest agent work**。它已实现“不可逆动作前拦截 + 从完整轨迹识别缺失证据 + 告诉智能体下一次读取或询问什么”。候选只把其概率式大语言模型验证器替换为可能世界和最优测试策略，而后者又被经典决策树/条件规划精确占据。

### 8. 求解器辅助验证、AgentSpec 与 PCAS

- 一手来源：[Solver-Aided Verification of Policy Compliance in Tool-Augmented LLM Agents](https://arxiv.org/abs/2603.20449)、[AgentSpec](https://arxiv.org/abs/2503.18666)、[Policy Compiler for Secure Agentic Systems](https://arxiv.org/abs/2602.16708)。
- 输入：自然语言或声明式策略、智能体可见状态/事件依赖图、待执行工具调用。
- 计算：把策略编译成 SMT、领域专用规则或 Datalog；在调用前由求解器/参考监视器判断是否满足约束，反例或规则失败触发阻断和反馈。
- 输出：允许/拒绝与结构化反馈。
- 碰撞：**component collision**。候选的“存在相反安全结论的可能世界”可直接表示为满足当前观察且令动作前置条件为假的 SMT 反模型；仅把反模型解释成“证书”不是新计算。

### 9. SAGE-Agent

- 一手来源：[Structured Uncertainty Guided Clarification for LLM Agents](https://arxiv.org/abs/2511.08798)，2025。
- 输入：结构化工具调用候选、参数联合不确定性、候选澄清问题与问题成本。
- 计算：把澄清建模为 POMDP，以成本惩罚的期望完美信息价值选择问题；在“继续执行最可能调用”和“询问”之间决策。
- 输出：澄清问题或工具执行。
- 碰撞：**strong partial/method collision**。它只覆盖用户意图与工具参数不确定性，且用概率而非最坏世界一致性，但“决策条件化的主动询问 + 成本”已经存在于工具型智能体方法中。

### 10. 信息增益澄清

- 一手来源：[Uncertainty-Aware Clarification in LLM Agents with Information Gain](https://arxiv.org/abs/2606.03135)，2026。
- 输入：$\tau$-Bench 工具轨迹、潜在用户目标、候选澄清问题。
- 计算：以澄清前后对真实目标的教师强制对数似然变化近似信息增益，并训练澄清策略选择何时问、问什么。
- 输出：执行反馈条件化的澄清问题或不干预。
- 碰撞：**partial collision**。它不是形式证书，并在训练期使用目标真值；但进一步压缩了“轨迹后主动询问”的智能体专属空间。

### 11. Verified Tool Calls

- 一手来源：[Verified Tool Calls Improve LLM Agent Reliability Under Non-Atomic Failures](https://arxiv.org/abs/2608.02645)，2026。
- 输入：状态变更型工具调用、幂等键、调用后可执行的后置条件验证器。
- 计算：执行后验证真实效果；遇到超时/模糊返回时先查询后置状态，再决定是否重试，幂等键抑制重复副作用。
- 输出：确认成功、重试或失败。
- 碰撞：**component collision**。其验证查询主要发生在动作之后或重试之前，不覆盖候选的通用执行前可能世界搜索，但覆盖了“先只读核实，再决定是否发出另一不可逆动作”的重要子情形。

### 12. Cordon

- 一手来源：[Cordon: Semantic Transactions for Tool-Using LLM Agents](https://arxiv.org/abs/2606.17573)，2026。
- 输入：任务级工具意图、结果血缘、授权、影子状态与待释放外部效果。
- 计算：可逆变更在影子状态执行，外向效果进入 outbox；把血缘、授权、暂存状态和效果作为整体校验，之后提交或中止。
- 输出：提交后的外部效果或无副作用的中止/恢复记录。
- 碰撞：**partial collision**。它通过暂存把“不可逆动作前查询”的紧迫性降为提交期验证。只有不能暂存的外部效果仍需要候选式前置判断，但该判断本身仍是已有决策树/强规划。

### 13. AgentCheck

- 一手来源：[AgentCheck: A Reproduce–Intervene–Mitigate Workbench for LLM Agents over MCP](https://arxiv.org/abs/2607.11098)，2026。
- 输入：真实工具轨迹、指定工具返回、12 类故障注入器与待测缓解方案。
- 计算：固定其他工具响应，只扰动一个返回；回放到分叉点后恢复在线执行，比较干净/故障/缓解轨迹。
- 输出：可复现故障对、通过/失败与故障类型分析。
- 碰撞：**no method collision; useful evaluation component**。它适合为候选制造陈旧、不完整、语义错误观察，但不做运行时查询合成。

### 14. When2Tool 等主动工具选择

- 一手来源：[LLM Agents Already Know When to Call Tools](https://arxiv.org/abs/2605.09252)，2026。
- 输入：问题及模型生成前隐藏状态。
- 计算：用线性探针判断工具是否必要，并以预填充语句引导调用/不调用。
- 输出：调用工具或直接回答。
- 碰撞：**weak component collision**。它优化“是否需要工具”，不是“哪个读取可区分相反动作判定”，不能单独杀死候选；但主动工具门控也不是空白领域。

## 基准与独立终局

### AppWorld-UL：首选公开基准

- 一手来源：[AppWorld-UL: Benchmarking Diverse Agent-User Interactions for Tool-Use](https://arxiv.org/abs/2607.20536)，2026。
- 516 个用户在环任务，显式覆盖欠规格、不可行与需确认三类情形及其组合；环境包含 9 个应用、约 475 个接口、长程状态变更与程序化终局。
- 其任务构造明确把关键信息从指令或环境中移除，形成只有询问用户或读取环境才能消除的信息缺口；“需确认”子集还直接引入高成本或不可逆效果。
- 独立终局可用交互任务完成率/场景完成率、程序化数据库断言、是否出现未预期状态变化、是否取得所需用户信息。方法不得看到任务知识集或评测代码。
- 结论：**benchmark fit 很强，但它是评测资产，不提供方法新颖性。**

### $\tau^2$-Bench / $\tau$-Bench：第二基准

- 一手来源：[$\tau$-Bench](https://arxiv.org/abs/2406.12045) 与 [官方评测说明](https://github.com/sierra-research/tau2-bench/blob/main/docs/evaluation.md)。
- 环境提供业务策略、用户对话、只读/变更型接口和隐藏数据库；终局按数据库目标状态与交流要求独立判断。
- PolicyGuard、求解器辅助验证、PCAS 和信息增益澄清都已在这一基准族上运行。因此若使用它，必须把这些工作纳入强基线，而不能只比 ReAct、自洽或“是否询问”的提示基线。

## 若强行保留，最小公平强基线

当前不建议实现。但若主研究者要做最后一次救援，至少需要同信息、同查询预算的下列基线：

1. **最优函数求值决策树/最优条件策略**：在同一 $H_t,d_a,Q,c$ 上求精确最优或可证明近似策略；这是必须基线，不可用信息增益贪心代替。
2. **EC²**：有先验、噪声或相关查询结果时的决策等价类基线。
3. **PolicyGuard / Solver-Aided**：同一策略文本、对话和工具文档下的执行前拦截与补救。
4. **ToolGate**：同一显式契约和可信符号状态下的前置/后置门控。
5. **全读取、无读取、固定确认、随机读取**：用于分离查询预算收益，但不能承担最近工作比较。

如果候选相对最优决策树的差异只是启发式搜索、提示生成问题或压缩上下文，则最多是工程近似；需要另有复杂度、规模、泛化或可靠性上的实质新算法，才可能重开方法价值。

## 最小高信息量杀手检查

无需先做大规模智能体实验即可检查方法核：

1. 从 AppWorld-UL 的 `train/dev` 选取 10–20 个欠规格/需确认任务，另构造一个 8–32 世界的小型人工实例；只用公开给智能体的只读接口和策略，不使用测试真值。
2. 由独立人工标注 $H,d_a,q(h),c(q)$，把“自动编译世界模型”的误差与“查询调度算法”的误差分开。
3. 分别运行候选调度器与精确最优决策树；逐节点比较剩余世界、停止判定、下一查询和最坏/期望成本。
4. 再把同一实例编码成条件规划或 EC²，检查策略树是否同构。
5. 单独评测自动编译器：在不看隐藏终局的情况下，能否召回所有相反判定世界对、预测所有只读查询结果域、并保证放行时没有遗漏的 `DENY` 世界。

**杀死条件：**

- 在固定 $H,d_a,Q,c$ 后，候选策略与最优决策树/EC²/条件规划只是同构或近似实现；
- 对强基线的收益只来自更多查询、额外工具权限、测试真值、隐藏数据库或更强模型；
- 任一“证书允许执行”样例仍存在被独立标注遗漏的 `DENY` 世界；
- 自动世界/查询模型的正确性由同一个大语言模型自评，没有独立终局或人工/程序标注；
- 改名为“反事实差分”“可观测性证书”“决策一致性”后仍没有新的状态表示、查询选择目标、求解算法或可证明边界。

上述第一项已由形式化映射满足，因此当前候选在概念层已经足以判杀。实验仅用于验证实现是否真的只是该映射，不应被当作新颖性发现手段。

## 可重开所需的真正窄楔子

当前没有发现可直接保留的窄楔子。未来只有同时满足以下条件才值得以**不同候选**重开：

1. 面向开放式工具生态，提出一种对隐式巨大可能世界进行查询合成的新算法；相对 ODT/EC²/条件规划有明确改变的计算与可证明/可测的规模优势；
2. 从自然语言策略、接口契约和轨迹编译 $d_a$ 与查询模型时，有独立校验或保守完备边界，而不是由同一大语言模型生成再自证；
3. 与 PolicyGuard 的“缺失前置条件/下一读取”、SAGE 的成本化主动澄清和 Solver-Aided 的反模型相比，能给出组件级不可吸收差异；
4. 在 AppWorld-UL 或 $\tau^2$-Bench 上，评价终局来自隐藏数据库/程序断言，候选不接触评测真值，并且优于上述强基线而不是只优于提示法。

满足这些条件的核心将是“可验证的开放式规范—查询模型编译”或“隐式超大信念空间的新求解器”，已不再是当前的决策条件化可观测性证书。

## 反复复活禁止规则

- 不得把“版本空间落入同一动作等价类”换名为“决策一致性证书”后复活；它就是函数求值/等价类判定。
- 不得把“跨类假设对”换名为“反事实相反世界对”后复活；它就是 EC² 的跨等价类边。
- 不得把“感知动作的条件计划”换名为“最小只读查询序列”后复活。
- 不得只把 PolicyGuard 的补救信息从自然语言改成结构化查询而声称方法贡献。
- 不得用 AppWorld-UL 的新颖基准情形替代方法新颖性。

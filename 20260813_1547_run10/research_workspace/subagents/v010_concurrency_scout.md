# v010 前置勘探：并发工具型智能体的可串行化与最小修复

> 身份：Codex App 原生 Research Subagent 的非权威前置材料；主研究者尚未采纳或裁决。  
> 日期：2026-08-13。  
> 写入边界：未修改 `hypotheses_*`、`portfolio`、`decision_*` 或任何共享知识库科学内容。

## 1. 勘探结论

原候选核：

> 从并发智能体的工具调用与响应中抽取语义读写集和不变量，构建冲突图；在提交时阻止不可串行化历史，并选择最小重放或补偿。

**直接失败证据很强。** 该广义方法核已经被 2025--2026 年的一组最近工作从不同侧面覆盖，尤其是：

1. **CoAgent / MTPO（2026-06）与目标问题、正确性目标和修复动作近乎同题。** 它显式研究多个 LLM 智能体并发修改同一 Git 树、Kubernetes 集群或文档，目标正是可串行化；中间件跟踪每个工具调用的读写足迹，预先固定串行次序，发现冲突后通知受影响智能体只修复依赖过时读值的动作，并用每个工具预注册的 Saga 逆操作撤销、重排错序写入。论文还把冲突可串行化与先行图无环作为经典判据。原候选的“读写集＋冲突图＋局部重放/补偿”没有提供越过这一最近工作的实质变化。一级来源：[CoAgent](https://arxiv.org/abs/2606.15376)。
2. **Atomix（2026-02/05）已经把“调用并非提交”落实为事务型工具中间件。** 它记录读作用域和副作用作用域，冻结事务足迹，利用每资源进度前沿决定何时提交；可缓冲副作用到提交才释放，已外化但可逆的副作用在中止时补偿。其多智能体 `tau-bench` 实验已经用“同一订单的取消与修改地址”强制读--计划--写重叠，并直接比较工作流锁、逐调用锁、乐观并发控制和无事务。原拟议的 `tau-bench` 最小构造不是新的评价路径。一级来源与公开资产：[Atomix 论文](https://arxiv.org/abs/2602.14849)、[代码与实验](https://github.com/mpi-dsg/atomix)。
3. **经验证的并发异常工作（2026-06）已经将丢失更新、过时生成、因果级联、工具副作用错序和工具注册表幻读形式化。** 它提供 TLA+ 反例、Verus 证明、因果前驱闭包、提交次序器、Saga 逆序补偿以及真实 LangGraph/deer-flow 复现。若只把传统先行图套到智能体轨迹上，会被该工作和经典数据库理论共同吸收。一级来源：[Verified Detection and Prevention of Concurrency Anomalies](https://arxiv.org/abs/2606.17182)。
4. **Cordon（2026-06）已经在线构造语义事务与结果沿袭图。** 它在工具分发点解析工具名、参数、资源和目的地；把读锚点、工具返回/派生结果、写入、删除和外部副作用连接成有类型沿袭图；本地修改进入影子状态，外部副作用进入发件箱，验证组合执行流后才提交。尽管它的主问题是安全边界而非多智能体可串行化，但它直接占据“从工具调用/响应构造语义依赖与事务提交边界”这一组件。一级来源：[Cordon](https://arxiv.org/abs/2606.17573)。
5. **MemTX（2026-07）进一步覆盖共享记忆的事务提交、快照隔离和级联修复。** 它显式建模“一个智能体的写成为另一个智能体的前提并最终触发真实工具副作用”，为每条记录附证据、权限、沿袭和有效性，写入在快照隔离事务中暂存，验证后提交；不可逆工具调用受在途信念状态门控，撤回信念会触发派生记录和工具副作用的有类型级联修复。它不是一般外部业务对象可串行化，但直接压缩“从共享信息前提到副作用的事务沿袭/级联修复”空间。[MemTX](https://arxiv.org/abs/2607.23929)。
6. **局部重放也不是空白。** 2026-08-11 的依赖引导回滚修复从运行时沿袭建立“记忆到动作”的有类型图，追踪下游依赖并只重放受影响且与答案相关的计算。其故障源是错误持久记忆而非并发外部世界，但足以构成“依赖图驱动选择性重放”的最近组件先行。[Dependency-Guided Rollback Repair](https://arxiv.org/abs/2608.10502)。

因此，本勘探建议主线程**直接杀死广义候选核**，不要以“事务包装＋冲突图＋局部补偿”立项。仅有一个很窄、尚需先做杀手实验的重构空间：

> 在工具没有可靠资源/足迹声明、工具响应会隐式引入跨应用语义依赖的条件下，从原始调用与响应在线恢复**可校准的语义资源身份、读写足迹和因果依赖**；再由确定性优化器计算一个带不可逆副作用约束的最小重验证/重执行切片，并输出可核查证书。

这一路线的贡献若存在，也必须是“**隐式语义足迹恢复与可证明最小修复**”，不能再声称新建事务、首次发现并发异常、首次保证可串行化或首次选择性重放。当前证据仍显示它很可能只是 CoAgent 的 ToolSmith/自愈、Cordon 的沿袭图、Atomix 的作用域事务、MemTX 的信念提交/级联修复和依赖引导回滚的组件拼接，风险高。

## 2. 最近先行逐项输入/计算/输出

### 2.1 CoAgent：最致命的同题碰撞

- **输入（I）**：并发智能体任务；共享外部对象；每个已注册工具声明的读集 `R(tool)`、写集 `W(tool)`、盲写/读改写类型和可选逆操作；启动时固定的智能体串行次序。
- **计算（C）**：MTPO 按固定次序过滤读视图；写入实时外化；当较早次序智能体的后到写入可能使较晚智能体的读前提过时时发通知；LLM 判断语义相关性并只修复受影响动作；中间件对错序写做逆操作、撤销和按次序重放。
- **输出（O）**：在静止点相对于固定次序可串行化的最终状态和读视图；论文报告十个争用负载上正确性接近串行执行、约 `1.4x` 加速，未协调执行只通过约 13% 试验。
- **直接重叠**：同一问题（并发共享外部状态）、同一正确性目标（可串行化）、同一足迹抽象、同一局部修复/补偿动作。
- **尚存差别**：CoAgent 需要工具足迹声明或由 ToolSmith 合成，并把“哪些前提受影响”的语义判断交给 LLM；它没有给出一个对原始不透明工具 I/O 的、可校准的足迹恢复模型，也没有证明修复集合为全局最小。但“少重放”本身已被明确主张，差别只能落在可测量的抽取与优化上。
- **来源状态**：2026-06 arXiv 预印本，标注 submitted to ATC 2026；未在论文页发现公开代码链接。新颖性审计仍必须将其视为最近一级来源，实验复现强度则低于有公开代码的 Atomix。

### 2.2 Atomix：事务包装、作用域和前沿提交

- **I**：工具调用通过适配器进入；事务带 epoch；适配器给出读作用域、效果作用域、副作用类型、幂等键与可选释放/补偿处理器；编排器提供进度前沿。
- **C**：执行、封闭足迹、前沿检查、提交/中止分离；只有所有接触资源都不会再出现更早冲突工作时才提交；缓冲型效果延后释放，可逆外化效果中止时补偿，不可逆效果提交前门控。
- **O**：面向工具副作用的分组原子性、隔离和恢复；论文在强制多智能体重叠上报告 0 个冲突环见证，在不可逆发送上报告 0/500 无效泄漏。
- **直接重叠**：原候选“在线阻止不可串行化提交”已被前沿＋过时重试实现；“最小构造用 tau-bench”也已实际做过。
- **边界**：作用域由适配器定义；论文明确不声称语义验证、分布式部署或完整崩溃安全恰好一次。这里是最窄重构可能利用的现实缺口，但不是一个现成新方法。
- **资产**：`https://github.com/mpi-dsg/atomix`，约 2,000 行单进程 Python 原型，含 tau-bench、WebArena、OSWorld 和受控争用/故障注入材料。

### 2.3 Verified Concurrency Anomalies：异常、因果闭包与提交次序

- **I**：把共享记忆、向量索引和工具注册表交互抽象为长时间“读--生成--写”操作历史；记录读值、写值、提交/中止、因果前驱和工具发出/完成次序。
- **C**：TLA+ 定义四类异常；Verus 验证从 `L0` 到 `L4` 的实现链。`L2` 用因果前驱闭包防止已提交动作依赖被中止祖先；`L3` 用 Saga 与提交次序器防止外部工具效果错序；`L4` 用注册表快照/提交验证防止工具版本幻读。
- **O**：异常见证或一致性级别；验证过的检测器与预防器；LangGraph 平行编辑/摘要过时生成和 deer-flow 丢失 todo 的真实复现。
- **直接重叠**：原候选提到的丢失更新、重复副作用、读写偏斜与错序均已有经典或本文形式化。仅构建冲突图不会形成智能体方法贡献。
- **资产**：arXiv 页面提供 ancillary files，论文列出 `Anomalies.tla`、`Levels.tla`、`lib_l2_exec.rs`、`lib_l3_exec.rs`、`lib_l4_exec.rs`、Python 分析器和离线复现材料；可从论文的 source/ancillary 包获取。
- **边界**：`L2--L4` 多数是模型级/执行级验证，不等于对真实外部工具栈的全面部署；论文自己承认真实工具幂等、超时和部分失败工程仍有限。

### 2.4 Cordon：在线语义沿袭和组合提交边界

- **I**：工具分发点的工具名、参数、资源、目的地、返回值和派生对象；任务级作用域、授权与审批义务。
- **C**：在线把读锚点、结果对象、变换、写/删和外部效果连接为有类型沿袭图；本地修改放入影子文件系统，外部效果进入 effect outbox；提交前联合验证沿袭、权限、状态和效果。
- **O**：批准后提升本地写入并释放外部效果，或中止并丢弃；恢复日志保留跨边界状态。论文报告 45/45 风险工作流被提交前截获。
- **直接重叠**：它已经从调用和响应构造语义依赖，不允许把“语义读写集/沿袭”单独包装成新颖性。
- **边界**：主张集中在安全/信息沿袭，不提供多智能体可串行化；因此它是组件碰撞而非同题完全碰撞。

### 2.5 MemTX：共享信念提交与级联副作用修复

- **I**：多个智能体读写的持久共享记忆；每条记录的证据、权限、沿袭和有效性；由这些记录支持的工具副作用。
- **C**：在快照隔离事务中暂存记忆写入，执行验证--提交；在途/未提交信念门控不可逆工具调用；信念被撤回后，沿有类型依赖向派生记录与工具副作用传播修复。
- **O**：安全提交或拒绝的信念状态、受门控的副作用，以及满足 action-safety gating 与 cascade-repair completeness 两个不变量的恢复结果；作者报告用性质测试与 550 万个有界协议状态枚举未发现违反。
- **直接重叠**：共享信息写入成为其他智能体行动前提、再触发不可逆副作用的链条，已经有事务提交、沿袭和级联修复协议。候选不能把这一子问题当作外部世界并发的新空白。
- **边界**：MemTX 的主对象是信念/记忆记录，而不是跨 AppWorld 应用的业务对象读写和一般冲突可串行化；它属于高强度组件碰撞而非 CoAgent 式同题碰撞。

### 2.6 SagaLLM、OptiMA、GoEX 与语义隔离

| 家族 | 已有核心 | 与候选的关系 | 不应混淆的边界 |
|---|---|---|---|

| [OptiMA 2025](https://arxiv.org/abs/2511.03761) | 多智能体事务模板、非共享插件的 RC2PL 锁、按批次静态/半静态事务调度、提交/中止回调 | 覆盖“锁/静态调度/事务包装”；公开实现支持上百智能体 | 冲突粒度是预声明非共享插件，事务被视为不可分块；没有原始工具 I/O 语义足迹抽取 |
| [GoEX 2024](https://arxiv.org/abs/2404.06921) | 自主 LLM 动作的后验验证、直观撤销和损害约束；开放式运行时 | 早期占据“可撤销外部动作/损害边界” | 主要是单动作运行时设计，不是并发可串行化协议 |
| [BEGIN AI TRANSACTION 2026-08](https://arxiv.org/abs/2608.05412) | 对长生命周期工作流的模型、提示、索引、策略、工具等语义资源建立快照隔离；检测语义读偏斜、兼容偏斜和合并偏斜 | 说明“智能体语义隔离层级”本身也已成为数据库近期议题 | 处理工作流语义环境版本变化，不是两个智能体对外部业务状态的读写冲突 |
| [Verified Tool Calls 2026-07](https://arxiv.org/abs/2608.02645) | 后置条件验证、重试前核验和幂等键，处理超时、延迟可见、部分写和重复动作 | 覆盖重复副作用的简单强基线 | 单调用可靠性包装，不能替代跨调用/跨智能体串行化 |

### 2.7 五类相邻方案的明确区分

1. **事务包装**：Atomix 把工具效果分组并门控提交；Cordon 把任务级语义沿袭、影子状态和 outbox 绑定为事务；OptiMA 使用预定义事务模板。原候选若只是“再加一个事务管理器”，必死。
2. **锁/版本号**：OptiMA 使用严格保守 2PL 锁住非共享插件；Atomix 和经验证异常工作都比较或实现乐观重验证/快照隔离；简单资源版本号、比较并交换和工作流锁必须是强基线，不可被省略。
3. **静态调度**：OptiMA 预估事务时长、按已知插件冲突矩阵批量调度；CoAgent 预先固定串行次序但允许物理并发。候选只有在工具足迹运行时才显现时，才与 OptiMA 有结构差异。
4. **Saga/补偿**：SagaLLM 自动生成/验证补偿；CoAgent 为每个写注册逆操作并重排；Atomix 由适配器给补偿处理器；GoEX 提供撤销。候选不能把“补偿”当主要变化。
5. **LLM 多智能体协调**：SagaLLM 用专门验证/上下文智能体；CoAgent 让被通知的执行智能体语义判断冲突是否影响计划并局部修复；这已覆盖“让 LLM 自己协调”。最窄差异必须来自一个可校准、可独立测量且优于 LLM 直接判断的运行时抽取/优化器。

## 3. 最窄可反证 changed computation

仅作为前置勘探，不是候选裁决。

### 3.1 严格输入、计算、输出

- **输入**：若干并发 agent 的原始工具调用/响应流；工具 JSON schema 和普通自然语言描述可见，但**没有可靠的人工读写作用域、逆操作或不变量注释**；可见提交代价、重放代价、是否不可逆等运行时事实。方法不得访问隐藏数据库日志或评价终局。
- **计算**：
  1. 从参数、响应句柄和跨调用引用中归一化语义资源身份，例如 `order#123.address`、`calendar/userA/time-window`、`mailbox/message-id`；
  2. 预测每步的 `R/W/CREATE/DELETE/EMIT` 足迹和结果到后续调用的因果依赖；对不确定足迹保留置信集合，而不是强行单标签；
  3. 用确定性冲突/依赖图检查当前提交是否能加入一个无环可串行次序，并将跨应用业务不变量表示为额外超边；
  4. 若不可提交，以整数规划或图优化求解最小加权修复集：重验证某些读、重执行某些依赖动作、补偿某些已外化可逆动作；不可逆动作只能被提交前门控，不能伪造回滚；
  5. 输出修复证书，列出造成冲突的边、被切断的因果路径、预计代价和更新后的可串行次序。
- **输出**：`COMMIT / WAIT / REVALIDATE / REPLAY / COMPENSATE / ABORT` 决策；待执行的最小动作切片；一个可由隐藏真实足迹和终局评估器复核的证书。

### 3.2 必须声明的不新之处

- 冲突图/可串行化判据来自经典数据库理论；
- 事务边界、版本验证、outbox、Saga 和幂等键不是贡献；
- 依赖图、级联修复和选择性重放不是贡献；
- CoAgent 已有声明足迹、通知和局部自愈；Cordon 已有在线语义沿袭；Atomix 已有作用域和进度提交。

若最终变化只能表述成“用 LLM 猜足迹，再调用已有事务协议”，则是模块拼接，不具有方法论文潜力。

## 4. 强基线

所有基线必须获得同样的原始工具调用、响应和预算；有人工/隐藏真实足迹的基线需明确标为 Oracle，不能与实际方法混在一起。

1. **串行执行 Oracle**：两个任务按 `A→B` 和 `B→A` 各从干净快照执行；定义所有可接受串行终局。
2. **无协调并发**：直接平行运行，衡量真实异常率和速度上界。
3. **逐调用互斥锁**：工具调用期间锁资源；预计无法覆盖读--计划--写空窗。
4. **工作流级锁/串行化**：正确性强、并发度低。
5. **资源键＋版本号/CAS＋全事务重试**：不使用语义依赖图的强简单基线。
6. **OCC（乐观并发控制）＋声明/Oracle 读写集**：区分抽取误差和修复策略误差。
7. **Atomix Tx-Full**：作用域事务、前沿、重试、补偿和不可逆门控；优先复用其公开实现。
8. **CoAgent 风格基线**：工具足迹由简单 ToolSmith/LLM 生成，冲突后把通知发回原智能体，要求自行判断并局部修复。若无法复现论文系统，至少实现机制匹配且披露差异。
9. **Cordon 风格在线沿袭＋全中止**：沿袭只用于检测，发生风险就整事务中止，用于测量“最小修复”是否真有增益。
10. **Saga/补偿、Checkpoint-Replay、Verified Tool Calls**：分别隔离补偿、全回放和幂等重试带来的收益。

## 5. 最小杀手实验

### 5.1 首先只杀最大不确定性：隐式足迹是否能可靠恢复

不要先实现完整事务运行时。先做 80--150 个离线、域外留出的工具轨迹对：

- 训练/开发只可见工具 schema、自然语言描述、调用参数与响应；
- 隐藏 Oracle 由 AppWorld/tau-bench 后端数据库访问日志、工具实现或手工双人核验生成，绝不能进入提示；
- 测试按**未见工具或未见应用**划分，避免记住字段名；
- 标注资源实体、字段级 `R/W/CREATE/DELETE/EMIT`、调用间因果依赖和真正冲突对。

比较：规则化资源键、工具描述直接 LLM 抽取、CoAgent 风格 ToolSmith、Cordon 风格句柄沿袭、候选不确定性抽取器、Oracle 足迹。指标：资源身份精确率/召回率、读写 F1、真正冲突召回、无害重叠误报、因果边 F1、校准误差。

**第一重 kill**：在未见工具/应用上，真正冲突召回低于 0.90，或在 0.90 召回时无害重叠误报高于 0.20；此时在线可串行化安全性主要建立在不可靠 LLM 猜测上，不值得继续构建完整运行时。

### 5.2 若抽取幸存，再做独立终局并发探针

#### 路径 A：AppWorld（更有差异）

[AppWorld ACL 2024](https://aclanthology.org/2024.acl-long.850/) 提供 9 个模拟日常应用、457 个 API、101 个数据库表，以及与代理文本独立的状态单元测试和 collateral-damage 检查。公开入口：[appworld.dev](https://appworld.dev/)。

构造 20--40 组配对任务，每组从同一数据库快照启动，在“完成初始读、尚未关键写”处设置确定性 barrier：

- 同实体丢失更新；
- 跨实体写偏斜（两边各自条件成立，合并后破坏总量/唯一性/时间窗口不变量）；
- 非幂等创建/发送导致重复副作用；
- 跨应用部分提交，例如一个应用记录已更新、配套通知/日历/结算未更新；
- 无冲突的同域和跨域对，防止系统通过过度串行化取巧。

隐藏评估器从干净快照分别执行 `A→B`、`B→A`，得到允许的串行终局集合 `S`；并发结果只有在最终数据库状态属于 `S`、全部不变量成立且无意外 collateral damage 时通过。**评价逻辑由后端和配对任务生成器给出，不由方法的语义图定义。**

#### 路径 B：tau-bench（仅作复现/校准）

公开资产：[tau2-bench](https://github.com/sierra-research/tau2-bench)。其 airline/retail/telecom 任务默认用 DB 终局而不是固定动作序列评分。可利用 gold actions 在新环境生成目标数据库状态。知识库已有只读卡：`D:\Desktop\crl\knowledge_base\cards\paper\paper-tau-bench.md`。

但 Atomix 已经做过同订单“取消 vs. 修改地址”的 2/4/8 智能体强制重叠，因此复刻它只能用于校准，不能作为新颖性证据。若主线程采用 tau-bench，应设计未被 Atomix覆盖的跨对象写偏斜或跨域副作用，并仍与 Atomix Tx-Full 正面对比。

#### 公平测量

- 相同模型、工具、上下文、最大工具调用数、并发度和墙钟上限；
- 每种策略在同一 barrier 调度种子上运行；
- 报告：串行等价终局率、不变量违反率、重复/残留副作用、误阻止率、整事务重试次数、被重放动作数、补偿失败、模型调用/令牌、完成时间；
- 额外报告 `Oracle 足迹＋候选最小修复`，把足迹抽取误差与优化器价值分开。

### 5.3 端到端 kill 条件

满足任一条件即应杀死这一窄核，而非继续加模块：

1. **最近工作吸收**：实现行为无法与 CoAgent 的足迹＋通知＋局部修复，或 Atomix 的作用域事务＋重试/补偿，在同一输入输出层面分开。
2. **简单强基线吸收**：资源键＋CAS＋整事务重试、工作流锁或 Atomix 在串行终局率上持平，且成本差异不稳定或不足以抵偿错误风险。
3. **抽取器不可靠**：未见工具/应用上的真正冲突召回/校准未过上述门槛，或者错误集中在关键跨应用不变量。
4. **Oracle 也无增益**：即使给出真实读写集，最小修复相比全重试/CoAgent 风格修复没有显著减少模型调用、工具调用或墙钟；说明“最小修复”不是有用干预点。
5. **最小性是假象**：只按图节点数最小，却因 LLM 非确定性、补偿成本或外部效果不可逆而不对应真实代价；不能给出代价敏感反例和证书。
6. **语义判定同源**：不变量、冲突边和成功标签都由同一个 LLM/提示生成，导致方法自证；必须保留隐藏程序化终局。
7. **只在手工合成同键冲突有效**：跨应用、字段级依赖或写偏斜一加入便退化，且无真实工具/应用留出结果。
8. **不可逆效果越界**：方案声称“补偿”邮件、付款或外部消息却没有提交前门控/真实撤销能力。

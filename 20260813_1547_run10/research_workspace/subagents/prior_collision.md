## 2. 总体碰撞结论（供主研究者裁决前使用）

当前空间不是空白，而是高度拥挤：

1. **验证后再提交状态**已经被 ToolGate、Verified Tool Calls、Cordon 等分别以调用后置条件、读取式验证、任务级语义事务实现。
2. **有限预算下选择验证节点**已被 Sherlock 直接表述为工作流图上的预算化验证放置与验证器选择；“按下游影响分配验证”不是新的问题表述。
3. **依赖图上的污染传播、隔离、后代失效、局部回滚/选择性重放**在 MemTX、Dependency-Guided Rollback Repair、Grounded Continuation、DART 中已经形成一条近乎闭合的方法谱系。

反证强度不均：h-v001-003 出现接近同一变换的直接碰撞；h-v001-002 的核心调度问题已被吸收且其“扇出”代理受实证反例挑战；h-v001-001 仍可能剩下很窄的差异，但必须证明“轨迹条件化关系检查”不是 ToolGate 的动态后置条件、Cordon 的事务约束或 ReLoop 的行为扰动在通用工具智能体上的重新命名。

## 4. 逐假设组件审计

### h-v001-001：轨迹诱导语义契约后置验证

**已被吸收的组件**：后置条件；通过后才写可信状态；失败隔离/回溯；跨步骤联合提交边界；无真值行为扰动；修复后的回归回滚。分别由 ToolGate、Cordon、ReLoop 和 Verified Tool Calls 覆盖。

**仍可能成立的最窄差异**：从“当前任务目标＋后续动作前置需求＋工具文档”在线生成实例级语义关系，并用与生成错误机制不相同的执行信号核验一个看似正常的工具返回；不是固定返回模式，也不是静态领域规则。

**致命风险**：

- 若“关系”只是由同一个大语言模型把任务要求改写成检查提示，则与普通自审/动态 ToolGate 后置条件难分，且生成者与验证者同源。
- 若关系需要可执行扰动或第二次工具调用，ReLoop 已占据“无真值的行为敏感性检查”；贡献必须是通用关系编译或选择算法，而非把它移植到 API。
- 若把整个轨迹暂存后统一验证，Cordon 已经给出任务级语义事务。
- 如果只能检测模式不匹配、空响应或显式冲突，ToolGate 已足够吸收。

**最低反碰撞要求**：明确给出 ToolGate 无法表达而本方法能自动构造的关系族；至少一个核验信号不能由原生成轨迹的同一判断直接复述；在相同工具调用/令牌预算下，分别对 ToolGate $P/Q$、第二次同工具读取、ReLoop 式行为扰动和普通自审做消融。

### h-v001-002：传播风险 × 可逆性验证预算调度

**已被吸收的组件**：工作流图上的验证预算放置、节点脆弱度/下游影响、验证器成本选择、在线预算约束、受影响节点回滚，Sherlock 已经直接覆盖；“边际价值÷预算”的表述也被 Inference-Time Budget Control 占据。

**可保留的差异**：不使用离线成功/失败标签或最终真值，只依赖当前轨迹可见的依赖结构、工具元数据与动作可逆性；把不可逆效果前的预期损失纳入验证价值，而不仅是准确率/延迟。

**直接反证**：Sherlock 的正文拓扑分析报告，终点和起始节点的脆弱度突出，fan-in 与脆弱度正相关，而 fan-out 在其测试域中几乎无相关性。因此当前以“下游扇出”作为主要传播风险代理没有经验安全性；它是应优先杀的假设，不应被写成先验事实。

**最低反碰撞要求**：先用小型故障注入检验 fan-out、fan-in、到不可逆动作的路径权重、重做成本分别对真实终局损失的预测；必须胜过 Sherlock 的 `terminal + initial + fan-in` 放置启发式、随机/均匀验证和仅不确定度调度。若只是把 Sherlock 的离线脆弱度换成手工 `fan-out × reversibility / cost`，方法贡献过弱。

### h-v001-003：证据隔离状态图与最小后代回滚

**近乎精确吸收**：

- MemTX：暂存/隔离、来源和有效期、传递后代、按类型撤销/隔离/补偿、不可逆动作门。
- Dependency-Guided Rollback Repair：运行时类型化溯源图、独立可信支持保留、无支持后代停用、答案相关的选择性重放。
- Grounded Continuation：主张—证据图上的独立支持和精确撤回传播。
- DART/Sherlock：生产者—消费者依赖、受影响节点回滚与安全检查点。

**仅剩差异**：把故障源从持久记忆/会话证据改成同一轨迹内的工具观察，并让诊断与回滚一体化。就当前表述看，这是任务实例迁移，而不是新的 changed computation。

**致命碰撞结论（非最终裁决）**：若不引入一个上述工作没有的计算对象或最优化目标，h-v001-003 应被视为被先行工作吸收。尤其 2026-08-11 的 Dependency-Guided Rollback Repair 与“最小后代失效＋保留独立支持＋选择性重放”几乎逐项对应。把 `memory node` 改名为 `tool observation claim` 很难通过方法新颖性审查。

## 5. 拥挤性与可证伪的剩余楔子

最可能仍有研究价值的不是“再加一张图/再加一个验证器”，而是尚未被上述工作同时满足的窄交集：**在没有标签、隐藏真值和领域手写后置条件时，自动把具体轨迹中的后续可执行需求编译成与原生成机制非同构的低成本语义试验，并证明它在严格等预算下能发现形式正常的错误工具结果。**

这个楔子仍然脆弱，原因是：

- 自动生成核验关系可能复用同一语义误读，独立性名不副实；
- 通用工具通常缺少 ReLoop 所依赖的可控扰动和单调不变量；
- 第二次查询可能只是昂贵的重试，且仍读取同一陈旧/错误来源；
- ToolGate/Cordon 已经占据提交协议，创新只能落在“如何生成和选择有效的语义试验”，不能靠隔离/事务包装补足；
- 预算调度又必须同时越过 Sherlock，并解释为何使用的结构代理比 fan-in/terminal 更有效。

因此，若后续最小实验无法展示至少一种 ToolGate 明确放行、同源自审稳定漏检、但轨迹诱导的外部关系试验稳定检出的错误族，则 h-v001-001 也应被快速淘汰。若 h-v001-002 的结构评分不能在等预算下超过 Sherlock 启发式，则不能作为独立方法主张。h-v001-003 不宜在现有计算形式上继续投资。

## 6. 检索失败与证据限制

- Semantic Scholar 三份先验审计均因 HTTP 429 退化；候选集合主要由 arXiv 和 Run-local 共享库补全，不能声称穷尽所有会议在审稿件。
- OpenReview 的 ReflectAgent 与 Failing Tools 页面/PDF遇到 403/反机器人阻断；仅保留“高风险身份线索”，没有把搜索摘要当作完整方法证据。
- 大量 2026 工作是 arXiv 预印本；这里判断的是新颖性碰撞风险，而非同行评审后的正确性或影响力。
- ToolGate、ProbeCal 有正式 ACL Anthology 页面；其余核心技术结论均链接 arXiv 正文。没有使用博客、新闻稿或二手综述支撑方法判断。
- 本草案没有进行最终候选选择、研究种子形成、固定 Reviewer 或 Run-level 决策。

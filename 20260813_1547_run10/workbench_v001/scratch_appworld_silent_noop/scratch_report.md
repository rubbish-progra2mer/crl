# v001 Scratch 结论：单次事后实体见证被证伪

## 结论

`h-v001-001` 当前实现及其核心计算——从公开工具文档、当前写调用参数和成功响应中，选择一次事后读回并用实体属性关系判定效果——不能安全地区分真实成功与模式合法的静默空操作。该方法核按预设反证条件淘汰；没有进入 Recorded、Formal 或固定 Reviewer。

这不是 Run-level 无交付结论。保留的可研究空间是：把验证对象改为写前—写后的可见状态变化，以写意图/响应句柄锚定变化，并在不可见、未穷尽、歧义或读错误时返回 `UNKNOWN`。

## 冻结实验

固定环境：AppWorld 开发集，源码提交 `a072b7a86e7c1d5b1d7175659d750ebb9b79f10a`，包版本 `0.2.0.dev0`，数据版本 `0.2.0`。所有夹具由官方开发集解答确定性地实例化有效调用；编译器不读取评价程序、任务真值、服务实现源码或历史正确轨迹。官方环境终局只作独立评价。

### 最初四个故障夹具

- `37a8675_1`：Venmo 原子付款；
- `530b157_1`：跨应用付款后短信的部分成功；
- `6171bbc_1`：播放列表漏写子项；
- `6c2c621_1`：批量文件导出漏一项。

在这四个为可行性选择的夹具上，洁净执行均通过；静默空操作均使官方终局失败；当前编译器均生成事后见证、拒绝故障响应，重放后官方终局恢复。该结果只证明 AppWorld 能承载“模式合法成功响应但状态未写入”的对照，不证明编译器的一般安全性。

### 十个未参与编译器设计的洁净夹具

在另外十种效果操作上：

- 10/10 洁净官方终局成功；
- 7/10 生成见证；
- 生成见证者中 5/7 返回真、2/7 对真实成功误报为假；
- 3/10 无法编译。

两项洁净误报的原因：

- `spotify.create_playlist` 选择默认仅返回前五项的 `search_playlists`，没有绑定查询，也没有证明分页穷尽；写响应中可精确绑定的 `playlist_id` 反被降权。
- `venmo.remind_payment_request` 选择调用者的“收到请求”集合，但提醒只能由发送者发起；即便改成“已发送请求”，该对象写前写后不变。真实副作用是接收者通知，在相同调用者权限下不可见，应为 `UNKNOWN`。

### 配对静默空操作判别实验

每个故障世界从同一任务初态执行同一确定性前缀；首个目标写调用不改变状态，但原样返回配对洁净世界捕获的真实成功响应。结果：

| 结果类别 | 数量 | 操作 |
|---|---:|---|
| 洁净真、空操作假（真正可判别） | 1 | `spotify.add_to_queue` |
| 洁净真、空操作真（伪见证） | 4 | `spotify.follow_artist`、`spotify.download_song`、`venmo.like_transaction`、`spotify.like_song` |
| 洁净假、空操作假（双边失败） | 2 | `spotify.create_playlist`、`venmo.remind_payment_request` |
| 两边均不可编译 | 3 | `file_system.move_file`、`spotify.previous_song`、`spotify.next_song` |

因此，在已编译的七个见证中只有一个同时通过洁净安全性和故障判别。四个伪见证只证明写前已存在的目标实体仍可读取，没有证明动作效果发生；另两个把“未观测到”错误地当成“明确失败”。

## 基础设施负结果

尝试在同一个 AppWorld 执行栈内以 `save_state(state_id)`、真实调用、`load_state(state_id)` 构造回滚故障：

1. 默认运行时安全器拦截检查点内部文件操作；
2. 仅对固定官方解答载体关闭运行时猴子补丁式安全器后，`load_state` 重建环境与时间冻结器，同一栈关闭时出现资源冲突。

两次失败运行不产生科学结果，第一份输出保留为 `discriminativity_probe_failed_checkpoint_safety.json`，第二次只有原始标准错误。随后改用独立配对世界完成等价判别，不修改 AppWorld 源码。

## 证伪范围

被杀：

- 单次事后读取；
- 仅凭同名实体/字段存在进行效果确认；
- 词法最高分直接决定读计划；
- 把分页不全、权限不可见、绑定歧义、读错误或不可编译压成布尔假；
- 将“发现原对象”误作“确认本次动作发生”。

未被本实验杀死、但尚未获得支持：

- 从公开工具规范和实例化调用自动枚举候选读计划；
- 写前—写后可见差分；
- 响应标识符锚定的状态变化；
- 对移动类操作使用源消失与目标出现的合取；
- `TRUE / FALSE / UNKNOWN` 三值裁决；
- 同权限、穷尽、经读纯度检查的运行时效果验证。

- `research_workspace/subagents/witness_compiler_audit.md`：原生研究子智能体的非权威独立实现审计，已由主研究者逐项复核并在本报告中采纳相符部分。

## v002 转向条件

v002 的最小杀手实验必须满足：

1. 计算对象确实是写前—写后效果差分，不复用 v001 的存在性关系；
2. 至少覆盖创建、成员/布尔状态、移动合取、游标变化和不可观测副作用五类结构；
3. 洁净成功不得误报；静默空操作不得因预先存在实体而通过；
4. 分页不全、权限不可见、读副作用、歧义和错误均单列 `UNKNOWN`；
5. 构造只使用智能体同权限的公开工具接口、实例化调用与可见响应，独立官方终局不参与编译。

## Active Diagnosis 解释

`post-falsification-v001` 事实快照显示：当前版本没有 Formal attempt、没有固定 Reviewer，三条假设分别处于 `falsified` 或 `prior_collision`；因此没有被旧正式结果约束，也没有理由把当前局部盆地失败扩大成 Run-level 结论。主研究者据此把写前—写后差分判为有意义的科学转向，而非 v001 的文字修订。

回忆重建同时把 Run 内 `external/appworld/data/tasks/*/ground_truth/` 纳入了全文索引，存在测试真值污染风险。本次诊断展示的回忆命中未用于选择任务级见证；v002 禁止从该派生索引生成 AppWorld 计划、夹具或 Claim。未来测试集 Formal 必须在构造侧不可见测试 ground truth 的进程/材料边界内执行，官方评价只在独立评价侧运行。

# v006 不确定提交路线的精确碰撞

## 问题事实

“工具返回超时或失败”与“外部副作用未发生”不是同一事实。若请求已被服务端提交但响应在返回途中丢失，盲目重试可生成重复付款、消息或其他不可逆效果。该问题与 v001 的“返回成功但语义效果未发生”方向相反，因此是一次结构不同的搜索扩张。

Run-local purpose-aware retrieval 位于 `hypotheses_v006/searches/ambiguous_commit_v006_01/`，包含 92 篇去重论文、535 条原始观测，3 条观测带机械噪声标记。知识库未给出足够精确的最近方法，随后核验了最新一级来源。

## 直接碰撞

- Verified Tool Calls（arXiv:2608.02645）直接以非原子工具失败为问题，包括 dispatch 后超时、延迟可见与部分更新；其包装器已经实现 postcondition verification、verify-before-retry 和 idempotency keys，并以重复动作与任务成功评价。
- Cordon（arXiv:2606.17573）把多步工具工作流纳入语义事务，跟踪工具意图与结果谱系，在影子状态执行可逆变更，把外部效果放入 outbox，并保留恢复元数据后再提交。
- Atomix（ICLR 2026 AIWILD Workshop）把效果提交推迟到进度谓词成立，报告重试诱发重复外部效果并用事务重试、补偿和效果门控处理。
- CapLease（arXiv:2608.01710）针对重规划、重试、委派和崩溃恢复造成的语义重放，用规范化动作、持久单调状态与 Issue–Prepare–Commit 转移限制同一授权效果的执行预算。

因此，`h-v006-001` 的“语义意图指纹 + 写后查询 + 验证后重试/幂等去重”被现有工作逐项占据；若再加状态查询范围证书，又会回到 v002 已杀的查询完整性拼接。没有必要运行 AppWorld 故障注入来证明一个已被直接方法论文实现的宽核。

## 局部裁决

`h-v006-001`: `prior_collision`。杀伤范围是模糊提交/语义幂等重试这一当前方法谱系，不是整个 Run。

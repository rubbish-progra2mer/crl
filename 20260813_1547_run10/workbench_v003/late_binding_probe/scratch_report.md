# v003 Scratch：结果—动作等变性与标识符晚绑定

## 结论

v003 的宽假设“工具结果—动作等变性”被近期反事实回放、因果动作归因、主动上下文获取、函数返回消费训练、实体绑定门与数据流控制共同挤压。为检验是否还存在一个可执行的窄计算，本 Scratch 比较了三种后续动作参数表示：真实长标识符、会话短引用、带来源行与字段的类型化选择器。

最小结果不支持类型化选择器作为方法贡献。它没有稳定胜过最简单的短引用；在一个模型上更差，在另外两个模型上同分。观察到的原始标识符退化也高度依赖模型，并且多数错误是选错语义候选，不是复制出不存在的标识符。h-v003-002 因强基线吸收而淘汰；h-v003-001 因最近先行与剩余机制过薄而淘汰。该裁决不结束 Run。

## 设计

- 8 个合成的双实体决策任务；每个任务有 5 个目标候选和 5 个资源候选，干扰项只错一个语义属性。
- 每个任务用两组 SHA-256 派生的 UUID 形标识符作双射重命名，共 16 个实例/条件。
- 三个本地冻结模型：`qwen3:4b`、`qwen2.5:7b`、`qwen3:8b`；Ollama 本地推理，`temperature=0`、固定 `seed=20260813`、关闭思考输出、JSON Schema 约束。
- 三种条件：
  1. `raw_id`：模型直接复制目标与资源的真实长标识符；
  2. `short_ref`：模型输出 `T1..T5 / R1..R5`，运行时映射；
  3. `typed_selector`：模型输出 `(source_call, row, field)`，运行时校验来源并晚绑定。
- 评价分离：JSON/绑定可执行率、目标语义正确率、资源语义正确率、联合正确率、两组标识符重命名下所选语义标签是否一致。
- 这是一项 Scratch，不是独立终局、不是真实多步智能体实验，也没有使用隐藏测试真值。

## 结果

| 模型 | 原始标识符联合正确 | 短引用联合正确 | 类型化选择器联合正确 | 主要观察 |
|---|---:|---:|---:|---|
| Qwen3-4B | 13/16 (81.25%) | 16/16 (100%) | 14/16 (87.5%) | 短引用最好；选择器在 SSO 文章上稳定选到 draft |
| Qwen2.5-7B | 14/16 (87.5%) | 14/16 (87.5%) | 14/16 (87.5%) | 三者完全同分；均把 latest 解释成跨 owner 的最大版本 |
| Qwen3-8B | 14/16 (87.5%) | 16/16 (100%) | 16/16 (100%) | 选择器只追平短引用 |

全部 144 次模型输出都满足 JSON 与运行时绑定格式。标识符双射下的语义选择稳定率除 Qwen3-4B 原始标识符为 7/8 外，其余模型—条件都是 8/8。这说明原始高熵标识符可能干扰小模型，但当前夹具没有观察到大量“选对行却复制坏字符”的纯运输错误。

结构化原始响应与每次耗时保存在：

- `probe_results_qwen3_4b.json`
- `probe_results_qwen2.5_7b.json`
- `probe_results_qwen3_8b.json`

## 强基线为何杀死当前机制

1. `short_ref` 与类型化选择器拥有相同的关键抽象：模型不输出真实标识符，由运行时映射。前者更简单，却在 4B 上更好、7B/8B 上不差。
2. 类型化来源路径的潜在安全价值没有在当前正确性任务中转化成额外可测收益；若要主张安全，需要明确策略约束和攻击评价，而这会直接进入确定性数据流控制、CaMeL 类信息流控制和实体绑定门的邻域。
3. 短 ID 映射已有公开工程实践，不能把本次小样本现象包装为首次发现。
4. 实体绑定与 Binding Drift 已明确提出候选解析、溯源、执行门、锁定与重核；2026 年确定性数据流控制又把用户请求、状态、工具参数及其来源建模成关系并在执行前约束。

## 反事实等变性宽路线的碰撞

- AgentCheck 已对真实工具响应做单点扰动与回放，直接测后续行为变化。
- AttriGuard 在每个拟议工具调用前并行运行反事实测试，以动作存活性衡量外部观察归因。
- Causal Agent Replay 用结构因果模型、单步干预和前向重执行做轨迹归因。
- ACCORD 在动作前主动探测缺失信息，并将轨迹中相关上下文重新整合到决策。
- Function-Aware FIM 明确把 `动作—观察—继续` 等同为函数调用方消费返回值，并通过函数依赖图选样进行中期训练；还在 τ-bench 与 BFCL 上报告迁移增益。
- Tool-Call Dependency Structure 工作已经以“前序工具输出供给后序参数”定义依赖边，做了同类型 `_id` 值替换；其探针追踪拓扑而非标识符值，且作者明确将行为控制留作未来工作。这个未来缺口本身不足以使普通等变训练成为新方法。

## 限制与负结果边界

- 夹具是人工合成的静态最终决策，不代表 AppWorld 或 τ-bench 的真实长程分布。
- 三种条件的输出 Schema 与指令不同，不能把差异纯粹归因于标识符长度；结果只足以执行最小杀手检查。
- 每个模型每实例只跑一次；Ollama 即使固定温度和种子仍不应被假设为跨硬件位级确定。
- 没有测量提示注入、越权数据流、标识符时效、候选重排或跨工具类型检查。
- 因此本结论只杀死“当前类型化选择器优于简单短引用”的假设，不否定短引用作为合理工程实践，也不否定未来更严格的信息流类型系统。

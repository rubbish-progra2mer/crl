# v008-h002 下游延续等价碰撞裁决

## 裁决

`h-v008-002` 记为 `prior_collision`，不进入 Scratch 实现。

这里杀死的是 v008 的局部方法核，不是整个 Run。否定理由不是“没有检索到完全同名论文”，而是候选没有留下不可约的新增计算：它把经典动态切片所保留的部分行为改写为“下游智能体延续”，再串联已有的接口迁移、反例引导适配器综合、轨迹数据流定位和配对技能修订。

## 核心归约

候选原定义为：从旧成功轨迹中抽取工具响应到后续参数、实体绑定和分支的动态切片，以合法下一动作或分支签名定义等价，并反例引导地综合最小返回适配器或新版调用子序列。

把切片准则记为 `C = {后续参数, 实体绑定, 分支谓词, 下一动作}`，该定义要求新旧片段在 `C` 上保留部分行为，而不要求完整响应相等。这正是动态程序切片和观察等价的标准计算形态；把 `C` 的变量换成语言模型智能体轨迹字段改变了应用载体，却没有改变“按准则投影后保持行为”的计算。

## 方法级碰撞

### 1. 反例引导适配器综合已经占据搜索骨架

Sharma、Hietala 与 McCamant 的《Finding Substitutable Binary Code By Synthesizing Adapters》（IEEE TSE 2021；前身 arXiv:1707.01536）在给定目标函数和内部函数后，反复：

- 综合参数适配器与返回值适配器；
- 检查适配后返回值和副作用是否等价；
- 由不等价输入产生反例；
- 用累积反例继续综合，找不到适配器时返回失败。

因此，“反例引导 + 参数/返回适配 + 等价检查 + 可失败”不是新增骨架。`h-v008-002` 只是把等价投影收窄到一个任务条件化切片。

### 2. API 迁移已经占据复杂调用替换

- Sprout（OOPSLA 2025）对有状态、非连续、多调用 API 片段合成一对多、多对一和多对多迁移，并以行为树等价保证迁移。
- M³（ASE 2020）从黑盒随机输入输出学习 API 行为模型，用 SMT 搜索拆分、合并和移动形成的迁移。
- APIMigrator/AppEvolve 已抽取跨项目多对多 API 更新并以差分测试验证。
- GUPPY 让大语言模型生成旧新 API 兼容迁移，执行双版本测试并迭代修复。

因此，返回适配、显式默认值和“单调用换成新版调用子序列”也不是剩余新计算。

### 3. 智能体轨迹切片与局部归责已有直接方法

HarnessFix（arXiv:2606.06324v2）把智能体轨迹编译为 HTIR，显式重建跨步骤数据流和控制流，定位工具响应如何被后续请求复制、摘要、语义复用、遗漏或改变，并把运行时证据锚定到工具模式、提示、适配器和控制器实现；随后选择范围化修复算子并做回归验证。

这已经占据“从语言模型工具轨迹中找出影响后续参数和分支的切片，再局部修补承载机制”的智能体特有部分。HarnessFix 不专门做跨 API 版本适配，但正因为该部分与上面的迁移综合只是顺序拼接，不能成为新的方法核。

### 4. 配对轨迹驱动的技能修订已有直接方法

SkillAudit（arXiv:2606.14239v1）对同一任务运行有技能/无技能配对轨迹，以过程对齐对比评价把轨迹分歧定位到技能段落，给出 helped/hurt/inert 三值裁决；固定结构验证器负责回滚有害编辑。论文明确把工具和 API 变化列为技能演化动因。

因此，若把适配器改写成技能文本、以配对轨迹差异修订并回滚，仍会落入已有配对轨迹技能演化。

## 为什么不运行最小实验

原候选 kill 条件 9 是：若新计算不能脱离 Sprout/M³ 的一般行为等价和 SkillRevise 类执行修订之简单串联，应杀死。当前核查已经满足该条件。

一个合成突变实验最多能证明：以更贴近任务的观察投影会比全响应相等更少误拒，并可能比少量终局测试更少误接收。这是观察抽象选择的预期效应，不能区分下面两种解释：

1. 新方法提出了新的等价计算；
2. 已知适配器综合采用了一个由已知轨迹切片产生的、更合适的切片准则。

实验无法修复方法身份问题，故不把“能跑出正数”当作继续实现的理由。

## 检索与证据边界

- 标准 Prior Audit 已生成于 `hypotheses_v008/priors/v008-h002-continuation-equivalence/`。
- 该审计为 degraded：Semantic Scholar 连续返回 HTTP 429；arXiv 词袋检索返回 25 个候选，但大部分与问题无关。
- 因而没有把标准审计的空白分类框架当作“没有先行工作”的证据。
- 裁决依赖的是已核一级来源和逐项计算归约；Research Subagent 草案只提供线索，不产生正式裁决。

## 可保留的负结果

工具接口演化确实会破坏缓存计划和技能，MCPEvol-Bench 也提供了直接问题证据；但下列宽路线不足以形成方法论文种子：

- 把工具计划视为普通客户端程序后做跨版本行为等价迁移；
- 把完整响应等价放宽为某个任务切片上的观察等价；
- 把 API 迁移综合、轨迹切片、配对技能修订和回归验证串成流水线。

若未来重返该问题，必须改变计算对象，而不是继续收窄同一个等价投影。例如需要一个不能由既有切片准则或适配器族表达的新推断问题，并证明它改变候选生成或可判定边界。

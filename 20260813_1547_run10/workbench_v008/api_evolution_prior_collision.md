# v008 跨版本工具计划迁移：精确碰撞记录

## 暂定计算核

给定一个在旧工具版本上成功的多步计划、两版公开接口和可回滚黑盒沙箱，搜索参数重写、操作拆分/合并及胶水步骤，使迁移计划在新版本的可见终局投影上与旧计划行为等价。与简单方案的差别原拟落在“保留已验证过程结构，而不是读取新文档后从头规划”。

## Run-local 检索

purpose-aware retrieval `api_evolution_plan_migration_v008_01` 无路线降级，命中 98 篇去重论文、1099 条原始观测、4 条机械噪声标记。共享库对 Agentic Plan Caching、ToolGate、ReLoop 等有邻近材料，但跨版本 API 迁移主谱系需要一级来源外扩。

## 一级来源反证

- EvoC2F 的“evolvable”是成功轨迹抽取候选技能并经单元测试、契约检查和回归后准入技能库；其主计算是 Plan IR 编译、并行调度、容错注入与验证门控技能积累。现有正文没有把跨 API 版本的旧计划迁移作为问题，因此它不是单独的致命精确碰撞。
- Differential Regression Testing for REST APIs（ISSTA 2020）已经对两版服务和两版规范执行状态化请求序列并比较行为，处理输出归一化、请求乱序与非确定性；它占据“跨版本黑盒差分发现语义破坏”。
- EVOL Migrators（MOBILESoft 2023）从 OpenAPI 或 EVOL 服务生成迁移指南和稳定客户端库，在 13 次版本升级、3896 个变化上自动识别并处理变化；它占据基于演化模式的 Web API 客户端适配。
- M3: Semantic API Migrations（OOPSLA 2020）在没有目标库先验、变更历史和内部实现时，用概率程序合成建模函数行为，再以 SMT 搜索迁移位置；这直接覆盖“只靠外部行为语义而非名称迁移”。
- Transforming Programs between APIs with Many-to-Many Mappings（ECOOP 2016）专门处理多个旧调用被多个新调用替换、调用不相邻且变量名不同的情形；因此操作拆分/合并不是 Agent 计划独有的新计算。
- Sprout（OOPSLA 2025）把 API 行为分解为原子操作，用有限状态机、语义类型、值流和草图合成迁移程序，并给出迁移后行为树等价的正确性结论；它精确占据“复杂替换搜索 + 行为等价认证”。
- APIMig（IJCAI 2025）以多版本 API 演化知识图和变化链定位项目级受影响代码，再用语言模型完成跨多个大版本的迁移；它占据跨版本变化链与语言模型迁移组合。
- MCPEvol-Bench（arXiv:2607.14642）用 123 个 MCP 服务器和 11 类真实演化启发的突变直接测量动态工具演化，确认问题重要，但它是基准而非迁移方法，不能挽救方法新颖性。

## 主研究者裁决

暂定核的计算对象“工具计划”仍是客户端程序；把 API 客户端代码改称 Agent 技能或计划没有改变输入、候选变换、行为等价判据或搜索问题。跨版本差分、复杂多对多替换、黑盒语义建模、迁移合成和行为等价已经由上述谱系覆盖。剩余差异只有 Agent 运行时封装和 MCP 基准接入，属于模块拼接，未达到值得实现的 changed computation。

因此 `h-v008-001` 以 `prior_collision` 结束；不构造突变夹具，避免用已知问题制造装饰性实验。本裁决只杀死跨版本行为等价计划迁移方法族，不推出 Run-level No-Delivery。

## Active Diagnosis 后的 backtrack

FTS-only Recall 刷新状态为 `READY`，semantic 状态因索引缺失为 `DEGRADED`。Recall 仍包含 AppWorld 隐藏终局材料，故不得用于任何 AppWorld 程序、任务或科研结论。Diagnosis 只给事实、不裁决；主研究者据 v001-v008 的结构判断，前八版高度集中在执行正确性、验证、恢复与客户端程序变换。下一版本必须离开该盆地，转向信息获取与证据决策，而不是继续给执行器添加验证模块。

# v005 跨表示自洽的联合页链内核

## 权威请求键

每张观察同时包含两种表示：外层来源、单元、游标与快照元数据，以及适配器声明的规范请求载荷。v005 严格解析载荷，得到权威请求键：

```text
RequestKey = (
  connector_id,
  operation,
  authentication_subject,
  scope_schema_version,
  adapter_version,
  request_serialization_version,
  entity,
  time_bucket,
  archive_state,
  cursor,
  snapshot_id
)
```

载荷必须是字段集合精确、非空字符串有效、游标类型有效且重新序列化后逐字节相等的规范 JSON。

## 全局自洽预检

在来源过滤、单元分组、游标建链和见证扫描之前，内核检查全部已认证观察。若外层请求键、载荷请求键，或同一期望来源与快照下的任一记录单元指向当前主张，该观察即属于相关并集；两种请求键不相等、相关外层键对应的载荷无法规范解析，或记录单元不等于载荷请求单元时，整个主张返回未知。

因此，外层来源 T、载荷来源 S 的页面不能被当作真正异源页路由出 S 的冲突桶。只有外层键和载荷键一致且两者都不指向当前主张的页面，才可作为真正无关观察忽略。

页链随后只按载荷解析出的权威请求键建链。同请求同游标的不同页面摘要、记录单元错标、循环、孤立页、缺页、权限缺口或截断继续失败关闭。

## 证书模式版本 5

每张证书新增 `audit_observation_digests`，它是本次求值输入中全部相关观察摘要的排序多重集。第二证书验证路径重新计算该多重集；在验证输入中加入隐藏冲突页后，旧干净证书失效。

这个字段只承诺求值器实际收到的相关观察集合。它不能证明调用者没有在进入内核之前删页；要获得全局完整性，需要把输入根绑定到可信只追加日志或传输捕获批次。

## 第二实现路径

`independent_certificate_verifier.py` 不调用生产求值器、生产追踪器或生产载荷解析器。它单独实现规范 JSON 解析、跨表示相关并集、自洽检查、请求绑定摘要、游标闭合、见证、覆盖和观察多重集复核。

它仍是归一化观察级第二实现路径，不是形式化证明或原始传输级外部验证；两条路径共享数据类型和有限规范。

## 信任边界

方法只在以下条件下成立：适配器声明载荷真实覆盖语义参数；响应与所记录请求正确关联；快照、权限和联合分区声明真实；输入相关观察集合完整；结构化主张正确。真实连接器和自然语言端到端有效性尚未验证。

# v009 实现说明：固定信任锚下的非对称签名会话清单链

本目录实现结构化列表连接器上的联合范围证据协议。v009 针对 v008 最后一个决定性信任缺口：生产解码器若能在漏记录或伪终止后自行重算普通 SHA-256 响应承诺，v008 只能验证错误对象内部自洽，不能证明承诺来自生产路径之外的可信边界。

## 核心变化

1. `SourceIdentity` 新增签名方案、公钥标识、RSA 公钥、签名侧解码器摘要；生产内核只持验证材料。
2. 每页签名载荷绑定规范请求摘要、原始响应字节 SHA-256、规范记录承诺、当前/下一游标、状态、权限、截断、会话标识、页序号、前页签名摘要和解码器身份。
3. 页链必须从声明起始游标出发，在同一签名会话中满足连续序号与前页摘要；缺页、孤立终止、跨会话拼接、循环、分支和完全相同的重放页均失败关闭。
4. `ScopeCell.semantic_id` 由签名请求与记录共同绑定；同一表示版本的 B1/B2 原始别名可以路由到同一语义单元，声明中重复语义单元会被拒绝。
5. 证书升级为模式 9，请求绑定规则为 `signed-session-manifest-chain-v6`。第二验证路径独立实现规范编码、公钥验签、预检、页链与证书模式，不调用生产求值器。

## 文件

- `joint_coverage_kernel.py`：生产求值器、标准库 RSA PKCS#1 v1.5/SHA-256 验签、语义单元、签名会话页链、证书生成与验证入口。
- `independent_certificate_verifier.py`：不调用生产求值器的第二证书验证路径。
- `simulated_attestation_signer.py`：仅供确定性模拟回归使用的公开夹具私钥签名器；不得用于生产。
- `independent_raw_page_signer.py`：端到端实验的独立签名进程；不导入生产内核，使用 OpenSSL 一次性生成 RSA 私钥，从原始字节独立解码并签名，只输出公钥与清单。
- `signed_manifest_consumer.py`：独立生产消费者进程；从固定公钥信任锚而非自报清单加载可信来源身份，重新读取和解码原始字节，再调用生产求值和第二验证路径。
- `run_signed_trust_bridge_experiment.py`：受控多页夹具、两个真实签名者和多个消费者的端到端实验。
- `run_soundness_counterexamples.py`：194 个具有独立预期的声音性攻击案例。
- `test_joint_coverage_kernel.py` / `run_kernel_tests.py`：65 项单元、变形、证书重放与第二验证路径独立性测试。
- `run_joint_coverage_experiment.py`：756 个任务、5 个预算、7 种方法的 26,460 回合回归。
- `compare_v008_v009_regression.py`：把 v009 初始观察投影回精确 v008 摘要，比较配置与 13 个原有行为字段。

## 信任边界

生产验签信任根是声明配置中的固定公钥，而不是观察或清单自报的公钥。端到端实验明确包含第二个攻击签名者：它用另一把有效 RSA 私钥产生内部自洽、密码学可验的恶意清单；消费者因该来源身份不等于固定公钥信任锚而在进入内核前返回 `UNKNOWN`。

独立签名进程执行顺序如下：

1. 生成 2048 位一次性 RSA 密钥；
2. 从保存的原始字节独立解析完整有序记录与页面元数据；
3. 为各会话按序生成前向链接的规范签名载荷；
4. 用 OpenSSL 对 SHA-256 载荷签名；
5. 输出签名清单和公钥，不输出私钥；
6. 进程退出前销毁系统临时目录中的私钥文件。

消费者从单独的固定信任锚取得来源身份和公钥，核对清单来源完全相等，逐页核对原始字节摘要，独立解码，再构造观察。生产内核无法访问签名私钥；漏记录后重算普通承诺、伪终止后重算、改签名、改原始字节、改解码器、改会话、删中间页、拼接另一会话和重放页面都不能形成认证提交。

模拟主回归为了可复现和缓存性能使用公开夹具 RSA 私钥。它只证明协议逻辑和行为回归；真实非对称进程隔离与私钥不外泄由端到端信任桥实验单独验证，两种证据不可混写。

## 可复核主张

在固定公钥信任锚正确、签名进程独立且诚实、签名侧解码器摘要对应已审计代码、请求—响应关联与原始字节捕获正确、求值器收到全部相关签名页的条件下：

- 生产路径不能仅靠重算普通响应哈希，把签名后发生的漏记录或伪终止升级成有效证书；
- 页删除、跨会话拼接、孤立终止、分支/重复、循环与重放不能构成完整负证据链；
- 签名语义单元允许同版本原始别名安全路由，并阻止一个声明重复计算同一语义单元；
- 任一未带证明、签名无效、表示不一致或全局内部不自洽观察都会进入审计并使当前主张 `UNKNOWN`；
- 在 v008 的干净模拟任务投影上，v009 不改变旧配置和 13 个行为字段。

这些主张仍不等于服务提供方事实真实性、跨运行透明日志完整性、真实连接器全部分页行为已验证，或方法已具备论文级新颖性。固定信任锚的安全注册、密钥轮换/撤销、真实权限与截断语义、混合版本可用性及不共享执行器的强基线仍在方法上界之外。

## 已知边界

- 固定公钥信任锚的注册在原型中是受控带外步骤；没有实现硬件根、证书颁发机构或透明日志见证。
- 签名者保证“其所见原始字节及其解码结果”的不可由生产路径重签，不证明远端服务端从未漏项或撒谎。
- 真实 GitLab/Crossref 原始页仍沿用 v008 的页级集成证据；v009 的完整端到端签名实验使用已知真值的受控三页夹具。
- 跨运行删去整个签名会话仍需外部只追加批次根；v009 解决的是给定固定信任锚和已提交会话内的页删除/拼接。
- 三个规划/联合方法共享执行器，不能作为独立系统基线，也不支持查询性能优越性主张。

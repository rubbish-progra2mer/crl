## 主要优点

1. 在它明确覆盖的故障族内，逐坐标包络的代数关系是成立的：只要每个来源身份坐标至少在外层键或载荷键中出现期望值，快照同样至少一侧匹配，且请求或记录提供范围信号，观察就不能再用跨表示分裂逃出预检。随后两键不等或记录—请求不一致会先于建链、见证早停进入 `UNKNOWN`。

2. 两键完全相等时的快速路径与一般公式在文本上等价：来源身份和快照须完整匹配，范围可由请求单元或记录单元提供。容量为 65,536 的解析缓存、不可变派生值缓存和同次预检复用，若确实以完整不可变输入为键且只做纯函数记忆化，淘汰只影响性能，不应改变语义。

3. 非规范载荷被定义为显式错误并全局失败关闭，确实消除了此前未定义的路由分支；材料也诚实承认真正异源非规范页会污染无关主张，而没有把这一可用性损失包装成免费安全收益。

4. `semantic_normalization_version` 的表述总体克制：它只是绑定规范化方案版本，A028 仍被保留为真实连接器上待验证的外部前提，没有宣称已经证明语义等价请求具有唯一规范键。

5. `audit_observation_digests` 被明确限定为当前谓词选中的、求值器已收到的观察摘要排序多重集；材料没有把它越界描述成外部日志完整性证明、相关谓词一般完备性证明或可信传输根。

## 可复现核心漏洞

### 共同错误来源坐标可以屏蔽记录—请求不一致

按绑定文本的定义，仍能构造一个记录—请求不一致先把自身路由出 `possibly_relevant` 的最小输入。该构造不需要适配器同时伪造请求和响应，也不需要删除输入页。

设主张为：

- 来源身份为 `C`，其中 `authentication_subject=alice`；
- 快照为 `s1`；
- 联合范围 `U={B}`；
- 判断是否存在满足谓词 `P` 的记录。

干净观察 `o0`：

- 外层键与载荷键均为 `C/B/s1`；
- 空页且按现有规则可信终止。

冲突观察 `o1`：

- 外层键与载荷键均在其余六个来源坐标及快照上匹配 `C/s1`；
- 但两键的 `authentication_subject` 都是 `bob`；
- 两键请求单元均为范围外 `A`；
- 页面包含记录 `r`，其中 `r.cell=B` 且 `P(r)=TRUE`。

于是：

```text
source_possible(o1,C) = FALSE
```

因为认证主体这一坐标在两侧都不是 `alice`；

```text
snapshot_possible(o1,C) = TRUE
scope_possible(o1,C) = TRUE
```

后者由 `r.cell=B∈U` 提供，但最终：

```text
possibly_relevant(o1,C) = FALSE
```

因此 `record.cell != K_payload.cell` 永远不会进入一致性检查。`o1` 也不会进入 `audit_observation_digests`。在绑定文本所述的闭合规则下，`o0` 可以产生 `FALSE` 证书，而加入 `o1` 后证书仍不因当前谓词而失效。

若还要同时得到两键不等，只需让 `o1` 的外层游标与载荷游标不同；认证主体在两侧仍共同为 `bob`，所以观察仍在检查两键不等之前被路由出去。

这个构造能否成为外部真值上的错误认证，取决于一个当前没有写出的前提：记录是否被公理化为必然继承载荷键的全部来源身份、快照和范围语义。现有 A017、A018、A023、A025、A028 都没有明确保证“响应记录及终止元数据在语义上忠实于请求键”：

- A017 可成立：规范载荷诚实表示实际发出的 `bob/A` 请求；
- A018 可成立：键确实包含认证主体和请求范围；
- A023 可成立：该响应确实与这个请求配对；
- A025 可成立：求值器确实收到 `o0` 和 `o1`，没有删页；
- A028 可成立：规范化映射仍然唯一。

唯一额外事件是连接器对 `bob/A` 请求返回了真实归属于 `alice/B` 的记录，例如跨租户泄漏、服务端范围失效或错误缓存。当前明确前提没有排除它。A018 若被解释为已经排除这种行为，则材料必须明说“覆盖参数”同时蕴含“响应语义忠实遵守参数”；否则它不能替代该前提，尤其当前方法本身又专门检查记录—请求不一致。

更一般地，当前条件声音性缺少下列覆盖引理：

```text
semantic_relevant(o,C) ⇒ possibly_relevant(o,C)
```

A025 中“相关输入”的定义也必须独立于 `possibly_relevant`。若“相关”直接由当前谓词定义，则 A025 会循环假设谓词没有漏掉观察。

## 主张或证据越界

1. “跨表示不一致、记录—请求不一致一律失败关闭”过宽。当前规范只能保证“已经满足逐坐标包络的观察中的不一致失败关闭”。具有任一共同错误来源坐标或共同错误快照的观察，可以屏蔽其余冲突。

2. 当前前提没有说明外部真值究竟是连接器真实状态，还是仅相对于已认证响应字节的观察真值。若主张是外部事实，需要增加响应内容、记录归属、快照和终止信号的语义忠实前提；若只是观察相对结论，则必须相应收缩“外部验证”“条件声音性”等措辞。

3. 五份绑定材料只提供实验计数、摘要字符串和实现独立性的文字陈述，没有绑定逐项攻击清单、原始结果、实现源文件或执行记录。因此本次文字评审只能确认计数内部一致，不能独立确认 150 项是否包含上述共同错误坐标组合，也不能确认缓存键完整或第二路径没有共享生产辅助逻辑。摘要字符串在目标字节未纳入评审包时不能单独提供可核验性。

4. 排除整个“初始观察摘要”不足以证明 v005 与 v006 输入除新增语义规范化版本外完全相同。原始摘要预期变化是合理的，但应比较删除该新增字段后的规范投影，或逐字段确认其余观察内容相同。当前 13 个行为字段零差异只能证明选定输出相同，不能单独排除输入同步变化。

5. 最近工作部分没有明显宽泛抢占，但“当前已核材料未显示同构方法”不能作为正面新颖性证据；在未提供检索覆盖范围前，只能维持“尚未知”的表述。材料目前基本守住了这一边界。

## 必须修改项

1. 在下列两条路线中明确选择一条：

   - 方法路线：对所有已认证观察全局检查两键不等和记录—请求不一致；或为记录增加独立认证的来源身份与快照归属，并将这些坐标纳入包络。前者会扩大可用性损失，但能关闭上述逃逸。
   - 契约路线：增加明确前提，规定任何语义上影响主张的观察必满足逐坐标可见性，且响应记录、页元数据和可信终止信号忠实继承规范载荷键的来源、快照及范围语义。随后把声音性主张严格收缩到该观察模型。

2. 独立定义 `semantic_relevant`，并给出或验证“语义相关必然落入包络”的覆盖引理；不得用当前选择谓词自身定义 A025 的“相关”。

3. 将上述“共同错误认证主体＋范围外请求＋范围内记录”加入正式攻击面板，至少覆盖存在假证书、全称真证书和两种输入顺序。若设计选择把它排除在模型外，测试也应明确记录排除所依赖的新增前提。

4. 改写所有“一律失败关闭”措辞为精确的条件式表述，并明确证书摘要不能发现被相关谓词漏选的观察。

5. 对 v005/v006 初始观察做去除新增版本字段后的规范投影比较，列明 13 个行为字段；若要让独立文字评审核验正式证据，还应把逐项案例清单与结果清单纳入固定评审材料。

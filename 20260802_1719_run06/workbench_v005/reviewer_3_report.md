## 核心漏洞

### 记录侧相关与非规范载荷之间存在未定义分支

固定材料规定：

- 观察可以因 `record_targets` 成为相关观察；
- 但载荷不能规范解析时，仅明确规定“外层键相关”才返回 `UNKNOWN`；
- `K_outer != K_payload` 和“记录单元不等于载荷请求单元”都要求 `K_payload` 已经存在。

因此，记录侧相关、外层完整键不相关、载荷语义完整但字节非规范时，规范没有给出必然失败关闭的规则。

最小输入构造如下：

- 主张 `C`：来源 `S`、快照 `σ`、范围仅含单元 `B`，判断是否存在满足谓词 `P` 的记录。
- 观察 `o0`：已认证；外层键与规范载荷键均为 `S/B/σ/起始游标`；页面为空且可信终止。单独使用它会认证存在为假。
- 观察 `o1`：已认证；外层键指向同一来源和快照下的范围外单元 `A`；请求载荷语义上也完整、正确地表示 `A`，但只改变 JSON 键顺序或加入合法空白，使其不能通过逐字节规范重序列化；实际响应含记录 `r`，其真实单元为 `B`，且 `P(r)=真`。

这里：

- `targets(K_outer,C)=假`，因为请求单元为 `A`；
- 严格解析不能产生有效 `K_payload`；
- `record_targets(o1,C)=真`；
- 但材料只保证“外层键相关且载荷不能规范解析”失败关闭；
- 后两项比较因 `K_payload` 不存在而没有定义。

若实现跳过该观察，`o0` 会产生错误的存在假证书；全称方向可用一个违反谓词的 `B` 记录构造错误的全称真证书。这个构造不删除输入页，也不要求适配器同时伪造请求与响应：请求确实是 `A`，响应也确实与该请求关联，只是连接器返回了错单元记录——这正是记录—请求一致性检查声称处理的故障。

我没有读取代码，因此不能断言当前 Python 实现实际返回错误结果；结论是当前固定规范允许该路径，而 81 项面板和 35 项测试的文字摘要没有证明这个组合已经覆盖。

### `record_targets` 的来源与快照权威不明确

材料只写“页面来源与快照对应当前主张”，没有说明在外层键与载荷键不一致时取哪一侧。

例如：

- 外层键为 `T/A/σ`；
- 规范载荷键为 `S/A/σ`；
- 记录属于目标单元 `B`；
- 主张为 `S/B/σ`。

若记录相关性使用外层来源，该页会被路由掉；若使用载荷来源，则会正确进入检查域。由于本方法的核心就是禁止外层重标控制路由，这里必须给出形式化定义，不能留给实现惯例。

### 相关摘要不能修复相关集合漏项

`audit_observation_digests` 只承诺已经被 `relevant` 判定为相关的观察。若上述组合页在相关性或解析分支中被漏掉，生产路径和共享同一有限规范的第二路径都可能重算出同一个不完整多重集，证书仍然自洽。因此该字段不是上述漏洞的补救。

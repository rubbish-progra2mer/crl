# 跨表示自洽的请求绑定联合页链协议：面向大语言模型列表连接器的失败关闭研究种子

## 交付定位

本版本把请求绑定从“桶内载荷相等”推进到“路由前跨表示自洽”：

> 对外部验证的结构化主张，任何已认证观察只要其外层请求键或规范载荷请求键任一侧指向当前主张，就必须在来源过滤、单元分组、游标建链和见证扫描之前证明两种表示完全一致；证书同时承诺求值输入中的全部相关观察多重集。已知不一致一律失败关闭。

这是一颗完成本地决定性反例验证、可进入真实连接器扩大阶段的窄系统研究种子。它不声称自然语言主张编译安全，不声称适配器声明等于传输事实，不声称请求与响应正确关联已经验证，不声称提出新的查询完备性、有限访问、证明驱动规划、动态契约或验证侧车理论，也不声称论文级新颖性已经建立。

## v004 的决定性故障

v004 已把具体单元、游标、快照和来源写入规范载荷，却仍先按外层 `cell` 和 `source` 过滤，再检查桶内载荷。三名互不可见的 v004 Reviewer 独立指出：一张载荷实际指向期望来源 S、外层来源却重标为 T 的冲突页，会被当作异源页移出 S 的冲突桶；合法空页随后可错误认证存在假或全称真。

主研究者直接调用冻结 v004 原实现重放：

- 空页：外层 S、载荷 S、当前单元、起始游标、可信终止；
- 见证页：外层 T、载荷仍为同一 S 请求、同单元同游标、包含正面记录、可信终止。

v004 返回 `FALSE`、证明类型为联合范围覆盖，第二验证路径判证书有效，构成错误认证提交。重放结果 SHA-256 为 `f1b3878937e474996b890090638234f9e84b580c65b402ebff5133dd0c47752b`。

因此 v005 不是增加测试数量，而是改变证据路由权威和证书语义。

## 方法内核

### 两种请求表示

每张观察具有外层请求键：

```text
K_outer = (
  connector_id, operation, authentication_subject,
  scope_schema_version, adapter_version,
  request_serialization_version,
  entity, time_bucket, archive_state,
  cursor, snapshot_id
)
```

观察还携带适配器声明的规范请求 JSON。v005 不使用外层标签替载荷选择解释方式，而是严格解析载荷得到同构权威键 `K_payload`。载荷必须满足：顶层和过滤器字段集合精确；所有字符串非空；游标仅为字符串或整数；以固定规则重新序列化后与原字节完全相等。

### 相关并集与自洽预检

对主张 `C`，定义请求键相关条件：来源身份等于 `C` 的期望来源，单元属于 `C` 的联合范围，快照等于 `C` 的快照。游标可以是该页链中的任意令牌。

一张已认证观察属于相关集合，当且仅当：

```text
relevant(o,C) =
  targets(K_outer(o), C)
  OR targets(K_payload(o), C)
  OR record_targets(o, C)
```

其中 `record_targets` 表示页面来源与快照对应当前主张，且至少一条记录的单元属于主张范围。若外层键相关但载荷无法规范解析、相关观察满足 `K_outer != K_payload`，或任一记录单元不等于载荷请求单元，整个主张立即返回 `UNKNOWN`。这个检查发生在任何来源过滤、范围过滤、游标分组和见证扫描之前。

这样可以区分：

- 外层 T、载荷也为 T 的真正异源页：两表示一致且都不相关，可忽略；
- 外层 T、载荷为当前期望 S 的重标页：载荷侧相关且两表示不一致，必须污染当前主张并失败关闭。
- 请求键一致地指向范围外单元 A、记录却指向主张内单元 B：记录侧相关且记录—请求不一致，必须失败关闭。

### 载荷权威页链

通过预检后，页链只按载荷解析键建链。对主张范围中的每个联合单元：

- 来源、单元和快照必须与主张一致；
- 当前游标必须从起始游标沿前页声明的下一游标准确可达；
- 同请求同游标不能有不同页面摘要；
- 页内记录单元必须等于请求单元；
- 游标不得循环，不得有孤立页面或已知截断；
- 状态、认证和权限完整性必须满足既有失败关闭条件；
- 只有可信终止才能闭合页面链。

存在真与全称假仍可由范围内见证早停，但任何全局跨表示冲突、同游标冲突或记录错标都在见证之前处理。存在假与全称真要求全部联合单元闭合。

### 相关观察多重集证书

证书模式版本升级为 5。除证明所用页面摘要外，新增：

```text
audit_observation_digests = sort(multiset(
  digest(o) for all relevant input observations o
))
```

第二实现路径独立重算该多重集。只含干净空页生成的旧证书，在验证输入加入外层重标冲突页后失效，不能通过把冲突页重新归类为异源而继续使用。

这个承诺只覆盖求值器收到的输入。若调用者可以在进入内核前删除日志页面，证书无法凭空证明历史完整；可信只追加日志或传输捕获批次根仍是扩大阶段要求。

## 条件声音性边界

本种子的本地结论严格条件化于：

1. 适配器声明的规范请求载荷真实覆盖所有响应语义参数；
2. 每张响应与所记录请求在并发、重试和缓存命中下正确关联；
3. 求值器接收到完整的相关观察集合；
4. 快照、权限和联合范围分区声明真实；
5. 自然语言已经由外部安全地编译成正确结构化主张；
6. SHA-256 摘要和可信采集层不被攻破。

假设账本 A023 和 A025 仍为未验证。v005 证明的是这些前提下所列攻击被当前实现失败关闭，不是一般形式化声音性定理。

## 第二证书验证路径

`independent_certificate_verifier.py` 不调用生产求值器、生产追踪器或生产规范载荷解析器。它单独实现字段模式验证、规范序列化检查、外层键构造、载荷键解析、相关并集、自洽预检、请求绑定摘要、游标闭合、见证、覆盖与相关观察多重集复核。

它仍共享数据类型、谓词定义和有限方法规范，准确名称是“归一化观察级第二实现路径”，不是形式化证明、独立真值裁决或传输级外部验证。

## 正式实验

### 81 项跨表示与记录路由攻击

正式尝试 `cross-representation-counterexamples-r2-v005` 运行 81 项，全部通过，错误认证提交 0。核心 9×2×2 矩阵逐字段覆盖：连接器、操作、认证主体、范围模式、适配器版本、序列化版本、联合单元、快照和游标；两种量词为存在与全称；每种输入采用正序和反序。对应错误覆盖方向均返回 `UNKNOWN`，顺序对证书摘要稳定。

面板同时保留范围外见证、跨来源页链、见证加冲突、不透明游标循环、真正异源页、多类证书变异，以及请求范围外但记录单元范围内的存在/全称双向反例。结果 SHA-256 为 `7baaba2454321059faec0cb708d04a334c40dd6536b1300b5dfe84490807c155`。

### 35 项单元与边界测试

正式尝试 `kernel-tests-35-v005` 运行 35 项，失败 0、错误 0、跳过 0。结果 SHA-256 为 `36560d30d8d12d4ba17293ce4e669e2879c34e9b68f4b9baf048e524345e68ce`。

### 26,460 回合干净回归

正式尝试 `cross-representation-joint-coverage-756x5-r2-v005` 使用 3 个固定随机种子、54 个世界、756 个主张任务、5 档预算和 7 种方法，共 26,460 回合。

- v004 与 v005 的 26,460 行在主张、预算、方法、决定、工具调用数、正确性和错误提交上差异 0；
- 初始观察摘要不一致 0；

## 真实计算成本

v005 r2 正式主尝试约 270.85 秒，v004 同规模尝试约 167.26 秒；当前 v005 原型约慢 1.62 倍。七个方法的工具调用行为不变，但总体实现成本仍明显增加。

最终实现分别在生产和第二路径中使用容量 4096 的有界载荷解析缓存，已把未缓存版本约 639.97 秒的时长明显降低；相关集合与摘要多重集仍会重复计算，也没有预索引或增量根。因此 270.85 秒不是机制的固有下界，却仍是不能省略的当前事实。后续比较必须同时报告宿主计算、端到端延迟、字节、工具调用和适配器成本。

## 最近工作与贡献上界

数据库工作已经覆盖有限访问下完整答案、访问限制与完整性约束、证明驱动计划、成本搜索和结果有界接口；ToolGate 和 EG-VAR 已覆盖动态契约、提交验证、证明义务、证书和弃权。因此这些类别都不是本种子的贡献。

可能保留的窄系统差异仅是：大语言模型列表连接器中，外层观察元数据与适配器声明请求载荷在证据路由前的相关并集自洽检查，以及把相关观察输入承诺接入失败关闭页链的具体协议。这个差异尚未经过更广最近工作排查和真实连接器验证，论文级新颖性未知。

三种强解释框架共享同一个精确范围执行函数，完全等价不是独立强系统比较。v005 不能声称击败动态契约或证明驱动规划器。

## 已知边界

1. 适配器声明不是独立传输事实。
2. 请求—响应正确关联仍是假设，当前没有交换标识或原始响应摘要。
3. 相关观察多重集不能证明外部输入集合完整。
4. 规范载荷可能遗漏真实接口的隐式语义参数。
5. 快照、权限和联合分区真实性未被验证。
6. 自然语言主张编译器尚未实现。
7. 第二实现路径不是形式化证明或传输级独立核验。
8. 当前原型宿主运行时显著增加，尚未优化。
9. 三个本地夹具不能估计真实故障率或端到端价值。
10. 独立强基线与论文级新颖性仍未建立。

## 为什么值得继续扩大

v005 关闭了 v004 三审共同发现并由原实现复现的错误认证路径，而且不是只补一个来源字段：它把九类可路由字段统一纳入“外层键或载荷键相关”的预检不变量，并同时覆盖存在假、全称真和两种输入顺序；证书又显式承诺求值输入中的相关观察多重集。修复在 26,460 行干净回归上没有改变决定或工具调用。

下一次决定性扩大应停止继续堆叠本地模拟器，选择两至三个真实列表连接器，从可信传输层绑定交换标识、原始请求摘要、原始响应摘要和只追加批次根；独立标注自然语言主张、请求范围、可见范围与终局事实。基线应包括同信息同证书能力的强动态契约、原生精确查询和原生优先回退系统，同时报告错误提交、未知、宿主时间、端到端延迟、字节、重试与适配器成本。

若真实连接器没有可独立取得的请求—响应绑定、跨表示故障极少、自然语言编译错误占主导、强基线完全吸收机制，或最近工作已经覆盖同构协议，则应收缩为连接器完备性审计基准，必要时终止方法主张。

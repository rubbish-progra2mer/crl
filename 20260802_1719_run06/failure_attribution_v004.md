# v004 失败归因与修复边界

## v003 的具体单元请求绑定缺口

v003 的 `SourceIdentity` 只包含连接器、操作签名、认证主体和范围模式版本。主实验的操作签名对所有联合单元都是同一个 `list-one-joint-cell-v1`，具体实体、时间桶和归档状态没有进入页面请求身份。

这在有记录时可能被 `record.cell == observation.cell` 交叉检查发现，但空页面没有记录级单元。若适配器实际请求单元 A，却把空响应标注为单元 B，v003 只看到“B 的空终止页”，会为“B 中不存在目标”生成完整覆盖证书。

工作台直接调用冻结 v003 原实现得到：实际请求外部事实为 `A|recent|active`，观察标注为 `B|recent|active`，v003 返回 `FALSE`、证明类型为联合范围覆盖，且原验证器判证书有效。结果文件 SHA-256 为 `dbd86596555047b8f318665a135e3d264b40bb643d11d9cdb894c29bb2cf3214`。v003 无法在自己的数据结构内表达实际请求单元，这正是漏洞本身，而不是测试遗漏一个现有字段。

## v004 修复

### 规范请求载荷

新增确定性规范载荷：

```text
RequestPayload = canonical_json(
  connector_id,
  operation,
  authentication_subject,
  entity,
  time_bucket,
  archive_state,
  cursor,
  snapshot_id,
  adapter_version,
  scope_schema_version,
  request_serialization_version
)
```

观察摘要绑定完整载荷和载荷摘要。生产追踪器不信任 `observation.cell` 足以证明请求范围，而是根据主张单元、游标和快照重算期望载荷并做精确字节比较。

### 冲突优先于见证

同一期望来源中出现错误请求绑定、记录单元错标或同游标不同页面时，追踪器先把单元标记为冲突，然后才考虑任何见证。因此：

- 合法见证与同游标终止页冲突时，两种输入顺序都返回 `UNKNOWN`；
- 合法见证后出现错误单元绑定续页时仍返回 `UNKNOWN`；
- 查询操作、认证主体或范围模式不同的续页不能闭合生产页链。

### 证书模式升级

证书模式升级为版本 4，并新增请求绑定规则摘要。第二条验证路径独立重构规范请求载荷和请求绑定摘要，拒绝跨来源覆盖、隐藏冲突、游标循环、错误终止、错误单元绑定和范围外见证等变异证书。

## 仍然没有解决的问题

1. 适配器如实记录实际出站请求仍是信任前提；若适配器同时伪造请求和响应，内核只能验证内部一致性。
2. 当前规范载荷只覆盖本地夹具已建模的语义参数；真实接口可能还有租户、区域、排序、隐式默认过滤器或特性开关。
3. 快照标识、权限完整和联合单元分区的真实性仍由连接器或可信运行时承担。
4. 第二验证路径不是传输级外部核验，也不是形式化证明。
5. 自然语言到结构化主张的危险欠近似尚未解决。
6. 三个半真实夹具不能估计真实故障发生率、适配器开发成本或端到端收益。

对应假设已保留在 `research_workspace/wiki/assumption_ledger.md` 的 A016–A021；未验证前提没有被升级为事实。

# 独立科研审阅意见

## 总体判断

建议交付当前严格限定的 v009 研究种子，但不得把它表述为生产级端到端安全方案、真实连接器完整性证明或已具备论文级新颖性的方法。

在五份绑定材料声明的前提内部，我没有找到一个既保持固定公钥信任锚、私钥不向生产路径泄露、签名侧诚实解码、请求—响应正确关联、完整提交声明会话以及服务端语义真实性，又能产生错误认证提交的可复现最小构造。v008 的循环自证缺口已经被实质性关闭，而不是仅增加字段或测试数量。

## 当前最强价值

最强价值是信任图发生了真实变化：承诺生成权从待约束的生产求值路径移到了只持私钥的独立签名者，消费者只持固定公钥。生产侧对记录、终止状态或普通响应承诺的重算不再足以恢复有效证明。第二把有效密钥自签清单仍被固定信任锚拒绝，也直接验证了验证公钥不是从攻击者清单自报后接受。

分页会话链、语义标识和三值许可的组合也具有方法种子价值：

- 页签名同时绑定原始响应摘要、规范请求、解码语义、当前及下一游标、会话、页序和前页签名摘要；
- 删除中间页、保留孤立终止页、跨会话拼页、同页重放、循环和分支均不能形成完整负证据；
- 同版本 B1/B2 通过签名侧 `semantic_id` 路由，声明中的重复语义单元被拒绝；
- 存在见证或全称反例与需要闭合整条页链的负证据被置于同一个失败关闭的 `TRUE/FALSE/UNKNOWN` 许可路径内。

相对 v008，这些变化同时改变了权限边界、数据流和实际计算，足以构成“值得继续扩大”的窄研究种子。

## 可复现核心漏洞判断

绑定材料内部未呈现可复现的核心声音性漏洞。几个最接近的攻击均落在明确保留的外部前提上。

最小边界构造是：可信签名者对同一请求产生一个完整空终止会话 S0，另有一个包含阳性记录的完整会话 S1；收集方只向验证器提交 S0。验证器可能据 S0 对存在主张认证 `FALSE`。这个构造不需要替换信任锚、泄露私钥或破坏 S0 的内部链，但它删除了整段 S1，因此正是 A025 所保留的“未提交会话或会话根不可见”问题。它推翻“整个采集历史完整”，却不推翻当前严格限定的“给定已提交声明会话，其内部连续性完整”。交付文本必须始终保持这个量词边界。

类似地：

- 用第二把有效私钥签署恶意空终止清单会因固定信任锚不匹配而失败；
- 让 B1/B2 错误合并或拆分需要破坏签名侧语义映射诚实性，属于 A028/A031；
- 让签名者签署漏项或错误终止响应需要破坏签名侧解码或服务端真实性；
- 用旧证书跨会话重放需要绕过已声明绑定的会话、来源、主张和全部观察字段，现有材料没有给出这种路径。

有一个尚不能从 Markdown 排除、但也不能据此宣称已存在漏洞的问题：签名载荷公式只以 `H(字段元组)` 概括规范编码，没有给出长度前缀、类型标签、空值与空字符串区分、整数编码、Unicode 规范化、映射排序、重复键处理及域分离的完整协议。材料声称两个实现路径均实现规范编码，但本次审阅没有代码依据，因而不能认证不存在编码歧义或类型混淆。这是必须补足的可审计规范，不是当前已经复现的反例。

## 主张与证据边界

13 场景双进程实验可以作为当前窄核心主张的最低限度非同源验证：签名者不导入生产内核，密钥和签名由独立进程及标准密码学工具产生，预期又来自受控原始字节的已知真值。它足以支撑“错误普通重算无法越过固定公钥边界”和“会话内删拼页失败关闭”。

但这种独立性仅是实现路径和测试真值层面的局部独立。第二验证路径仍共享协议规范、数据类型和 Python 运行时；受控三页夹具也由同一研究流程构造。因此它不能被描述为形式化证明、外部事实验证或真实连接器非同源系统评测。

其余证据也必须按以下上界解释：

- 194/194 和 65/65 证明冻结攻击集合与测试集合内未出现错误提交，不证明协议对全部攻击完备；
- 26,460 回归主要证明旧行为非回归和模拟分布内回答正确，不能替代真实多页连接器安全验证；
- 3,780/3,780 只适用于联合覆盖门的证书分母；
- 两项双进程场景在内核或固定信任锚之前拒绝，其第二证书验证分母不是 13；
- 进程标识不同和声明输出中没有私钥文件，只证明实验级进程分离及输出约束，不证明硬件隔离、不可提取或完整密钥生命周期；
- 三个共享执行器的方法不能包装为独立强基线；
- 约 95.3% 的宿主时长增加排除了低开销或性能优势主张，但在当前以声音性为目标的研究种子阶段不构成交付阻断；
- 受控 B1/B2 结果只支持已给定正确 `semantic_id` 时的协议路由，不支持真实连接器语义规范化已经解决。

## 最近工作与方法潜力

非对称签名、固定公钥、签名元数据链、一次性密钥、来源证明和透明日志均已有成熟工作。尤其 in-toto 已强覆盖“指定受信主体签署链接元数据并由布局验签”，证书透明度和 Sigstore 又提供了比当前单会话前向链更强的只追加、身份及多视图机制。

因此，当前可辩护贡献只是面向工具智能体有限联合主张许可的任务特定协议组合，而不是密码学类别创新。它有研究种子价值，但论文潜力是条件性的：若下一阶段不能在真实多页连接器、外部会话根、密钥生命周期、独立系统基线和安全—可用性权衡上形成相对既有来源证明系统的独特计算或问题结构，就应停止新颖性宣传，将其定位为工程安全协议。

## 必须修改项

交付前至少应收紧以下文字或协议说明：

1. 把真值域明确写成“一个由固定信任锚认可、显式选定且完整提交的签名会话”，并明确不保证其他未提交会话、整个采集历史或远端数据库完整。
2. 给出签名载荷和证书载荷的逐字节规范编码，包括类型、长度、排序、空值、Unicode、重复键、域分离及首页面前驱哨兵；最好提供跨实现测试向量。
3. 将“独立验证”统一限定为“第二实现路径”，将双进程实验限定为受控已知真值验证，避免使用“外部验证”“形式化验证”或“真实连接器验证”等表述。
4. 在证据表中明确区分 13 个场景中 11 个进入证书路径、2 个在内核或信任锚前拒绝，避免把 13/13 描述成 13 个证书均由第二路径复核。
5. 将“私钥文件为 0”“进程标识不同”保留为实验观测，不提升为硬件隔离、私钥不可提取或生产密钥安全。
6. 将 B1/B2 主张限定为“给定可信签名侧语义映射后的别名路由正确”，继续保留 A028/A031。
7. 明确 26,460 回归、共享执行器基线和 1.953 时长比各自只支持什么，禁止性能、新颖性或独立系统胜出外推。

这些问题需要收紧当前 Seed 的可审计边界，但不要求为了交付这个严格限定的研究种子再开启一个科学版本。透明日志或可信批次根、硬件根、真实连接器、多验证器一致视图、密钥轮换撤销、不共享实现的强基线及论文级新颖性，属于下一科学版本的扩大任务。

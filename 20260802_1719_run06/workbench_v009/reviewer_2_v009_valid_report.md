# Reviewer 2 独立评审报告

## 总体结论

**建议：交付当前严格限定的研究种子，但在定稿前完成若干规格与措辞收紧；不需要仅因现有核心机制再进入下一科学版本。**

仅依据六份固定材料，我没有找到一个同时满足以下明示前提、又能让生产侧错误认证 `TRUE` 或 `FALSE` 的可复现最小反例：

- 公钥由独立可信渠道固定；
- 生产路径拿不到签名私钥；
- 签名者诚实执行声明的解码器；
- 请求与原始响应正确关联；
- 验证器收到声明会话的全部相关签名页；
- 快照、权限和服务端语义正确。

v009 相对 v008 确实改变了信任图：生产路径只能验签、重算和弃权，不能在漏记录或伪终止后重新产生可信承诺。当前最强价值不是“数字签名”本身，而是把固定信任锚、原始响应与规范语义的共同签名、分页会话连续性、语义单元规范形和三值证书许可放进同一条失败关闭路径，并直接复现关闭了 v008 的循环自证漏洞。

## 最小反例审查

### 1. 漏记录或伪终止后重算

设可信签名页原本含阳性记录，生产解码器删除该记录、把页面改为空终止页并重算普通响应承诺。新对象的记录承诺、终止字段和原始字节摘要均与原签名载荷不同；生产侧没有私钥，不能生成新签名。

在固定信任锚与私钥隔离前提内，该构造只能验签失败并返回 `UNKNOWN`，不能复现 v008 的错误 `FALSE`。这是 v009 最扎实的改进。

### 2. 删除 P1、保留或拼接 E(c2)

对原链 `P0(initial→c1), P1(c1→c2), P2(c2→终止)`：

- 删除 P1 后，从 P0 得到的下一期望游标仍是 c1，c2 终止页不能填补该位置；
- 另一会话的 c2 页还会在会话标识、页序号或前页签名摘要上不匹配；
- 孤立非初始终止页不能充当起始页；
- 完全相同页面重放会触发游标冲突。

因此该 Reviewer 构造在当前协议描述下只能 `UNKNOWN`。

### 3. 整段会话删除

删除整个签名会话或隐藏可信会话根，仍可能让验证器根本不知道该会话存在。这不违反固定公钥、私钥隔离或签名者诚实，但**违反“验证器收到全部相关签名页”这一明示前提**。它是 A025 的真实外部边界，不能用来击穿当前局部主张，也不能被宣传为已经解决。

### 4. 完整旧会话原样重放

材料没有显示一次性挑战、可信时间或外部会话根。因此，对相同公钥、请求、声明快照和主张，完整旧会话可能被原样重放。若声明仍指向同一快照，这不产生事实错误；若拿旧会话回答“当前状态”，则需要错误或欠明确的快照/新鲜度语义，落入 A031 或主张编译边界。

这不是当前核心主张的内部反例，但应明确写成“同一声明快照下允许重放；新鲜度不在当前保证内”。

### 5. 规范编码歧义

六份材料声称存在“规范编码”和第二实现路径，但没有给出足以排除以下碰撞的完整编码契约：

- 字符串 `"1"` 与整数 `1`；
- 字段缺失与显式空值；
- 无长度分隔时的 `("ab","c")` 与 `("a","bc")`；
- 重复对象键、数值表示、统一码归一化和字段顺序；
- `H(M前页, 签名前页)` 的类型和域分离。

我不能据此断言实现存在漏洞，因为未查看代码；但这是当前材料中唯一可能在不违反外部信任前提时直接影响签名消息唯一性的内部规格缺口。定稿应明确编码是类型标记、长度分隔、字段域分离且拒绝重复键的单射规范，或者准确引用冻结的规范算法。

## 五类判断

### 内部逻辑充分性

在材料明示的密码学与输入前提下，核心逻辑基本充分：固定公钥排除攻击者自签清单；每页绑定请求、原始字节、规范记录、游标、终止、权限、截断、会话、页序、前页链接和解码器身份；链从起始游标闭合；重复游标、跨会话拼接、循环和分支均失败关闭。

主要缺口是规范编码未在文字规格中完全闭合，以及“证明状态”究竟是签名字段、验签派生状态还是证书外层字段需要写得更明确。实验中的“证明布尔状态降级”通过不能替代消息格式定义。

### 实验支持

实验口径总体透明：

- 194/194 攻击和 65/65 测试支持受控反例关闭；
- 双进程实验使用实际非对称签名、两个不同密钥和固定信任锚，13/13 达到预期；
- 其中 11 项由第二证书路径复核，原始字节变异和错误信任锚两项在内核前拒绝，分母没有混写；
- 26,460 回合与 v008 精确投影主要支持行为非回归，不是新的密码学证明；
- 受控三页夹具的预期来自已知页面事实和明确拒绝条件，不是生产求值器自行给自己打分，因此足以作为当前窄机制种子的非循环验证；但仍不是外部真实连接器或独立协议实现验证。

第二验证路径共享协议、数据类型和运行时，只能称“第二实现路径”，不能称形式化验证或强独立验证。材料对此表述基本诚实。

### 信任根闭合

当前受控信任根闭合是成立的：消费者先固定可信公钥，另一把有效密钥的自签清单被拒绝。

但不同进程标识和声明输出中没有私钥文件，只能说明实验未把私钥作为声明产物传递，不能证明操作系统级、硬件级或攻击面意义上的私钥不可访问。固定公钥注册、轮换、撤销、回滚和多验证器一致视图均未闭合。这些是后续扩大问题，不阻塞当前条件式 Seed。

### 外部有效性

v009 尚无真实多页连接器上的签名闭环。真实 GitLab/Crossref 证据沿用 v008 且只有第一页，因此不能支持真实分页、权限变化、重试、乱序、缓存或语义别名映射。

这一局限已被如实保留为 A025、A028、A031、A041 等边界。只要最终交付继续把真值域限定为“签名者所见并按声明解码器解释的可见关系”，外部有效性不足不阻塞当前种子。

### 最近工作碰撞

根据材料中的最近工作映射，非对称签名、固定公钥、链式元数据、来源证明、一次性密钥和只追加日志都有强先例。尤其 in-toto 已强覆盖“指定主体签署元数据并由固定布局和公钥验证”的主要密码学结构；证书透明度和 Sigstore 在日志、身份与多视图审计方面明显更强。

因此当前贡献只能定位为工具智能体有限联合范围主张的任务特定协议组合。论文级新颖性尚未建立。若后续无法证明“三值主张许可＋分页闭包＋语义联合单元”产生超出成熟来源证明直接套用的新理论、协议不变量或经验权衡，应停止新颖性宣传并将其保留为工程安全协议。

## 定稿前必须修改

1. 补全签名消息的规范编码契约，明确类型、长度、字段域、空值、重复键、排序、数值和统一码规则。
2. 明确证明布尔状态与签名验证结果的关系，避免读者误以为一个可改写布尔字段本身构成真实性根。
3. 把“私钥无法访问”收缩为实验直接支持的事实：未传入消费者、未出现在声明输出、使用后删除；不要外推为硬件或操作系统级隔离证明。
4. 明确区分“收到的会话内部连续性”与“所有相关会话均被提交”；终止后孤立页拒绝仅针对进入全局审计的观察集合。
5. 明确完整旧会话重放与新鲜度边界：相同声明快照下的重放不改变结论，跨时间的当前态保证需要可信快照、时间或外部日志。
6. 将受控三页实验表述为条件式机制验证，不写成真实连接器事实验证或强外部验证。

## 最终建议

**交付当前严格限定的研究种子。**

不存在已确认、可复现且不违反明示前提的核心错误认证构造。现存最大风险主要位于外部信任锚、整段会话可发现性、真实连接器语义、密钥生命周期、强独立基线和论文新颖性，而非当前固定信任锚下的局部方法核。

约 95.3% 的宿主时长增加不阻塞声音性研究种子，因为材料已撤销低开销主张并将其列为优化任务；但它阻止任何性能优势或“轻量级”表述。

# v034 Selection Context

## Durable starting point

v033 is frozen as `NO_GO_FOR_CONFIRMATION`. Its successful-only conditional
action innovation reached AUC `0.771443`, while the strongest mandatory
`task_concat` comparator reached `0.864684`; every generator, every source and
all `8/8` conjunctive gates failed. v034 cannot retune or reuse v033's
vocabulary, SVD, ridge map, residual, folds, controls, subsets, gates or Claim.

Earlier Run versions also rejected retrieval alignment, donor matching,
prompt-redaction, precedence aggregation, signed lexical residuals,
support-selection, role factorization and mutation-role pooling. v034 therefore
selects a new carrier, a new learned signal and a new evaluation boundary:
pairwise next-action judgment on ToolPRMBench by a frozen causal language model.

files. Before selecting the v034 computation, the current main Codex acquired
and read only:

- GTA: 118 pairs;

These 315 pairs are exposed Development. Exploratory character/word TF-IDF and

not present, has not been downloaded and has not been read. It may be acquired
only after every frozen Development gate passes and the main Codex writes a
positive Promotion Audit.

## Open-network nearest-prior check

Four views were checked against fixed primary-source bytes:

- benchmark and base-model view: ToolPRMBench;
- decomposition and aggregation view: Recursive Rubric Decomposition;
- learned pairwise reward-model view: ToolRM;
- executable-state and process-verification view: Tool-Verifier, supplemented
  by the formal-knowledge-base ToolGate paper.

The current main Codex directly read the relevant original sections.
ToolPRMBench already evaluates pairwise step judgments and tool-specialized
PRMs. RRD already establishes recursive rubric decomposition, rubric filtering
and correlation-aware aggregation. ToolRM already trains generative and
discriminative pairwise tool-use reward models. Tool-Verifier already combines
executable outcome consistency with an LLM committee, and ToolGate already
uses pre/postcondition contracts over trusted state.

Consequently, v034 cannot claim generic rubric decomposition, generic
tool-action evaluation, learned pairwise reward modeling, executable
verification or formal correctness.

## Selected computation

The surviving narrow question is whether a small frozen judge can benefit from
mechanically compiled, complementary tool-contract views and a conjunctive
bottleneck rather than a holistic impression.

For every candidate action, five fixed obligations receive independent
`Yes`-versus-`No` log odds from the same frozen model:

1. action mode;
2. tool choice and availability;
3. argument contract;
4. evidence/value grounding;
5. prerequisite, order and progress.

Each obligation sees a deterministic projection of the same frozen
history/schema/action bytes. Per-obligation scales are converted to empirical
percentiles using only the other two Development sources and no labels. The
Candidate action score is the minimum percentile: one unsupported mandatory
obligation cannot be averaged away.

This is not a generated rubric, trained PRM, executable verifier or formal
contract proof. Its only potentially supportable contribution is a
training-free fixed composition that must beat holistic, single-obligation,
soft aggregation, voting and supervised linear controls under source holdout.

# Selection Context v029

v028 is frozen as a mechanically valid negative result. Its field factorization improved over a monolithic cross-encoder, but MFCR, pointwise field learning and equal field aggregation had identical per-row reciprocal rank on all 200 exposed Development queries. MFCR serializers, aggregation, pointwise/pairwise learner, folds, regularization, gates and Claim may not be retuned.

v029 preserves the exposed P084/BFCL v3 set only as Development and keeps the pinned BFCL v4 live-multiple files unacquired and unread. The new computation is not learned field weighting. It asks a counterfactual necessity question at inference: how much does the frozen query/tool score fall when the operation description is deleted, and how much does it fall when the argument contract is deleted?

The Candidate adds only the smaller of those two deletion drops to the full-schema score. This fixed lower-support rule rewards a tool only when both operation semantics and argument contract are necessary to its relevance. It has no training, fold fitting, TPPA spans, parameter assignment, generated documentation, task decomposition, hard-negative mining or adaptive threshold.

The design is informed by exposed wrong-function examples and therefore cannot establish a result without untouched Confirmation.

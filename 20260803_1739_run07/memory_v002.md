# v002 运行内研究记忆

## 必须继承的失败

1. v001 同实体未声明字段污染：已转为 v002 的帧污染和字段删除正式回归；候选错误接受为 0。
2. v001 实体集合无法表达同实体重复写：已改为事件序列/多重性；同实体重放正式回归错误接受为 0。
3. v001 强人工基线缺失：v002 完整人工后置条件与候选均为零错误，主张已收缩。
4. 伪造读取和未记录旁路：继续作为外部信任边界，各 1,200 次 100% 绕过。
5. 延迟变化：新增 1,200 次边界反例，明确只对观察修订作出判断。

## 试运行中新失败

第一次小规模试运行中，删除操作的抽象“复活”同时改变了版本，编译器只选版本数值便通过审计，却漏掉同版本错误存活实体；4 个已部署配置在具体值漂移下不安全。修复方式是：

- 用事件—当前修订一致关系代替固定版本数值；
- 让复活反例在同修订上强制依赖当前存在性；
- 单独增加修订不一致变异。

第二次试运行与正式尝试中，该类危险部署均为 0。此失败必须在未来版本保留为回归。

## 当前负面结论

- 没有证据表明候选比人工完整后置条件更准确；两者应持平。
- 没有证据表明 SQLite 日志写入开销为负或可忽略；观测到的普通写更慢是单进程时序噪声，不能作性能结论。
- 没有证据证明真实 API 能强制完整谱系或提供闭世界效果规格。
- 没有证据证明变异库覆盖现实故障分布。

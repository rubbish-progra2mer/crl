# 候选方法：变异充分的因果绑定效应见证

英文工作名：Mutation-Sufficient Causally Bound Effect Witnesses（MS-CBEW）。

## 改变的计算

普通运行时执行：

`写调用 → 检查返回结构/成功字段 → 把结果写入智能体可信状态`

本方法执行：

`具体写调用 → 注入调用唯一标识 ν → 执行写 → 通过独立读取面按 ν 取回当前受影响实体 → 运行经缺陷变异覆盖检验的见证合取式 → 条件提交可信状态`

失败时，运行时向智能体返回 `EFFECT_UNVERIFIED`，而不是把工具自述的成功结果注入可信状态。

## 见证编译

每个写工具提供效果模板：目标实体、必须成为的字段值、允许受影响实体数和调用唯一标识的持久化位置。对一次具体调用实例化候选谓词：

- 恰好一个与 `ν` 关联的效果实体；
- 该实体标识等于调用目标；
- 每个任务关键字段等于调用要求值。

编译器在抽象影子状态上构造与真实评测代码分离的缺陷变异：空效果、错目标、重复效果、额外效果、单字段错误。候选谓词只有同时接受正确关系、并能覆盖全部抽象缺陷时才可形成见证；使用确定性贪心集合覆盖选择最小谓词子集。未覆盖的工具标为“不可见证”，不得降级为默认通过。

## 与近邻的组件差异

- 相对 ToolGate：从“返回值相对于响应模式”改为“真实当前效果相对于具体调用意图”，并加入调用唯一标识与缺陷区分充分性。
- 相对普通读后写：不只读取目标终值；见证必须绑定本次调用，并检查效果基数、目标身份和关键字段。
- 相对签名收据：收据证明某次工具执行记录存在；效应见证证明与该调用绑定的当前外部状态满足意图。
- 相对 Cordon：不提供事务暂存或回滚；处理提交到智能体可信状态之前的持久化效果确认，可作为事务释放后的确认层。
- 相对 ReLoop/规格变异测试：迁移的是“用反例检验验证器是否有区分力”；被验证对象从生成程序/规格变为工具调用产生的外部状态转移。

## 最危险替代解释

1. 收益完全来自增加了按调用标识的读取工具，而非见证充分性。
   - 对照：给“弱正见证”同一份按标识读取结果，只把任一正确实体视为通过；候选必须在相同读取信息上继续降低重复/旁路错误提交。
2. 评测故障与编译器变异同源，结果只是构造闭环。
   - 对照：运行时故障注入器、终态标签器与方法编译器分文件实现；评价故障在真实状态上执行，并包含确认后回滚等编译器未直接实现的过程故障。
3. 方法只是全状态检查的包装。
   - 对照：报告读取调用数与返回标量数；全状态快照作为上界，候选必须以更小证据载荷接近其检测能力。
4. 独立读取面被伪造，或旁路副作用不带调用唯一标识时仍能通过。
   - 负对照一：让读取面伪造与调用意图一致的记录，预期候选失效。
   - 负对照二：正确更新目标并制造一个不带 `ν` 的额外实体污染，预期候选漏检。
   - 两项反例都必须进入外部信任前提：读取面可信且读到已提交当前状态；效果执行层对本次调用的所有持久副作用完整传播 `ν`。

# CRL 收敛性优化与真实验收计划

制定日期：2026-08-18  
依据：CRL 机器与 Run13 资源包审计、CRL 大前提评估、当前机器源码复核，以及自动科研、进化式程序搜索和科研智能体评测的原始论文与官方材料。  
当前动作边界：只制定计划；不修改 `crl_agent_v3`，不恢复 Run13，不启动新 Run，不写共享论文知识库。

## 一、决策摘要

CRL 值得继续做，但必须更改优化对象。

当前隐含优化对象近似是“在长时间运行中不断生成新版本并排除不够新颖的候选”。Run13 证明，这会产生一个稳定但错误的吸引子：**版本越来越多、否定越来越快、候选越来越容易与既有工作碰撞，但最值得投入的实现并没有得到保留、追加证据和资源倾斜。**

新的唯一优化对象应当是：

> 在用户可承担的扩大实验条件下，提高最终 Top-1 候选确实值得投入的概率，并尽快形成一个有真实实现、局部实验证据、最近先行边界、扩大路线与明确失败条件的“投资就绪实现核心”。

这里的“投资就绪”不等于本机已经做完论文，也不等于模型给出高分。它至少要求：

1. 有可运行的实现核心和可复现命令；
2. 有一个非同义反复、非人为植入答案的本地高信息量实验；
3. 最近先行审计能够说明哪些部分已有、哪些贡献形态仍存；
4. 强基线或最危险替代解释没有在本地筛选中直接吸收结果；
5. 给出扩大实验需要的数据、算力、指标、风险和停止条件；
6. 用户能够据此做出“是否投入显卡时间与论文精力”的决定。

优化的核心不是再加一层复杂科研流程，而是在现有 Contract v3 内补上四个缺失闭环：

| 闭环 | 当前 Run13 表现 | 优化后必须做到 |
|---|---|---|
| 候选保留 | 候选被快速关闭，最佳候选不持续存在 | 保存当前聚焦候选、比较候选与正交踏脚石的证据视图，任何转向都解释其去向 |
| 外部适应度 | 文本判断和先行碰撞主导 | 可执行实验、结构化先行审计和独立评审共同产生证据 |
| 资源分配 | 大量候选在实验前死亡，实验资源没有流向优胜者 | 先廉价筛选，再向存活者逐级投入，同时保留探索配额 |
| 策略更新 | Diagnosis 反复报告事实，但下一步仍重复旧行为 | 失控信号必须对应一个可检查的策略变化和后续结果 |

在完成真实对照验收前，不应恢复 Run13，也不应原样启动 Run14。Run13 应冻结为只读取证样本；它的任何候选、失败或记忆都不得注入新的正式 Run。

## 二、为什么这一改法有外部依据

成功的长周期大语言模型搜索系统并不依赖“模型自己多想就会变好”，而是依赖候选档案、可执行评价和优胜候选回灌。

| 来源 | 已验证机制 | 对 CRL 的直接启示 | 不能照搬之处 |
|---|---|---|---|
| [FunSearch](https://www.nature.com/articles/s41586-023-06924-6) | 保存多样程序群体；偏向高分程序回灌；用可执行评价器评分；用多个“岛”避免局部最优 | CRL 需要候选档案、最佳候选回灌和贡献形态多样性，而不是单链条全灭 | 科研课题没有一个像组合优化那样完美的单一分数 |
| [AlphaEvolve](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/) | 模型生成程序，评价器运行和评分，程序数据库决定后续提示样本 | “实现—运行—保存—再变异”应成为主循环；大量文本版本不是进化 | 只适用于能被客观评价的部分，不能把论文潜力压成自动总分 |
| [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) | 保存生成智能体档案；从档案采样变体；在真实编码基准上经验验证；开放探索优于无开放探索基线 | CRL 必须保存高质量踏脚石，并用真实任务验证机器改动是否有效 | 它优化的是编码能力，科研价值的反馈更稀疏、更滞后 |
| [MAP-Elites](https://arxiv.org/abs/1504.04909) | 在预先选择的行为维度中保存各区域精英，兼顾质量与多样性 | 按方法、现象、评价/基准、系统、分析五类贡献形态保存精英，避免只剩“新计算原语”一条路 | 贡献形态不是固定自然坐标，只能作为搜索多样性工具 |
| [Hyperband](https://www.jmlr.org/beta/papers/v18/16-558.html) | 先给许多配置少量资源，逐步淘汰后向少数配置增加资源 | 候选应经过廉价先行审计、最小现象探针、Recorded、Representative/Formal 的渐进投入 | 科研早期信号可能与大规模结果不一致，不能机械早停所有弱信号候选 |
| [AI co-scientist](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist/) | 生成、反思、排序、演化和元评审协作；以锦标赛比较候选；部分假设得到实验验证 | 候选之间应进行成对比较和演化，不应逐个孤立地“想完即杀” | 官方材料也明确其 Elo 是自动自评且非独立真值，专家样本较小，不能把自评分当真值 |
| [大规模人类研究](https://arxiv.org/abs/2409.04109) | 100 多名自然语言处理研究者参与；大语言模型想法被评为更有新颖性但可行性略弱；发现模型自评失败和生成缺乏多样性 | CRL 大前提有局部支持，但必须外接可行性实验、独立评价和多样性控制 | 只评价构思仍不能证明执行后值得投入 |
| [PaperBench](https://proceedings.mlr.press/v267/starace25a.html) 与 [ReplicationBench](https://arxiv.org/abs/2510.24591) | 将整篇复现拆成专家制定的可评分任务；当前最佳智能体仍只有约两成或低于两成 | CRL 的验收必须检查真实实现与研究执行，不能只评想法文本 | 复现能力不是新课题发现能力，但它是后者的必要底座 |

外部研究给出的结论不是“只要套进化算法就能自动发论文”，而是：**当前模型可以提供有竞争力的候选生成能力，但长周期改善必须依赖可验证反馈；模型自评、文献相似性和运行时长都不足以单独提供这种反馈。**

## 三、Run13 对优化目标的约束

Run13 的主要数字决定了优化不能继续围绕“提高调用稳定性”展开：

- 25.10 小时内推进 172 次，中位推进间隔 3.92 分钟；
- 40 个结构化假设全部关闭，其中 25 个为先行碰撞；v115 后没有结构化假设；
- 22 次 Recorded 中 21 次成功，3 次 Formal 全部成功，说明持续无响应不是主要失败；
- 正式知识库检索只集中在 v001—v016，后续大量裁决没有结构化搜索快照；
- 29 份 Diagnosis 没有改变后续行为；v165 已识别连续实验前关闭，v166—v172 仍然重复；
- 当前状态停在 `ACTIVE / v173`，而 v173 没有当前研究材料；
- 当前检查器花约 136.71 秒报告 485 个第三方换行错误，却没有把空的 ACTIVE 当前版本突出为核心错误。

因此，优化后的 CRL 至少要让下面三件事可观察：

1. **最佳候选证据上包络**：当前最值得投入的候选是谁，它相较上一次增加了什么外部证据；
2. **搜索策略变化**：当候选连续在实验前关闭时，下一步是否真的换成了现象优先、贡献形态切换、实现变异或正交扩展；
3. **真实效用变化**：同一组隐藏研究任务上，优化版是否比当前版更常产出可运行且通过强基线的候选。

科研进展本身不保证单调，最佳候选也可能因新证据被推翻；但这种回退必须表现为“新证据使旧上包络失效”，而不能表现为最佳候选无声消失、版本编号继续上升。

## 四、目标控制回路

优化后的主循环应是：

`发现问题/现象 → 形成少量候选 → 绑定可运行核心 → 廉价区分实验 → 先行与强基线攻击 → 更新候选档案 → 选择变异、加注、转向或诚实终局`

### 4.1 Run 内候选档案与精英视图

每个正式 Run 继续使用已有 Hypothesis portfolio、selection context、实现、实验与负面记忆作为候选档案，不跨 Run 共享；在它们之上增加一个很薄的“当前精英视图”。视图可以包含：

- 一个 `focus_candidate`：当前确有存活候选时，主研究者认为最值得下一单位资源的候选；
- 若干 `comparison_candidates`：有现实机会替换聚焦候选或提供反例的候选；
- 若干 `orthogonal_frontier`：位于正交贡献形态、可能成为后续踏脚石的问题或候选；
- 关闭候选及其精确死亡范围，进入既有负面记忆，但不占活跃资源。

frontier discovery 期间允许没有 `focus_candidate`，但应说明为何当前没有聚焦候选和下一项正交探索是什么。不设置固定候选配额，也不因为比较候选数量少就自动停止。

精英视图不是“再造一个科学状态机”。它只保存主研究者已经做出的科研判断、证据引用和当前聚焦关系，不能自动改变 Hypothesis 状态、宣布候选死亡、Delivery 或 No-Delivery。

每个候选必须有稳定 `candidate_id`，跨版本沿用，不因文字重写重新计数。实现、实验、搜索、Prior Audit 和 Review 材料都通过相对路径与 SHA-256 绑定到该候选。

### 4.2 投资就绪向量，不设黑箱总分

不得用一个由同一模型生成的“潜力总分”作为选择真值。每个候选保存以下向量，每一维都包含结论、证据引用、证据保真度、不确定性和最近变化：

| 维度 | 必须回答的问题 |
|---|---|
| 问题价值 | 失败是否真实、频繁或阻碍现有系统，解决后谁会受益？ |
| 先行差分 | 最近工作覆盖了哪些组件，候选剩余贡献具体是什么？ |
| 经验信号 | 现象是否在自然数据/真实任务上出现，强基线后是否仍存在？ |
| 实现现实性 | 是否有可运行核心、测试、依赖与复现命令？ |
| 本地保真度 | 当前小实验能杀死哪些主张，不能外推哪些规模结论？ |
| 扩大路径 | 用户增加算力后要跑什么，成本与最危险失败是什么？ |
| 贡献形态 | 方法、稳定经验现象、评价/基准、系统、理论/分析中哪些仍存？ |

证据强度使用离散事实标签，例如 `UNASSESSED`、`CLAIM_ONLY`、`SCREENING_SUPPORT`、`REPRESENTATIVE_SUPPORT`、`INDEPENDENT_SUPPORT`、`REFUTED`。这些标签不求和。候选晋升主要依据：

1. 是否在一个关键不确定性上获得更高保真证据；
2. 是否在不牺牲其余关键维度的情况下支配当前聚焦候选；
3. 是否打开了当前档案没有覆盖的正交贡献形态；
4. 独立评审的成对比较是否更愿意把下一单位实验资源投给它。

如果一个候选语言描述很漂亮，但没有可执行 artifact 或自然数据证据，它不能凭自评分成为当前聚焦候选。

### 4.3 候选变异，而不是只生成全新候选

主研究者每次选择一种显式操作：

- `REFINE_FOCUS`：改进当前聚焦候选的实现或实验；
- `ATTACK_FOCUS`：对当前聚焦候选运行最危险反证或强基线；
- `MUTATE_MECHANISM`：保留问题与评价，改变实际计算；
- `MUTATE_CONTRIBUTION_SHAPE`：方法贡献碰撞后，检查现象、评价、系统或分析贡献是否仍存；
- `ORTHOGONAL_EXPANSION`：在不同问题/计算阶段/信息源上建立挑战者；
- `BACKTRACK`：回到有证据的祖先候选，而不是继续修补已死分支；
- `CLOSE_WITH_SCOPE`：只关闭证据实际杀死的实现、局部经验主张、方法核心或整条论文方向。

资源策略不做自动预算器。主研究者在每个执行 episode 中显式说明本轮主要用于聚焦候选深挖、比较候选攻击还是正交探索，并避免因长期聚焦而永久饿死探索；具体比例由当前证据和信息增益决定。

### 4.4 渐进式实验资源分配

建议保留现有实验层级，但赋予清晰作用：

1. `Scratch`：检查代码可运行、数据可取得、现象能否初步诱发；不能支持论文级晋升；
2. `Recorded Screening`：固定输入、命令、输出和指标，用来淘汰明显错误并比较候选；
3. `Representative Recorded/Formal`：覆盖代表性模型、任务、数据或种子，才能提高经验信号与本地保真度；
4. `Fixed Review`：只对已绑定实现、证据包和测量进行外部攻击，不能把审稿语言质量当实验结果。

除 `DIRECT_EXACT` 最近先行明确覆盖同一计算、同一信息条件、同一评价主张外，若候选满足以下条件，主研究者原则上应优先完成一个区分实验，而不是仅凭“机制名字已存在”关闭整个论文方向：

- 目标失败有真实载体；
- 本地有可取得的数据或公开任务；
- 存在一个能区分候选与最近先行/强基线的小实验；
- 该实验失败会显著降低用户继续投入价值。

如果主研究者仍决定不做实验，必须说明该实验为何不可执行、信息增益为何低，或为何其结果已不再改变投资价值；脚本不自动判定这一解释是否充分。人为植入差异、把标签直接泄漏给方法、只证明脚本能运行、或评价指标与候选定义同构的实验，不计为高信息量实验。

## 五、修复“先行碰撞等于全杀”

当前机器已经有 Prior Audit 能力，但 Run13 的结构化 Prior Audit 为 0。优化后，任何实际关闭候选或方法谱系的先行碰撞都必须绑定结构化审计。

直接复用当前 CRL 已有分类，不再创建第二套碰撞术语：

- `DIRECT_EXACT`：问题、信息、时机、计算、输出与评价路径基本直接占据；可关闭对应精确主张或方法核心；
- `EMPIRICAL_ABSORPTION`：公平、同信息/工具/预算的强基线追平或超过候选；按实验实际测量范围杀伤；
- `CONSTRUCTIVE_COMPOSITE`：多个已知组件可以具体组合；只表示高风险，不能自动关闭组合产生的新现象、评价或系统贡献；
- `ANALOGICAL_REDUCTION`：与经典或跨领域计算范式类比；需要证明结构映射成立，不能凭名称相似全杀；
- `PROBLEM_OCCUPIED_METHOD_OPEN`：问题已提出，但方法或实现路径仍开放；
- `METHOD_KILLED_PHENOMENON_SURVIVES`：方法死亡而现象、评价机会或分析问题仍存。

当碰撞实际参与候选关闭、方法核心/论文方向杀伤或重大升级时，审计应列出组件级映射，并填写现有 `KILLED`、`SURVIVES`、`WHY`；仍存贡献形态和下一项区分动作写入 researcher assessment 或精英视图。普通检索不强制填写，脚本不按字段内容自动判断碰撞对错。

这项改动直接针对 Run13 的核心偏差：已有机制应当压缩夸大的新颖性主张，但不应让评价型、现象型和系统型课题在没有自然数据实验的情况下全部消失。

## 六、版本语义与持续性修复

### 6.1 同一科研坐标内不推进版本

候选措辞修改、同一实现的调试、增加一个种子、补一篇同类论文、重复一次相同探针，都应作为候选 revision、实验 attempt 或搜索快照记录，不应推进 `vNNN`。

`advance-version` 只用于问题族、计算阶段、干预族、信息源、贡献形态或主要评价路径发生实质改变。为避免建立新的版本 Gate，保留当前 `CHANGED_COORDINATE`、`SURVIVING_FRONTIER`、`NEXT_HIGH_INFORMATION_ACTION` 三段自由文本；可以增加两个可选、只做身份绑定的字段：

- `FOCUS_DISPOSITION`：当前聚焦候选保留、关闭、被替换或当前无聚焦候选的研究者说明；
- `EVIDENCE_DELTA_REFS`：促成转向的实验、搜索、Prior Audit 或 Review 路径与哈希。

机械层只检查可选引用存在且身份正确；是否真的改变科研坐标继续由主研究者负责。Diagnosis 可以把连续高度相似的 `CHANGED_COORDINATE` 原样呈现为预警事实，但脚本不得因语义相似自动拒绝科研转向。

### 6.2 原子续接，禁止空 ACTIVE 当前版本

版本推进应成为一个原子事务：

1. 验证旧版本关键材料和 transition；
2. 预创建新版本的 continuation 与最小研究进展快照；
3. 快照绑定当前聚焦关系、存活 frontier、证据增量和下一行动；
4. 最后原子更新 `RUN_STATUS.md` 与 Ledger；
5. 任一步失败都回滚，不得让 Status 指向空版本。

一次 Codex 执行 episode 结束时，不需要新增生命周期状态，但必须在当前版本保存：当前聚焦候选（若有）、比较候选或正交 frontier、已完成证据、下一行动和真实外部边界。若没有外部边界且仍有可执行高信息量实验，则不能把“任务消息结束”伪装成科学终局。

### 6.3 失控预警必须有响应

Diagnosis 继续保持 facts-only 和非权威，但增加以下机械事实：

- 聚焦候选是否存在、最近一次证据增量；不存在时的研究者说明；
- 活跃候选各自绑定的实现、实验、Prior Audit 数；
- 连续实验前关闭数；
- 连续先行碰撞数及碰撞种类；
- 最近若干行动的贡献形态与描述符重复度；
- Diagnosis 后是否记录了 `RESEARCHER_RESPONSE`，以及后续行动是否符合所声明的策略变化；
- 当前聚焦实现 artifact 是否仍可运行、哈希是否仍有效。

初始预警阈值可设为“连续 5 个候选在实验前关闭”“连续 5 个关闭均由先行碰撞触发”“连续 3 次 Diagnosis 没有新的策略响应”。这些是需要在真实评测中调优的报警参数，不是自动 Gate；触发后主研究者必须解释并选择现象优先、贡献形态切换、正交扩展、回溯或终局论证中的一种，不能只再读一篇同类论文。

## 七、机器级具体改动清单

### P0-A：可复现身份与基线冻结

目标：以后能够准确回答“这个 Run 使用的是哪一版机器”。

1. 将 `D:\Desktop\crl` 或至少 `crl_agent_v3` 纳入 Git；首次提交前明确排除 Run、知识库大文件、压缩包、虚拟环境和派生索引；
2. 新 Run 创建时写入机器提交号、脏工作区状态、`AGENTS.md`/`CRL.md`/环境协议哈希、核心工具清单哈希和主研究者指令标识；
3. Formal 继续绑定具体运行器，并额外绑定整机身份；
4. 将当前实现标记为 `pre-convergence-control` 基线，用于后续 A/B 回放。

拟修改：`tools/manage_run.py`、`crl_v3/workspace.py`、Run Charter/Status 模板、相应测试。  
验收：从任何新 Run 单独取出控制文件，都能定位机器版本和权威协议；脏状态必须显式记录，不能伪装为可复现提交。

### P0-B：最薄研究进展快照

目标：让“最佳候选是否变好”成为可检查事实。

不增加新的 Hypothesis 状态，不立即升级 schema 2，也不新建复杂候选状态机。新增一个 research-owned、非权威的 `progress_snapshot_vNNN.json`，并让 `selection_context_vNNN.md` 继续承载自由科研解释。快照只保存：

- `focus_candidate_id`，允许为空并附原因；
- `comparison_candidate_ids` 与 `orthogonal_frontier`，不设数量 Gate；
- 非评分 `contribution_vector` 与第 4.2 节的证据标签；
- `artifact_refs`、`evidence_refs` 及 SHA-256；
- `fatal_uncertainty`、`next_discriminating_action`、`scale_up_path`；
- `strategy_response`：最近 Diagnosis 后主研究者选择了什么策略及为什么。

快照可以由一个薄校验/写入器原子保存，也可以先由现有文档工具生成；它不能调用 `transition_hypothesis`，不能改变候选状态，只为 Diagnosis、恢复和对照评测提供事实。已有 schema 2 decision event 继续保存候选关闭的精确范围，Prior Audit 继续使用现有设施。

验收：旧 schema 1/2 可读且不被改写；快照完整往返；所有路径/哈希均为 Run-local；聚焦候选变化能追溯到成对比较、证据增加或证据失效；即使没有聚焦候选也保留正交 frontier 与下一行动；候选关闭后仍可追溯其最后可运行 artifact。

### P0-C：版本原子性与防空转

目标：消除 Run13 式 v173 断尾和版本计数器化。

拟修改 `tools/manage_run.py`：允许上述可选 transition 引用；先落地新版本最小快照再改 Status；为失败注入测试覆盖每个写入步骤。对于疑似同一坐标连续推进，只由 Diagnosis 报告事实，不由脚本做科研语义拒绝。

验收：任意故障点都不会产生 `ACTIVE` 指向空版本；聚焦候选去向、证据增量和下一行动在新版本可读；脚本没有新增自动科研裁决。

### P0-D：先行裁决与正向实验义务

目标：纠正只淘汰、不晋升。

拟修改 `CRL.md`、`AGENTS.md` 的行动提示与现有 Prior Audit/候选决策使用指南，优先复用当前已经写明但 Run13 未落实的规则：

- 明确五种贡献形态均合法；
- `DIRECT_EXACT` 之外，若存在可行、高信息量且会改变投资价值的区分实验，主研究者应先运行或解释为何不运行；
- 先行实际参与重大关闭时，优先绑定现有结构化 Prior Audit；
- 候选晋升必须绑定 artifact 或更高保真证据；
- Diagnosis 预警后保存非权威但可审计的策略响应。

验收：构造“组件已有但评价缺口真实”的轨迹时，主研究者策略应缩窄方法新颖性并检查评价贡献，脚本本身不自动杀死或保活；构造真正 `DIRECT_EXACT` 时，主研究者可以选择不浪费实验资源并留下可审计解释。

### P1-A：Diagnosis 与 inspect 修复

目标：让检查器突出真实科学执行风险，而不是第三方噪声。

1. `tools/inspect_run.py` 的 Markdown 完整性只检查 CRL 所有的正文和控制材料，排除嵌套仓库、`external`、虚拟环境、vendor、构建缓存；
2. 对 `ACTIVE_CURRENT_VERSION_EMPTY`、快照声明的聚焦候选无法解析、Status/Ledger/continuation 不一致给出高优先级错误；没有聚焦候选但已写明 frontier discovery 原因不算错误；
3. `_directory_fact` 不递归统计可重新获取的第三方树，或只返回分组体积；
4. `crl_v3/diagnosis.py` 增加第六节所列进展事实，但继续声明“非质量分数、不自动裁决”。

Run13 回归验收目标：不再报告 485 个第三方 CRLF 错误；明确报告一个空 ACTIVE 当前版本核心错误；检查耗时从约 136.71 秒降到 30 秒以内。30 秒是当前机器上的工程目标，不是科研指标。

### P1-B：Recall 与资源卫生

目标：长期记忆研究决策，而不是复制外部工程树。

1. Recall 只索引 CRL 所有的正文、候选摘要、实验摘要、Prior Audit、Decision 和压缩过的证据；
2. 规则、代码或源文件身份改变时将索引标为 stale，不静默继续使用；
3. Run 内不建大型虚拟环境，不保存可重新克隆的完整仓库；保存仓库地址、提交号、补丁和必要输出；
4. 大数据只保存清单、哈希、获取脚本和最小样本，除非它本身是不可替代实验输入；
5. `inspect`、打包和 Recall 对同一排除规则使用单一权威实现。

验收：用当前规则回放 Run13，Recall 候选源规模应接近只读模拟的约 11.06 MiB，而不是 196.68 MB；研究正文、候选证据和实验摘要召回不下降。

## 八、真实研究发现评测：优化能否被证伪

这是整个计划最重要的部分。没有它，CRL 仍可能只是生成了更整齐的档案。

### 8.1 对照条件

在同一模型、知识库快照、工具权限和总调用成本下比较：

- A：单次强提示的大语言模型；
- B：大语言模型 + 同一知识库检索 + 工具，但没有 CRL 长周期控制；
- C：当前 Contract v3 基线；
- D：加入候选档案、外部适应度和资源分配后的优化版 CRL；
- 可选 E：多次独立短运行后由盲评选择，用来检验“一个长轨迹”是否真的优于“多次正交重启”。

正式比较必须匹配模型版本、温度/随机性、可见文献、实验预算和总调用成本；不能让优化版仅靠多花数量级成本获胜。

### 8.2 任务构成

先建立 12 个配对任务的工程试验集：

- 6 个隐藏正例：从真实论文或作者确认的机制构造“只给截止日前文献、数据与问题，不给后来机制”的再发现任务；
- 3 个负例：表面有缺口但强基线或最近先行已经完全吸收，检查系统会不会制造伪新颖性；
- 3 个贡献形态陷阱：关键计算组件已有，但现象、评价或系统差分仍可能成立，检查是否发生 Run13 式误杀。

公开时间截断任务存在模型训练污染风险。每个任务都要做题名补全、关键短语识别和直接机制复述测试；疑似污染的任务剔除或单独报告，不能把“模型记得论文”当再发现。更强的后续版本应使用研究者私有的未公开机制、同期但未公开材料，或新采集数据上的前瞻任务。

Run13 的 v172 只可作为维护评测中的“贡献形态误杀”取证夹具，不能复制到新正式 Run，也不能把它算作新 Run 自主发现。

### 8.3 主要终点

不以版本数、想法数、文档长度或模型自评分为主要结果。预先登记：

1. **Top-1 投资偏好**：盲化评审在“愿意投入下一单位显卡/研究时间”上的成对选择；
2. **可运行存活率**：候选形成可运行核心，并在强基线与最近先行审计后仍有明确贡献差分的比例；
3. **隐藏正例误杀率**：真实可发现机制在任何区分实验前被错误关闭的比例；
4. **伪新颖性率**：负例被错误晋升为投资就绪的比例；
5. **首次可运行存活者成本**：调用成本、墙钟时间和实验资源；
6. **贡献形态多样性**：不是候选措辞数量，而是方法、现象、评价、系统、分析中有证据的覆盖；
7. **审计完整性**：候选、实现、证据、先行裁决和版本转向是否可追溯。

定性科学评审至少采用盲化成对比较。大语言模型评审可用于预筛和一致性检查，但不能冒充人类领域专家；最终“是否值得我投入”的主评审应由用户完成，必要时再请真实领域同行。评审看到的候选格式、篇幅、模型身份和运行条件必须尽量一致。

### 8.4 工程放行条件

12 任务试验集只能作为产品放行，不足以发表“CRL 有效”的普遍结论。建议放行条件为：

- 结构完整性：D 条件 100% 无空 ACTIVE 版本、无机器身份缺失、无未绑定的关键实验结果；
- 行为改变：评测轨迹中，所有实际用于关闭整条方向的先行碰撞都有结构化审计；符合区分实验条件的非 `DIRECT_EXACT` 候选不再无解释地在实验前全灭；这些是轨迹结果指标，不是脚本 Gate；
- 配对结果：D 相对 C 至少在 9/12 个任务上得到更高 Top-1 投资偏好，且隐藏正例误杀和负例误晋升均不恶化；
- 资源约束：若 D 的总成本超过 C 两倍，必须报告每单位成本效用，不能只宣称绝对结果更好；
- Run13 回归：检查器正确突出空 v173，不再被第三方换行噪声淹没。

“9/12”和“两倍”是首轮工程决策阈值，不是统计学真理。若结果接近阈值，应扩展到至少 30 个配对任务并报告置信区间，而不是修改阈值来宣布成功。

## 九、测试与同行评审安排

### 单元测试

- progress snapshot 创建、更新、证据绑定与旧 Run 缺失快照兼容；
- 聚焦候选替换、空聚焦原因和正交 frontier；
- Prior Audit 碰撞种类与死亡范围；
- transition 可选引用和新版本最小快照；
- 机器身份哈希、脏状态和协议哈希；
- Recall/inspect 排除规则共用；
- Diagnosis 新事实不含自动科研裁决。

### 集成与故障注入

- 在版本推进的每个文件写入点注入失败，确认 Status 不会指向空版本；
- 候选从 draft 到聚焦候选、实验反证、回退到祖先候选的完整轨迹；
- “已有组件 + 新评价缺口”和 `DIRECT_EXACT` 两类相反夹具；
- Recall 规则更新后的 stale 检测与重建；
- Run13 只读检查与性能回归。

### 评审顺序

1. 先运行当前完整测试和新增测试；
2. 由其他编码智能体分别做安全、数据一致性、科研语义和 Windows 编码审查；
3. 对评审意见逐条验证，不把角色模拟当成真实独立同行；
4. 通过后才执行 12 任务对照；
5. 对照通过后才允许正式新 Run。

## 十、实施顺序与回滚点

### 阶段 0：冻结基线

产物：机器 Git 身份、当前测试基线、Run13 只读取证清单、12 任务评测草案。  
回滚点：任何 Git 初始化都不得纳入用户 Run、知识库论文、压缩包或大文件；提交清单先人工检查。

### 阶段 1：最小 P0 控制闭环

实施 P0-A、P0-B、P0-C；不先改科学提示，不引入新候选状态。  
目的：先确保候选能被保留、版本不会断尾、机器身份可复现。  
回滚点：旧 Run 必须保持只读可审计；不迁移旧 Hypothesis schema，也不为历史 Run 回填进展快照。

### 阶段 2：科研行动策略

实施 P0-D 与 Diagnosis 策略响应；加入贡献形态、先行碰撞范围和正向实验义务。  
目的：让机器从“只会杀”变成“保存—比较—加注—反证”。  
回滚点：脚本不得替主研究者自动 Delivery、No-Delivery 或科研裁决。

### 阶段 3：检查、Recall 与资源卫生

实施 P1-A/P1-B，修复 Run13 取证回归并降低打包/检查成本。  
回滚点：任何排除规则都要证明没有漏掉 CRL 所有的正式研究材料。

### 阶段 4：真实对照验收

先跑 4 个任务的冒烟对照，再跑完整 12 个配对任务；盲化整理结果。  
如果优化版没有改善 Top-1 投资偏好或只是用更多成本换取结果，不进入正式 Run，回到控制回路设计。

### 阶段 5：新的正式 Run

只有阶段 4 放行后才创建全新 Contract v3 Run。新 Run 不读取 Run13 候选、实验、Decision、Memory 或失败记录，只共享正式论文知识库。其目标仍是产生一个 Top-1 投资就绪实现核心，不以运行时长或版本数作为成功证明。

## 十一、哪些事情暂时不要做

1. 不要通过增加更多 Reviewer 角色来替代真实实验；同源模型多数投票仍可能共同偏误；
2. 不要把所有维度压成一个 0—100 潜力分；这会重新制造内生评价闭环；
3. 不要设置固定候选配额、自动资源比例或复杂科研状态机；聚焦关系只帮助保存和比较，不替代主研究者判断；
4. 不要为了“收敛”硬设版本数、Token 或时长终止科研；这些只能用于公平基准预算，不能自动支持科学终局；
5. 不要把跨 Run 失败记忆、候选档案和实验结果引入新 Run；应遵守当前隔离契约；
6. 不要先扩充知识库再期待策略自动修复；Run13 后期的核心失败是行动策略，不是单纯论文数量不足；
7. 不要直接恢复 Run13；其旧机器身份不可精确复原，且轨迹已经形成强烈的先行碰撞吸引子；
8. 不要在没有真实对照的情况下声称“优化后会收敛”。正确说法只能是：优化版建立了可保留、可比较、可证伪的进展信号，是否有效由对照结果决定。

## 十二、预期结果与失败判据

完成本计划后，CRL 不会获得“保证找到论文课题”的能力。合理预期是：

- 同样的模型和本地资源下，少量最有希望的候选获得更多可执行验证；
- 先行工作更常用于缩窄主张，而不是不加区分地全杀；
- 最佳候选及其证据不会因版本推进无声消失；
- 任务停止、机器改版和资源打包后，研究状态仍可恢复与审计；
- 用户拿到的是可运行且知道哪里最可能失败的实现核心，而不是一份仅靠措辞显得新颖的想法。

以下任一情况都应视为本轮优化失败，而不是继续无限运行：

- 12 任务对照中，优化版的 Top-1 投资偏好没有稳定优于当前版；
- 可运行候选增加，但强基线后存活率没有增加；
- 研究进展快照只增加文档量，聚焦候选的外部证据没有增长；
- 隐藏正例仍大量在实验前因宽泛先行碰撞被杀；
- 优化收益完全依赖不成比例的调用成本；
- 新约束使主研究者只会填写更多字段，而行动策略仍不改变。

本计划最核心的一句话是：**CRL 的收敛不应定义为候选越来越少，而应定义为“被保存的最佳实现核心，其关键不确定性被真实证据逐步消除，并最终足以让用户决定投入或诚实放弃”。**

## 2. 方法改变的计算步骤

- [AUTHOR_FACT] 论文比较两条路径：LLM-as-Planner 由自然语言 domain description（DD）和 problem description（PD）直接生成动作序列；LLM-as-Formalizer 先由 LLM 生成完整 PDDL domain file（DF）和 problem file（PF），再交给确定性 planner 搜索计划。定位：物理页 2–3，Figure 1、Figure 2；短定位文本：“generate the entire PDDL including PF and DF”。
- [AUTHOR_FACT] 相比只预测 PF、PF goal、DF action semantics 或 DF 的先前工作，本方法明确要求同时预测 DF 与 PF。定位：物理页 3，§3；物理页 9，§6；物理页 14，Table 1。
- [READER_INTERPRETATION] 真正改变的计算不是“让同一个模型更会规划”，而是把一次端到端动作序列生成改写为“自然语言→可执行世界模型→符号搜索→计划验证”的分解；新增的 planner 是实质计算组件，因此 Formalizer 与 Planner 不是只差输出格式的同预算对照。

## 3. 输入、输出、可用信息与输入泄露边界

- [AUTHOR_FACT] 两条路径都接收 DD 与 PD；DF 和 PF 对模型 withheld。最终任务是得到相对于 ground-truth DF/PF 可执行并到达目标的计划。定位：物理页 3，§2–3；短定位文本：“DD and PD are always provided and the DF and PF are always generated by the LLM”。
- [AUTHOR_FACT] 模型并非从纯自然语言和空白 ontology 开始：作者称“minimally necessary”地提供 action space，即 DF 中动作的 identifiers 与 parameters，使模型知道允许哪些动作。定位：物理页 3，脚注 2；短定位文本：“provide the action space, the identifiers and parameters of the actions in DF”。
- [AUTHOR_FACT] DD/PD 被设定为 fully observed，并应包含完成计划所需的全部信息；自然文本可以省略人类易推断的显式谓词，例如“栈顶”隐含 clear。定位：物理页 3–5，§2、§4.1。
- [AUTHOR_FACT] Heavily Templated 描述近似逐词翻译 PDDL，显式列出谓词、前置条件和效果；Moderately Templated 仍显式谈论前置/效果；Natural 描述改写为更一般的规则，不逐项列出全部谓词。定位：物理页 4–5，§4.1；物理页 15–17，Listings 3–8。
- [AUTHOR_FACT] Natural DD 由 gpt-4o 高温生成/改写 seed annotation，再由人工核对 predicates、preconditions、effects；Natural PD 从符号初始/目标配置生成后人工与配置对照。定位：物理页 4–5，§4.1。
- [READER_INTERPRETATION] “完整 PDDL formalizer”是相对于输出端完整：模型仍拿到动作名称、参数及 fully-observed DD/PD。尤其 Heavily Templated 输入已显式暴露几乎全部动作语义；因此结果不能解释为从无结构用户请求自主发现完整 ontology。
- [OPEN_QUESTION] 正文与附录没有给出 LLM-as-Formalizer 的完整实际 prompt；Appendix B 声称 Listings 13–16 是给所有模型的 prompts，但这四个 listing 均标为 LLM-as-Planner。故 formalizer 是否还获得 JSON schema、PDDL requirements、示例或其他格式约束，无法由 PDF 独立复核。定位：物理页 13，Appendix B；物理页 18–20，Listings 13–16。

## 4. solver、VAL 与指标链条

- [AUTHOR_FACT] Formalizer 的 Solvability 是生成的 DF/PF 能否被 `dual-bfws-ffparser` 解析并返回计划；若无计划或发生错误，不计为 solvable。定位：物理页 5，§4.2；物理页 13，§C.1、§C.3。
- [AUTHOR_FACT] Correctness 对两条路径均通过 VAL、相对于 ground-truth DF/PF 验证计划：逐动作检查前置条件，并检查最终状态是否满足 ground-truth goal。定位：物理页 5，§4.2；物理页 13，§C.2–C.3。
- [AUTHOR_FACT] Formalizer 的 DF/PF 本身不与 ground truth 作等值比较，因为同一规划域可能有多种形式化；只验证最终计划。定位：物理页 5，§4.2；短定位文本：“only the eventual plan is validated”。
- [READER_INTERPRETATION] 该口径正确区分“代码可被 solver 使用”与“返回计划在真实模型中正确”，但不能证明预测 DF/PF 对未执行部分忠实；一个错误世界模型只要碰巧产生可过 VAL 的计划，也会计为正确。
- [AUTHOR_FACT] gpt-4o 在 Heavily Templated BlocksWorld 上有 64/100 solvable、60/100 correct；Planner 为 33/100 correct。定位：物理页 6，§5.2；物理页 21，Table 2。
- [AUTHOR_FACT] gpt-4o-mini 常表现为 solvability 远高于 correctness，作者据此区分语法掌握与语义理解。定位：物理页 6，§5.1；例如 Natural BlocksWorld 为 19/100 solvable、3/100 correct，Table 2（物理页 21）。

## 5. 最强基线、closest baseline 与比较结果

- [AUTHOR_FACT] 直接 LLM-as-Planner 是论文的主基线，模型、数据自然度和 100 个问题尽量对应；结果表同时列 Formalizer 的 solvability/correctness 与 Planner 的 correctness。定位：物理页 5–7，§4.2–5.3；物理页 21–22，Tables 2–5。
- [AUTHOR_FACT] 不能概括为 Formalizer 总是更好。Natural BlocksWorld 中 DeepSeek-R1 Formalizer 81/100、Planner 91/100；o3-mini 为 68/100 对 87/100。Heavily Templated BlocksWorld 中 o3-mini 为 94/100 对 96/100。定位：物理页 21，Table 2。
- [AUTHOR_FACT] Formalizer 在若干重要设置大幅领先：Heavily Templated BlocksWorld 的 gpt-4o 为 89/100 对 29/100；MysteryBlocksWorld 的 gpt-4o 为 70/100 对 0/100，o3-mini 为 95/100 对 74/100。定位：物理页 21，Tables 2–3。
- [AUTHOR_FACT] 更复杂域会改变排序：Natural Logistics 中 DeepSeek-R1 Formalizer 9/100、Planner 12/100，o3-mini 为 7/100 对 14/100；Barman 上 Formalizer 几乎为零，而 Planner 最高达到 DeepSeek-R1 22/100、o3-mini 19/100。定位：物理页 22，Tables 4–5。
- [READER_INTERPRETATION] 最接近的组合基线是“同一模型、同一 DD/PD、直接生成计划”，但 Formalizer 额外拥有通用符号搜索器；论文未纳入更强的 LLM-modulo / iterative validation planner。作者也在限制中承认，带符号验证的 Planner 会是更强基线。定位：物理页 10，§8；短定位文本：“combines LLM-as-planner with symbolic validation, will likely lead to a stronger baseline”。
- [OPEN_QUESTION] 未报告 planner 的搜索预算、超时、节点上限或 Formalizer 的端到端成本，因而无法把准确率差异换算成同等算力/延迟/费用下的优势。

## 6. naturalness 结果及其边界

- [AUTHOR_FACT] BlocksWorld 与 Logistics 各有 100 个问题。两种 templated 设置各使用一个 DD 配 100 个 PD；Natural 设置使用 100 个不同 DD/PD 对。Moderately Templated 与 Natural 只覆盖 BlocksWorld 和 Logistics，Barman 因规模未覆盖。定位：物理页 5，§4.1。
- [AUTHOR_FACT] 对能 formalize 的模型，correctness 总体随描述从 Heavily Templated 变为 Natural 而下降。例：gpt-4o BlocksWorld 为 89→67→60，o3-mini 为 94→70→68；Logistics 也呈相同方向。定位：物理页 7，Figure 4；物理页 21–22，Tables 2、4。
- [AUTHOR_FACT] 作者解释之一是自然描述省略显式 commonsense，例如不直接给出 clear 谓词，模型常漏掉该谓词。定位：物理页 7，§5.3。
- [READER_INTERPRETATION] 该“naturalness”变化同时改变了措辞自然度、domain-description 多样性、显式信息密度和需要补出的常识量；它不是只替换表面措辞的单因素干预。因此性能下降可可靠描述为“这套 Natural 数据更难”，但不能单独归因于语言自然度。
- [OPEN_QUESTION] PDF 未报告各自然度输入长度、token 分布或逐实例严格配对检验，也未报告置信区间/显著性检验。

## 7. 模型、prompt、token、tool-call 与 oracle 混杂

- [AUTHOR_FACT] 作者使用 Gemma-2、Llama-3.1、DeepSeek-R1 系列、gpt-4o-mini、gpt-4o、o3-mini 等；通过 KANI 的默认超参数查询。开放模型在 4×RTX A6000 上运行；仅报告 BlocksWorld Formalizer 平均约 1062 个输入与输出 token。定位：物理页 5，§4.3。
- [AUTHOR_FACT] 主实验为 zero-shot；附录另做少量 few-shot 与 chain-of-thought。few-shot 和 CoT 对不同模型有升有降，作者结论是未稳定改善。定位：物理页 13–14，§D.5–D.6；物理页 22–23，Tables 6–7。
- [AUTHOR_FACT] DeepSeek-R1 会输出 reasoning string；作者观察其 Planner 会逐步检查计划，并可能尝试 pattern-match prompt 中的 example output。定位：物理页 8，§5.6。
- [READER_INTERPRETATION] 模型间比较混合了模型能力、推理 token、服务端实现和响应格式；方法间比较又混合了 LLM 调用与外部 planner。论文没有给出每模型/每方法 max tokens、实际 token、延迟、费用、停止条件或 planner 搜索成本，不能据此作严格预算等价结论。
- [OPEN_QUESTION] formalizer prompt 缺失使 prompt parity 无法验证；planner prompt 明确包含示例动作序列，而 formalizer 是否有等量示例未知。

## 8. 作者明示限制、负向结果与未测试边界

- [AUTHOR_FACT] Barman 对全部模型几乎不可解；小型 open models 常出现 PDDL syntax errors，而 GPT 模型仍有 semantic errors。定位：物理页 6–8，§5.1、§5.5；物理页 22–23，Tables 5、8–9。
- [AUTHOR_FACT] error analysis 是从“未找到计划或计划错误”的样本中随机抽 20 个进行分类；Table 8/9 的比例因此是失败样本内的错误标签，不是全体 100 题的总体错误率，且错误标签可重叠。定位：物理页 7–8，§5.5；物理页 23，Tables 8–9。
- [AUTHOR_FACT] 作者明示只研究四个 toy domains、主要 zero-shot、没有 prompt tuning/self-refine/voting；任务依赖 domain，复杂/common-sense action space 可能更有利于 Planner；真实世界、部分可观察和更复杂环境未验证。定位：物理页 9–10，§7–8。
- [AUTHOR_FACT] 对 MysteryBlocksWorld 的强结果只支持 lexical perturbation 下的鲁棒性，不消除 solver、模板结构或形式语法带来的帮助。定位：物理页 7–9，§5.4、§7。

## 9. 可抽取的 Operator 与真实 Failure（仅二读建议，不生成 Card）

- [READER_INTERPRETATION] 可抽取 Operator：把端到端 plan decoding 替换为“完整 DF/PF 生成→确定性 PDDL search→ground-truth VAL 验证”的神经符号分解；适用前提是 fully observed、动作 ontology/参数已给、语言可被映射到 PDDL。
- [READER_INTERPRETATION] 可抽取 Operator：对同一规划问题系统性改变描述的显式程度，用 Heavily/Moderately/Natural 三档暴露从模板匹配到隐式常识恢复的能力差异。
- [AUTHOR_FACT] 可记录 Failure：自然描述下遗漏 predicates、错误 initial/goal facts、错误 action effects/preconditions；弱模型大量 syntax error。定位：物理页 7–8，§5.3、§5.5；物理页 23，Tables 8–9。
- [AUTHOR_FACT] 可记录 Failure：Formalizer 优势依赖模型和域；DeepSeek-R1、o3-mini 在若干设置由 Planner 更强，Barman 上 Formalizer 接近零。定位：物理页 8–10，§5.6、§7–8；物理页 21–22。
- [READER_INTERPRETATION] 不应抽取为无条件 Failure：“自然语言必然导致 formalizer 失败”或“formalizer 总是优于 planner”；原文只支持特定数据、模型和工具链下的条件性结果。

## 11. 独立结论

- [READER_INTERPRETATION] 论文有力支持一个有边界的结论：在动作 schema 已给、环境 fully observed、且域较简单时，完整 PDDL formalization 加符号搜索能显著改善若干强模型的计划正确率，并对 lexical perturbation 有时更稳健。
- [READER_INTERPRETATION] 它同样提供了清晰反例：优势不跨模型、自然度和域稳定成立；自然描述、完整 PF 初始状态、复杂 action space 与语义一致性仍是主要失败点。
- [OPEN_QUESTION] 在 formalizer prompt、预算和更强 iterative Planner baseline 未补齐前，不宜把差异解释为同等计算条件下 formalization 本身的纯因果优势。

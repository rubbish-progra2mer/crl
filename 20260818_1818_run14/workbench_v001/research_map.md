# v001 研究地图：工具模式等价性与执行鲁棒性

## 问题

工具型大语言模型智能体通常只在一份工具模式上接受评测，但工具名称、参数名称和 JSON 属性顺序等接口表征会随供应商、框架与版本变化。若两个接口经适配器映射后执行同一规范函数，任务结果原则上应保持不变；实际模型可能因预训练名称偏好或结构表征敏感性产生差异。

## 已确认最近先行边界

- P084《On the Robustness of Agentic Function Calling》已经评测自然语言查询改写和相关工具集扩张；其受控子集主要以抽象语法树匹配判断调用，不覆盖严格等价工具模式变换后的真实执行不变性。
- Lee 等人的 PA-Tool 已把工具构件重命名用于预训练对齐，并在 MetaTool 与 RoTBench 上验证。因此，“发现名称敏感后选择更熟悉的名字”不再是可主张的新方法核。
- 仍待核验的贡献差分是：把语义等价的工具模式变换定义成可执行的蜕变关系，进行同任务、同语义、配对的端到端执行评测，并区分选择、参数映射、解析和执行阶段的失效。

## 当前候选关系

- `h14-001`：预训练对齐的工具构件重命名；预计被 PA-Tool 杀死方法核，但必须保留并重审现象、评价与系统能力维度。
- `h14-002`：严格等价工具模式变换下的配对执行不变性审计；由 `h14-001` 的存活维度派生。
- `h14-003`：运行时别名恢复与一次受控重试；作为不同干预阶段的备选，先不承诺新颖性。

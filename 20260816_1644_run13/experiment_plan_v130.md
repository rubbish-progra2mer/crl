# v130 Recorded 最小实验计划

## 科研问题

[Beyond Retrieval](https://arxiv.org/html/2608.12847) 的查询条件轨迹复用（QCR）同时引入了两项变化：读取历史轨迹，以及让额外一次模型调用读取当前查询和初始观察后编写支持笔记。论文与来源-only 通用摘要、原始轨迹和无记忆比较，但没有目标-only、调用数匹配的预规划条件。

本实验只检验一个归因问题：在匹配额外推理调用后，正确历史轨迹是否仍提供可测的边际程序信息。它不复现论文三套大型交互环境，也不评价不可逆副作用或真实部署安全。

## 良性合成载体

固定 16 个本地抽象工作流任务，使用四个无副作用操作 `op_amber`、`op_blue`、`op_coral`、`op_dusk` 和一个目标记录标识符。执行器只解析模型返回的四步 JSON 计划，不真正调用工具、不修改外部状态。

- `transfer_needed`：目标观察给出工具集合与新记录标识符，但不显示四步顺序；正确历史轨迹包含一次被拒绝且状态不变的尝试，以及随后被验证成功的四步顺序。
- `target_sufficient`：目标观察额外明确给出当前四步顺序，历史轨迹不再必要，用于检验目标-only 预规划条件是否能正常工作，以及当前证据能否覆盖错误历史。

四个预定义顺序各重复两次；来源和目标标识符逐例变化。错误历史来自同一工具集合的另一顺序，不带显式“错误”标签。

## 四个条件

1. `direct`：目标查询与初始观察直接交给执行模型；一次模型调用。
2. `target_plan`：额外支持写作者只读目标查询与初始观察，生成与 QCR 同字段、同长度预算的预规划笔记；执行模型再行动。
3. `qcr_correct`：支持写作者读取正确历史轨迹、目标查询与初始观察，生成工作流不变量、待重新绑定项、适用条件和核验守卫；执行模型再行动。
4. `qcr_shuffled`：与 `qcr_correct` 相同，但历史轨迹替换为同一工具集合上的另一成功顺序。

后三个条件均为两次模型调用。所有条件共享模型、温度 0、逐任务种子、目标提示、输出模式和执行评分器。条件顺序逐任务轮换。

## 指标

- `valid_count`：严格解析为四个已知操作及字符串参数的数量；
- `exact_count`：操作顺序与目标真值一致，且四步全部使用目标标识符；
- `correct_order_count`：仅顺序正确；
- `correct_binding_count`：四步全部使用目标标识符；
- `stale_source_binding_count`：至少一步复制正确或错误来源标识符；
- 以上指标分别按 `transfer_needed` 与 `target_sufficient` 报告。

## 第一模型继续条件

先运行 `qwen2.5:7b`。只有以下条件全部成立才运行 `qwen3:8b`：

- 四条件总体有效响应均不少于 15/16；
- `target_plan` 在 `target_sufficient` 上严格成功不少于 7/8，证明匹配预规划载体可用；
- `qcr_correct` 在 `transfer_needed` 上严格成功不少于 7/8；
- `qcr_correct - target_plan` 在 `transfer_needed` 上至少为 4/8；
- `qcr_correct - qcr_shuffled` 在 `transfer_needed` 上至少为 4/8。

任一条件失败则顺序停止，不增加歧义、不改顺序、不移动阈值。通过只支持“历史轨迹在当前抽象载体上具有超出额外目标预规划的边际值”；失败只否决当前归因载体或该模型上的历史特异性，不直接反驳 QCR 的公开系统结果。

## 安全与解释边界

实验只访问本机 Ollama。没有外部网络、真实工具调用、文件/数据库业务写入、安全过滤器、攻击载体或策略绕过内容。Recorded 结果不构成交付级证据。

# v111 研究地图

## 候选分解

对每个候选更新，可定义四个量：更新器是否提出、验证器估计的增量、提交决定以及密封测试中的真实增量。正确拒绝有害更新是选择器真阴性，错误接受是伪阳性；评价提交策略需要同时计入两者，而不能只报告已接受版本的最终得分。

## Run 内精确重复

- v048 已检查自演化执行框架，明确区分更新器能否产生有用持久更新与求解器能否从更新中受益。
- v048 同时记录“Self-Evolving Agent Harnesses via Gated Semantic Quality-Diversity”把更新提议、确定性归因、显著性检验和密封测试分离，用验证后提交决定何种更新应保留。
- v055 已关闭自适应候选搜索复用验证信号，v100 又关闭赢家诅咒与选择后校正的重复实例。

## 直接系统

- [HarnessBank](https://arxiv.org/abs/2607.13683) 针对贪心候选选择、噪声自反馈、搜索塌缩和过拟合，维护语义执行框架基因库，并以门控执行框架筛选过滤大量后代候选。
- [Harness Updating Is Not Harness Benefit](https://arxiv.org/abs/2605.30621) 已分别测量产生更新与利用更新的能力，并将低收益分解为未激活相关工件或激活后未遵循。
- [Living-Harness](https://arxiv.org/abs/2607.26598) 已把完整轨迹与评价信号转成受限、证据支持的持久更新。

## 计算归约

若评价器拥有每个接受/拒绝候选的真实反事实收益，则这是标准二分类、选择性决策或后悔评价；若真实收益只对已接受候选可见，则必须额外执行被拒候选，回到密封测试与候选筛选。无论哪种情况，“把正确拒绝计分”都没有改变自演化更新计算。

## 结论

v111 与 v048 是精确问题重访，并被 HarnessBank 的门控筛选进一步直接覆盖。不注册实验或 Seed。下一 frontier 不再扩展执行框架更新的提议—验证—提交链，重新寻找不同于状态、训练信用和自演化选择的分析单位。

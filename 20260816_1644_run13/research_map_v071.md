# v071 研究图谱

## 现象定义

固定任务、工具说明、模型、提示和模型生成动作，只对同一动作进行两种离线解释：

- 严格执行器：工具名、参数名、类型、枚举和标识符都必须精确符合契约；
- 宽容执行器：只允许意图保持且唯一的机械修复，包括参数别名归一、枚举大小写/分隔符归一、带前导零标识符的类型恢复、规范化资源代码和补入任务已明确要求的标准策略。

主指标是 `compensation_gap = forgiving_success - strict_success`。它不比较两个模型采样，也不真正执行任何工具，因此不受工具随机性、网络或副作用影响。

## 与当前 Run 的区别

- v033 研究字段编译，v034 研究事务/假值，v035 研究参数名缺失；它们关注模型能否生成动作或解释状态，没有把同一生成动作在严格/宽容后端下做配对归因。
- v044 的执行差分见证被实验否决，关注声明与真实状态变化；本版只测执行前动作如何被后端机械纠错。
- v069 关闭随机工具故障与方差归因；本版执行器完全确定，研究的是系统性补偿而非随机性。

## 当前证据状态

先运行最小现象实验。只有后端补偿差在至少三个修复族中稳定出现，才进一步检索“环境辅助、API 宽容度与能力幻觉”的直接工作并构造方法；否则不把宽容执行器包装为新贡献。

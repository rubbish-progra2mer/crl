# v157 研究图谱

## VAKRA 的跨域现象

- [VAKRA](https://arxiv.org/abs/2608.12282) 提供 62 个领域、8,000 余个本地可执行接口，以及 2--5 跳的接口链和接口—文档检索混合链；预测工具调用会重新在真实数据库后端执行，并允许多条有效路径。
- 同一底层数据被暴露成三类接口：9 个通用组合工具、26 个展开函数工具和每样本约 116 个查询特定端点。最强配置分别得到约 50.0%、51.0% 和 70.4%，且论文报告模型排名随接口范式反转。
- 多数模型随推理跳数增加损失超过 50%。跨源任务中，从文档抽取实体再填入接口参数的准确率在 58 个标注案例上仅为 13.79%--32.76%；更一般的跨跳参数值抽取也远未饱和。
- 244 个多源样本带自然语言工具使用政策。政策使问题不可回答时，各模型成功率只有 1.7%--5.5%；论文观察到模型仍强行回答。政策无影响时明显较高，说明约束解释而非一般任务难度是独立压力源。
- 论文把错误主要定位到实体消歧、跨源落地和模式对齐等语言中介步骤，而不是调用传输本身；但固定 ReAct 运行框架不能识别某一接口重构机制的因果优势。

## 接口抽象与工具设计先行

- [《工具接口设计的艺术》](https://aclanthology.org/2025.realm-1.5/) 已把业务状态机暴露为工具、把局部推理委派给语言模型工具，并以接口结构改变长程任务表现。
- [Agent-First Tool API](https://arxiv.org/abs/2605.10555) 已把搜索、解析、预览、执行、核验和恢复编成语义接口，并给出规范化工具契约。
- [工具制造与自演化智能体](https://arxiv.org/abs/2607.08010) 已把重复标准流程编译为经过验证、版本化的工具，运行时直接调用并在必要时回退到代码生成。
- [DocsChisel](https://arxiv.org/abs/2608.10037) 已按目标模型、任务域和失败轨迹自适应增删、改写工具文档字段；ToolDNA、PA-Tool 与当前 Run `v105` 又覆盖工具元数据共同优化和模式表面对齐。

## 政策、跨源依赖与 Run 内边界

- `v029` 已关闭把自然语言工具政策编译为能力—效果图、跨工具访问控制和禁止效果可达性检查；`v126` 又记录每次调用前的确定性范围、授权和默认拒绝决策。
- `v038` 已处理跨工具单位、尺度、时基和模式语义；`v050` 已关闭动态依赖图上的逐步查询规划。
- `v121` 已处理根据任务价值与成本选择工具子集；`v156` 刚关闭逐参数来源绑定、充分性判断和跨应用定位。

## 结论

VAKRA 是适合后续方法验证的强基准，但“查询特定宏端点”“按模型挑接口粒度”“把政策隐藏到允许工具集”“显式跨源参数映射”分别被接口设计、工具制造、工具选择、确定性访问控制和依赖规划覆盖。将这些模块并置不能产生新的改变计算。

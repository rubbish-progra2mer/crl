# v024 研究图谱

- `Vero`（arXiv:2608.13522）是仓库级代码—证明联合生成基准，含 43 个多模块 Lean 4 实例、743 个接口和 2,705 个规格。
- 论文报告所有配置都在运行前半程达到最终实现规模，此后证明文本持续增长；作者据此判断智能体把实现当作固定脚手架。
- galoistools 个案中，Claude Opus 4.8 留下 76 个暂存文件和 42 个不同引理尝试；一个桥接引理出现 16 次。作者指出若把自写定义改为与参考函数同形，该等价引理可直接成为 `rfl`。
- Vero 公开仓库提交为 `4bc6e4b3646c7c781cc7c5a72ba5f71978568055`。本机能取得 Git 对象，但 Windows 工作树检出会被多个 `Spec/Aux.lean` 路径的保留设备名限制阻断；公开树中也没有论文所分析的完整模型暂存轨迹。
- `P3`（arXiv:2608.09277）已经把程序草图、证明草图、桥接谓词、不变量与辅助引理统一规划，然后再展开实现和证明。
- `P3` 明确把“反复局部修复仍无法关闭义务”或“出现计划外算法、不变量、结构引理”定义为计划级失败；此时返回规划阶段修改分解和证明结构，再重新展开程序与证书。
- `P3` 在三个基准、四种前沿模型的全部 12 个组合中均优于程序后证明基线，提升解决率 4.6–11.2 个百分点；联合程序—证明规划相对仅实现规划提升 3.3–8.3 个百分点。

结论：用重复证明失败触发实现回退只是 `P3` 计划级失败检测的一种特例信号，核心控制流、修改对象和重展开时点已被覆盖，不能独立晋升。

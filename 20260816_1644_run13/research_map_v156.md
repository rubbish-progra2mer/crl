# v156 研究图谱

## 新经验入口：散落个人信息定位

- [《SPIEval：跨应用散落个人信息上的工具智能体评测》](https://arxiv.org/abs/2608.10692) 含 250 项任务、4,335 条虚构记录、10 个应用和 21 个工具；单项任务平均涉及 17.3 条相关记录与 6.2 个应用。
- 结果按每页最多 5 条分页；应用内工具支持子串、正则、模糊及字段检索，全局工具只支持子串。在 18 个模型配置的 126,279 次检索调用中，普通子串占 98.5%，正则与模糊合计不足 2%，字段检索只占 9.5%。
- 所有模型在失败任务上的检索量都低于成功任务，常在找到一条貌似相关的记录后停止。去除分页只把平均成功率从 35.5% 提到 36.0%；把全部相关记录直接放入提示则从 35.5% 提到 66.8%。这把主要瓶颈定位到相关信息的查询与定位，而不是翻页预算。
- 失败标注中 79% 是参数值错误，缺少强制参数占 6%，错误工具较少。该标签说明执行参数未被正确支撑，但不能独立区分错误来自查询、候选选择、跨记录整合还是最终复制。
- 评测采用精确金标工具与参数检查、每项设置 3 次运行和 50 轮上限，不依赖语言模型裁判。

## 最近邻方法族

- [S2G-RAG](https://aclanthology.org/2026.acl-long.901/) 已把结构化“是否充分／还缺什么”判断接到下一轮检索查询：缺口判断不是本版可独占的新算子。
- [ProvenanceGuard](https://arxiv.org/abs/2607.01236) 在工具调用执行前检查调用内容是否由可追踪证据支撑，覆盖“参数必须有来源”的直接修复。
- [PACT](https://arxiv.org/abs/2605.11039) 把工具调用中的不同论元绑定到跨步骤证据来源，进一步覆盖参数级溯源而非只给整个动作附引用。
- 动态工具依赖检索与 JTPRO 已分别覆盖按执行依赖规划检索，以及针对错误工具／槽值实例化优化工具描述和提示表面。

## Run 内回忆

- `v050` 已关闭根据动态依赖图逐步生成检索查询的候选。
- `v081` 已对照边际信息效用、证据覆盖和显式充分性停止规则，关闭“证据不足就继续查”的通用计算。
- `v104` 已覆盖检索可见性、覆盖、顺序、停止和反事实检查。

## 结论

SPIEval 提供了强而新的跨应用经验现象，但自然机制——缺口驱动查询、逐参数证据绑定、竞争候选后再停止——均落入直接先行和 Run 内负记忆。剩余空间是针对该基准的组合与工程适配，不足以注册论文级 Seed。

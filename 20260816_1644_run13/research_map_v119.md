# v119 研究图谱

- [PACE-Bench](https://arxiv.org/abs/2608.14441) 包含 36 个基础任务、6 个物理领域和每任务 4 个目标环境，共 144 个源—目标对。所有方法在相同 20 次尝试预算下接收 Box2D 结构化诊断并输出修订后的 Python 设计。
- PACE-Bench 报告 Qwen3-14B 上 Reflexion 的完整基准成功率为 35.9%；GPT-5.5 在静力学子集达到 66.7%。公开分析把失败分为硬失败与设计固定、停滞、无向探索、晚收敛和预算耗尽。
- Vanilla 的设计固定率为 41.0%；ACE 的得分检索反复返回早期中等成功设计，使固定率升至 47.1%；Tree-of-Thought 的固定率接近零，但停滞率为 50.2%。这说明简单保守与简单增大差异分别卡在锚定和无向探索两端。
- 基准还公开精确环境参数变化。较大模型的六个比较中，五个变化仍在正负 5 个百分点内，最好的“变化公开”结果没有超过最好的“变化隐藏”结果；论文据此把瓶颈定位为机制重设计而非参数识别。
- 论文也运行了从零构造控制：Qwen3-4B/8B/14B 的 Pass@2 分别为 11.3%、12.8%、18.3%。因此无条件删除旧设计并不能成为强方法。
- [反例引导程序修复](https://arxiv.org/abs/2502.07786) 已用 MaxSAT 定位错误语句，把这些语句从程序草图移除，再由大语言模型补全；每次失败都把测试反例送回综合循环。
- [性质引导的大语言模型程序综合](https://arxiv.org/abs/2605.16142) 已把数值得分替换成可验证性质，失败时返回具体反例，并在规划启发式综合中以更少候选取得更强结果。
- 当前 Run v048 已记录受验证器约束的语义质量—多样性搜索：更新提议、确定性归因、显著性检验与密封测试分离，直接覆盖“固定时增加结构差异、探索时保留验证进展”的通用搜索骨架。
- [PACE-Bench 公开仓库](https://github.com/thunlp/PACE-Bench) 在本次审计时只有一个提交和 `.pace-bench-bootstrap` 占位文件；论文所述数据、任务和评价套件尚未实际出现在仓库中。

因此，最自然的“反例定位—删去可疑片段—草图重综合”已是直接程序修复方法；“失败后提高结构新颖性并由得分保留方向”又属于质量—多样性搜索。把二者移植到 Box2D 设计不能形成独立方法核，且当前公开工件不足以做公平复现。

# v049 研究地图

## 现象与评测证据

- *Benchmarking Reference-Free LLM Agent Robustness Under Schema, Policy, and Toolset Drift* 在 tau2-bench 零售任务上构造参数名、工具名和策略漂移，区分参考轨迹指导的上界与无参考适应。其结果显示盲轨迹回放相对静态基线在五个模型中的四个显著变差；论文把主要瓶颈归于隐藏状态重建和多个订单、产品、变体之间的分支选择，而不是简单的接口名映射。
  - https://doi.org/10.1109/ACCESS.2026.3696096
- *ReliabilityBench* 已把模式漂移纳入工具/API 故障注入，并用最终状态等价的动作变形关系评估智能体可靠性。
  - https://arxiv.org/abs/2601.06112
- *ToolMisuseBench* 提供模式漂移、超时、限流等可重放故障，并包含确定性启发式、模式错误修复和策略感知的基线智能体。
  - https://arxiv.org/abs/2604.01508

## 近邻方法

- *M3: Semantic API Migrations* 在不知道目标库内部实现和历史变更日志时，以概率程序综合建模函数行为，再用可满足性模理论代码搜索发现语义相似调用；“靠黑盒行为对应进行接口迁移”不是新的通用机制。
  - https://arxiv.org/abs/2008.12118
- A-Evolve 已明确提出在模式漂移下新增模式、修补解析器或生成版本化适配器，并用回归测试决定是否提交。
  - https://openreview.net/forum?id=9ypfISYVNZ
- *StructHallu-Drift* 已系统构造列重命名、类型变化和约束变化，评估结构化输出在模式演化下的语义失真。
  - https://aclanthology.org/2026.surgellm-1.22/

## 组合差分审计

候选把 M3 式行为对应、旧轨迹数据流、A-Evolve 式适配器与最终状态验证组合起来。每个核心步骤均已有直接来源；唯一新增绑定是把软件接口迁移应用到语言模型智能体轨迹。受控漂移研究又表明，接口正规化并不解决隐藏状态和分支选择，盲用旧轨迹会系统性伤害任务成功率。因此该组合没有独立、可辩护的方法内核。

## 结论

v049 不注册正式假设。模式漂移是可测现象，但“迁移旧轨迹”在当前形式下同时遭遇机制拼接和现象反证。

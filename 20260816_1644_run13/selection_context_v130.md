# v130 选择上下文

v129 关闭证据聚合、数字孪生、自适应停止和电子表格子图后，v130 从近期多学科论文流筛查 PACE-Bench、ScienceFlow、协议可识别性与轨迹复用。PACE-Bench 的机制重设计回到反例引导程序修复，ScienceFlow 的重锚定与预算控制回到检查点搜索和执行调度；协议可识别性则是 v061/v062 的精确旧前沿。QCR 是唯一对 v049“盲轨迹回放失败”给出新增大规模正向证据的路线。

QCR 的公开设计严谨地固定了检索和执行边界，但其支持写作者比来源-only 摘要多读取目标并多执行一次推理。v130 因而没有直接比较论文数字，而建立目标-only、调用数匹配的本地归因载体，并加入打乱轨迹负控。

第一模型结果没有支持历史特异增益：需要历史组四条件均为 2/8，两个差值都是 0；同时所有响应有效、绑定正确，目标充分组全为 8/8。派生分层又显示执行者通常遵循支持，而正确历史的支持写作者只在 2/8 例提取正确顺序。因此不能把失败归因于格式崩溃、目标绑定或执行拒绝，也不能把它外推成公开 QCR 的反证。

预注册继续条件失败后没有运行第二模型或调提示。最直接的修复是按显式状态变化确定性剔除拒绝动作；一般化后则与程序性记忆、状态图编译、失败经验适用性和轨迹边际价值门控直接碰撞。v130 以“评价控制有用、支持提取现象成立、方法差分不足”关闭。

`crl-active-diagnosis` 随后收集了非权威 facts-only 视图：FTS Recall 为 `READY`、语义索引未请求而为 `DEGRADED`，无陈旧来源或污染；当前版本只有本次 1 个成功 Recorded，全 Run 有 130 个科学版本、16 个 Recorded 和 3 个 Formal。诊断没有选择或杀死候选。主研究者据此只收紧下一步策略：当前负证据杀死轨迹复用盆地而非宽 Charter；下一版本优先验证跨模型稳定现象，再讨论方法。

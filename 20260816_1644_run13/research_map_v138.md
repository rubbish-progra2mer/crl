# v138 研究地图

## 工具架构与重复一致性

- [The Devil Is in the Interface: Evaluating How Tool Architecture Shapes Coding Agent Behavior](https://arxiv.org/abs/2608.11386) 比较六种编码智能体工具架构、三个执行模型和 11,700 条轨迹。Atomic 只是把 bash 已有动作重包装为有结构的原子工具；NLSearch 则由同一执行模型充当搜索子智能体并用 grep 等 bash 命令迭代检索；Python 接口允许把多个操作合并在一个可执行代码块中。
- 论文把 `pass^k` 定义为同一任务的十次试验中任取 k 次均成功的概率估计，并报告 Atomic 在三个模型上均相对 BashOnly 提升。该量仍由每个任务的成功次数决定，不单独识别“均值能力不变而运行内方差降低”。
- 当前 Run v069 已依据 τ-bench、ReliabilityBench、智能体评测随机性研究和广义化理论关闭重复执行、`pass^k`、任务内/任务间方差分解与可靠性曲面。故重新构造 `pass^k` 反例没有新计算。
- 论文已经把 Atomic 的候选机制直接定位为减少错误命令、破损编辑等环境交互错误；这与 SWE-agent 的智能体—计算机接口及结构化工具先行工作相邻，而不是论文之外尚未识别的新状态变量。
- 论文的效率定义是主轨迹累计输入/输出令牌和交互步数。NLSearch 使用额外同模型子智能体，但正文没有明确说明内部模型调用是否计入该口径；公开仓库链接在本版检索时返回不存在。因无法核实实现，不能声称论文漏计成本，也不能据此注册实验或否定论文结论。

## 错误—成本耦合与溯因

- [LLMs Don't Pay for the Jump](https://arxiv.org/abs/2608.14397) 提出 `∂E_cost/∂ε > 0` 的“成本耦合溯因”判据，并以固定权重变换器的令牌熵不依赖最终正确性为对照。论文自己承认当前只给出判据和可证伪预测，没有运行耦合架构实验。
- 论文给出的工程方向是推理时由预测误差持续驱动权重更新的神经形态硬件，并明确连接自由能原理和已有 Intrinsic Cost 机制。它没有给出文本/工具型大语言模型智能体中的新算法。
- 当前 Run v107 已精确审查同一论文：一旦把“错误有代价”转成现有软件可执行机制，只剩按损失、不确定性、核验成本和行动价值分配测试时计算；期望信息价值、风险敏感决策和自适应核验预算已有直接工作。

## 决定

两个入口均与当前 Run 的直接负记忆或论文自述先行机制碰撞。v138 不注册实验，不创建 Seed、Reviewer 或 Formal 证据；推进到结构不同的下一前沿。

# v130 研究图谱

## 目标工作与归因边界

- [Beyond Retrieval: Query-Conditioned Reuse of Long-Horizon Agent Trajectories](https://arxiv.org/html/2608.12847) 固定检索候选、最终选中轨迹、目标状态、执行模型、解码和工具预算，比较无记忆、来源-only 通用摘要、完整轨迹和 QCR 支持。
- QCR 支持写作者额外读取目标查询和初始观察，输出工作流不变量、需重新获得的绑定、适用条件和核验守卫；论文把支持合成输入/输出词元计入在线成本，不允许支持写作者私下调用环境或读取核验器。
- 论文在 2,391 个 WebArena、WorkArena 和 AppWorld 目标上报告 QCR 平均成功率 62.3%，比完整轨迹高 10.7 个百分点；大绑定变化下陈旧绑定错误由 46.9% 降至 10.9%。这些是公开系统结果，本地实验不复现也不否定它们。
- 论文明确说明四字段只是诊断性最小实现，不声称普遍最优格式；实验没有逐字段隔离，也没有目标-only、额外调用数匹配的支持写作条件。因而“历史信息本身提供多少边际值”仍需匹配对照。

## 本地 Recorded 实验

- 预注册计划：`experiment_plan_v130.md`。
- 实现：`workbench_v130/qcr_attribution_pilot.py`。
- 第一模型：本机 `qwen2.5:7b`，温度 0；16 个良性抽象工作流，四个条件，共 112 次本地推理调用。
- `transfer_needed` 的目标不显示四步顺序，正确历史含一次明确“被拒绝、状态不变”的动作和一个核验成功的四步后缀；`target_sufficient` 的当前运行手册直接给出顺序。
- 四条件全部得到 16/16 可解析响应，全部 16/16 使用正确目标绑定且没有复制来源标识符。目标充分组四条件均严格成功 8/8，证明任务解析、目标绑定和匹配预规划载体有效。
- 在需要历史的 8 例中，`direct`、`target_plan`、`qcr_correct`、`qcr_shuffled` 都严格成功 2/8；正确 QCR 相对两个匹配对照的差值均为 0，未达到预注册的至少 4/8。
- 派生定位显示，`qcr_correct` 支持笔记自身只在 2/8 例写出正确顺序，而执行者在 7/8 例采用支持笔记给出的顺序。主要失败位于支持提取，不是绑定恢复或支持采纳。
- 支持笔记多次回落到 JSON 枚举排列或把被拒绝动作混入顺序；前者与 v120 的受限解码表面形式/枚举偏置相邻，当前数据只能说明模式相容，不能单独识别因果来源。
- 按预注册顺序停止，没有运行 `qwen3:8b`，没有改提示、顺序族或阈值。

## 自然修复与最近边界

- 在当前合成载体中，结果已明确标记 `REJECTED: state unchanged` 和成功后缀；确定性删除无状态变化动作并读取接受序列只是日志解析，不需要新的语言智能体方法。
- *Living-Harness Is an Interactive-Agent Evolver* 已把轨迹与评价信号编译为受限程序性记忆和状态图；A-Evolve 已把诊断、更新、验证和条件提交组成执行框架演化闭环。v048 已据此关闭一般失败经验编译与工件遵循方法。
- v018 已记录任务相似度、失败类型、负迁移风险和目标侧验证对经验适用性的直接方法；QCR 自身又显式提供适用条件、重新绑定和核验守卫。
- v106 已记录固定上下文下的轨迹边际价值、留一反事实重放和上下文条件在线选择器。把正确/打乱历史对照变成部署门只会回到现有轨迹价值选择。
- v049 已关闭通过旧轨迹与接口映射迁移数据流的组合方法；QCR 的新证据说明目标绑定支持可以显著缓解盲回放，但不使“解析成功后缀 + 目标重绑定”重新获得新颖性。

## 结论

匹配目标-only 控制是解释 QCR 类系统的必要评价条件，本地小模型也暴露了“支持写作失败而执行者忠实采纳”的清晰分层。然而，自然修复分别退化为确定性轨迹解析、既有程序性记忆/状态图编译和已覆盖的轨迹价值门控。v130 不注册活动方法假设。

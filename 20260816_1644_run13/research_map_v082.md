# v082 研究图谱

## 相邻智能体工作

- *Revisable by Design* 把用户输入与智能体执行并发化，并按幂等、可逆、可补偿、不可逆动作设计最早冲突回滚；它研究用户中途改写任务后的动作修订，不研究工具结果事件的聚合语义。
  - https://arxiv.org/abs/2604.23283
- SUTRADHARA 在解码时增量分派工具调用以降低延迟，但没有评价增量、快照、替换与撤回型工具结果进入模型上下文后的语义正确性。
  - https://arxiv.org/abs/2601.12967
- 流式大语言模型综述区分输出流、顺序输入流和并发输入输出，但不提供工具事件到智能体逻辑状态的可靠性基准。
  - https://aclanthology.org/2026.findings-acl.498/

## 传统吸收关系

- 事件溯源系统把追加事件日志投影为可核验的物化视图；ESAA 已把该模式用于软件工程智能体的意图事件与项目状态分离。
  - https://arxiv.org/abs/2602.23193
- 增量自然语言处理长期把输入分期、输出修订和撤回作为显式增量单元及修订策略处理。
  - https://aclanthology.org/2023.sigdial-1.14/
- 因而“按已知流协议聚合成最终状态”不是新算法。v082 只有在大语言模型面对明确协议仍出现跨语义稳定错误时，才可能形成新的智能体界面现象；后续方法仍必须超越经典物化视图。

## Run 内最近邻

- v052：受理响应与未来完成事件；
- v060：轨迹压缩丢失开放义务；
- v065：用户改写目标后迟到结果污染新轨迹；

v082 不研究完成顺序、异步未来、压缩、取消或接口版本；唯一变量是同一有序结果流如何构造当前逻辑状态。

# v147 研究图谱

## 责任发布闭环

- [AppLooper：带虚拟用户反馈的可问责发布智能体应用工程闭环](https://arxiv.org/html/2608.14093v1) 连接应用所有者、开发智能体、虚拟用户智能体群、所有者意图模拟智能体、只读测试智能体与编排层。
- 所有者确认冻结需求、提供反馈、实际检查候选版本并保留最终发布权；所有者意图模拟智能体只使用已明确确认的要求和反馈，证据不足时弃权；虚拟用户结果始终标为模拟证据并与真人行动分开保存。
- 编排层把需求、反馈来源、界面目标、实现变化、复测结果、所有者检查和发布决定绑定到不可变候选版本。候选改变后，旧检查和旧批准失效。
- 正文只有引言、相关工作、系统概览与实现、结论四部分，没有实验、用户研究、基线比较或组件消融。论文描述了一个已实现的工程协议，但没有识别虚拟用户、意图复测、只读测试、版本绑定或人类检查中哪一项带来独立效果。
- 论文声称公开的 GitHub 仓库在本次审计时返回 `404`。这只记作公开工件可用性边界，不作为科研反证，也不影响下述方法碰撞判断。

## 计算归约与当前 Run 去重

- 冻结需求、来源—反馈—变化—复测—批准链和版本变更后的选择性失效，被 `v085` 的来源完整性、工作流卡、证据契约与受治理记忆直接覆盖。
- 虚拟用户的形成性发现及其人口群体适用边界，被 `v088` 的真人—模拟用户一致性、模型敏感性、群体校准误差和真实多轮行为缺口直接覆盖；给模拟结果加标签不能校准其外部有效性。
- 仅以所有者明确确认的意图进行复测，归入 `v116` 的不确定意图集合、等待/澄清和知识边界；它没有新增一个意图推断或取证算子。
- 所有者、角色、权限、责任、等待对象和最终行动权被 `v103` 的人机委派与责任移交协议覆盖。
- 独立测试、候选阈值、版本变化后重新验收和人类最终发布，分别归入常规回归测试、`v126` 的继续/阻断与提交授权，以及版本化发布门控。

因此 AppLooper 的承重对象是可审计生命周期编排。其组合具有工程价值，但没有超出上述组件的独立状态更新、选择规则或因果证据。

## 其他人类行为入口

- [并非所有干预都有效](https://arxiv.org/abs/2608.12582) 用八周被动感知研究中的 369 篇日志检查改变意图与后续行为；依赖他人的行为改善率只有 15%—22%，个体可控行为为 50%—63%。这是真实人类行为边界，但其干预单位是行为改变资源与社会依赖，不是文本/工具智能体的可执行协作状态，且样本为小规模探索性观察。
- [可审计的人工智能辅助研究写作](https://arxiv.org/abs/2608.10858) 使用版本封存、哈希来源、红线门控、跨模型角色分离、程序化组装和预冻结停止规则。它进一步证明审计生产链可工程化，但这些计算与 `v085` 的来源治理及当前 CRL 协议同构，不能注册为新方法核。

## 判定

`v147` 不注册本地实验。合成一个所有者、几个语言模型角色和版本账本，只会复现论文协议；没有真人比较或组件随机化时，实验既不能验证责任改善，也不能识别组合中任何一个机制。

# v001 问题定义：工具结果的状态语义混叠

## 当前研究问题

文本与工具型大语言模型智能体收到空列表、零影响行数、超时或“已接受”响应后，是否会把以下不同事实错误压成同一个二值状态：

- 查询成功但合法地没有结果；
- 调用明确失败且没有产生副作用；
- 请求已经发出，但副作用是否发生未知；
- 调用成功返回，但因版本、条件或目标不匹配而没有完成任务；
- 副作用已被环境确认。

候选贡献不是再做一个通用“重试提示”，而是检验工具观测是否需要把传输状态、执行状态、证据基数、副作用状态和可重试性分开表达，才能让代理选择正确的结束、重试、核验或修正动作。

## 价值与智能体特有约束

代理的下一步控制流由工具结果驱动。同一个表面空值可能意味着“没有匹配项”，也可能意味着“没有观察到结果”；同一个 HTTP 200 也可能只代表请求被接受而不是任务完成。错误二值化会导致无谓重试、重复副作用、假成功或错误结束。

## 当前边界

- 只研究文本与结构化工具返回，不研究图形界面或多模态工具。
- 首轮只测可由原始响应本身推出的事实，不向类型化包装器注入隐藏真值。
- 当前只是待反证候选，不是 Seed，不宣称新颖性。

## 直接反证条件

满足任一条件即杀死当前方法候选：

1. 强通用提示已能在跨表面模板上稳定达到与类型化契约相当的动作准确率；
2. 让同一模型先结构化解析原始响应即可吸收类型化包装器的增益；
3. 类型化包装器的优势依赖直接泄露正确动作，而不是分解原始可观测事实；
4. 最近先行工作已经以等价状态分解、同类对照和相同控制动作完整覆盖该问题。

## Independent Opinion

# 独立终审意见

**结论：通过，但属于范围极窄、杀死风险很高的研究种子。**  
依据本次提供的同字节材料，未发现能够推翻最小 Claim、阻止 v005 交付或强制再开科学版本的问题。该结论不等于论文级新颖性成立，也不支持 CEP 优于通用变形测试。

## 核心判断

1. **不同源评价依据基本成立。**  
   ToolSandbox 固定上游实现、原始测试以及干净状态差分，为“正确行为是什么”提供了不同于 CEP 构造的语义依据。故障适配器、匿名审计适配器和状态差分接入仍由本 Run 编写，因此这不是独立自然缺陷集，也不是完全独立的评价实现；但该限制已经明确披露，最小 Claim 也只绑定到这些适配器和25个具体持留故障，没有外推到真实缺陷分布。就正式 Seed 要求而言可以接受。

2. **最小 Claim 被现有绝对结果完整支撑。**  
   材料同时给出了逐方法总数、五类故障各5/5、五个工具族各5/5、五个干净项5/5，以及三类边界各0/5。由于覆盖内总数为25/25，各故障族和工具族的边际结果又全部满检，不存在被聚合平均掩盖的失败项。公平手写基线的计划逐字段相等及结果打平也被明确写入 Claim。这里的判断限于所提供的结果记录，并非对未提供的逐项原始文件进行重新审计。

3. **`base_repeat` 冲突已经消除。**  
   材料一致说明它是在另一份独立重置克隆上执行的单次名义复测；共享上下文中的连续第二次调用由独立边界终局处理，且 CEP 不执行该序列。二者不是同一种状态语义，因此 v004 的表面矛盾不再存在。

4. **“编译器”表述目前没有越过已披露范围，但证据只覆盖一个锁定实例。**  
   五字段仅生成精确数量、允许辅助类型、目标响应性和 `ambient_canary` 载荷不变性四类固定关系，并拒绝未知禁止因素。材料已经明确说明它不是一般策略语言，因此称为“有限域的最小契约编译器”是可辩护的。  
   不过，当前实验只证明一个锁定契约实例可以生成与手写计划相等的结果；它尚未证明改变 `K`、`n`、`A`、`D_target`、`I_payload` 后计划会正确变化。因而不能声称“五字段契约族的普遍编译正确性”。这不推翻当前精确 Claim，但应作为扩大实验的首要检查。

5. **手写基线打平已经杀死检测算法优势，但尚未完全吸收研究种子。**  
   剩余对象只能是：

   - 有限效应契约到关系计划的自动生成；
   - 匿名审计所需的信任前提和不可辨识属性清单；
   - 不允许消费端越过具体探针范围解释结果的覆盖记录协议。

   当前证据只证明编译计划能够达到手写计划的功能等价，没有证明它减少人工遗漏、降低维护成本或改善跨版本可靠性。因此这些只能作为值得验证的研究假设，不能作为已经成立的系统收益。以“研究种子”而非成熟论文贡献交付，尺度是合适的。

6. **未发现杀死精确 Claim 的反例。**  
   非恒等一一映射、双因素组合触发和共享状态第二次调用均被诚实记录为0/5边界；它们不属于最小 Claim，因此不是反例。相反，它们有效阻止了把目标响应性包装成身份正确性、把固定单次探针包装成序列或组合保证。

## 不阻止交付、但扩大实验必须解决的问题

- 对多个不同契约实例做差分编译测试，排除“无论输入契约如何都输出固定计划”的退化实现。
- 在真实服务或独立持留适配器上验证，降低同 Run 编写故障和审计适配器造成的构造偏置。
- 实际比较人工关系与编译关系的遗漏率、编写成本、维护成本和跨版本失效。
- 实现并验证消费端可执行的记录对象；当前 CSV、计划和汇总 JSON 更准确地说是“精确覆盖记录原型”，还不是带签名、失效、重测和拒绝语义的证书系统。
- 独立核验最近工作是否已经能够从相同契约自动产生同一计划、不可辨识清单及覆盖记录；若可以，当前增量即被完全吸收。

建议最终 Decision 明确写成：**允许 v005 作为窄协议型 Seed 交付；检测新颖性已经否定，编译收益和记录消费收益尚待决定性验证。**

# v006 独立审阅报告

## 审阅结论

仅依据给定的同字节审阅材料，我没有发现足以推翻最小可证伪主张、要求阻止 v006 交付，或必须先推进到新科学版本的具体反例、证据矛盾或静默放行路径。

v006 可以作为一颗严格限域、仍需扩大验证的研究种子交付。它目前证明的是有限合同—投影域内的编译正确性、不可辨识见证有效性和消费端失败关闭性，不是一般可监测性理论、检测优势、真实服务泛化或生产安全性。材料对这些边界的表述总体诚实且一致。

## 核心主张与证据匹配

最小主张与正式实验结果直接对应：

- 864 种合同—投影组合、1,440 个合同关系主张、零个候选—预言机分歧；
- 576 个不可辨识主张均有同观察、异真值见证；
- 6,048 次七类陈旧绑定变化全部被拒绝；
- 非一元合同的 0、2、3 三种计数均拒绝编译；
- ToolSandbox 四种合同形状、23 个变体上，候选与同信息手写计划逐项相同并均为 23/23；
- 消费面板与真实状态消费面板分别为 17/17 和 16/16。

这些数字在 Seed、实验计划和实验结果之间一致。尤其是手写计划完全打平没有被包装为正向检出率提升，而是被明确解释为“关系检测本身没有新颖性”。因此材料没有用外部面板支持其并未测量的主张。

## 独立语义预言机是否循环

独立预言机不导入候选实现，以隐藏输出、允许的匿名映射和观察分组直接计算主张是否在观察等价类中真值恒定；候选则使用闭式规则。这是两种不同计算路径。对“候选闭式实现是否符合当前有限形式语义”这一主张而言，它构成有效的差分语义验证，不属于用候选输出给候选自身贴标签的直接循环论证。

不过，它不是对模型真实性的独立验证。预言机与候选仍共享以下前提：

- 相同的三类投影语义；
- 二值隐藏输出抽象；
- 事件类型和数量完整可见；
- 一次调用、成对探针以及有限关系词汇；
- 同一 Run 对合同含义的解释。

因此，这一预言机足以支撑当前有限域内的编译正确性，却不能支撑真实审计投影一定符合该模型，也不能替代独立团队适配、真实服务或自然缺陷验证。材料已经明确披露了这一限制。

二值隐藏域对当前只依赖相等、不等和身份关系的公式具有合理的小模型直觉，但材料没有给出正式的小模型完备性证明。当前最小主张本身明确落在有限穷举域内，所以这不是交付阻塞项；若后续把结果推广到任意值域，应先给出证明或扩大穷举模型。

## 支持域与 v005 类静默漏检风险

三份核心材料对支持域的描述基本一致：

- 恰一个主效应；
- 三类目标义务：无、响应性、身份一致性；
- 两类载荷因素的任意子集；
- 目标和载荷各自采用三类投影；
- 序列、复合触发、异步、重试和多主效应均在域外。

1,440 恰好对应 864 个组合中全部声明的目标关系义务与逐因素载荷关系义务；576 个不可辨识主张又与忽略投影基线的 576 个错误一致。结合非一元拒绝、13 个合同差分用例、七类字段敏感性以及四个历史故障回归，当前证据针对 v005 的“合同被接受但义务没有进入检测路径”问题形成了实质性修复链。

材料没有显示仍存在某个已接受字段只改变散列而不影响语义的情况。合同版本只改变绑定而不改变探针语义是合理设计，不应被误判为字段无效。

仍建议在后续正式论文中增加一个显式的编译完备性不变量：

> 每个由原始合同直接导出的关系义务，必须且只能进入“已生成可执行关系”或“不可辨识见证”之一，二者并集等于原始合同义务集合。

现有结果强烈暗示实现已经满足该不变量，但把它写成直接检查项会比“唯一计划散列”和抽样字段敏感性更直接地封死 v005 类回归。这个表述增强项不阻止当前 Seed 交付。

## 消费者与失败关闭性

从材料所列条件看，消费者同时核对：

- 工具身份与版本；
- 合同、投影、探针目录、计划和证据散列；
- 记录摘要与模式版本；
- 记录总体状态；
- 请求主张非空；
- 请求主张属于合同、可辨识并已通过；
- 域外身份、序列和复合保证。

17 个差分场景还覆盖已通过主张篡改、不可辨识见证绑定篡改、未知模式、失败证据和空请求；6,048 个穷举绑定变异覆盖七类主要绑定。因此，在材料明示的威胁模型与请求模式内，没有可确认的静默放行路径。

这套消费者不抵抗恶意签发者：无密钥摘要可以被重新计算，证据散列只绑定引用内容而不证明其真实性，见证散列也不等同于消费者重新验证见证。Seed 和实现说明都明确否认了数字签名、信任根、重放防护、远程证明与生产授权，因此这不是主张—证据矛盾，而是后续部署必须补齐的安全层。

## 需要澄清但不阻止交付的形式化问题

Seed 使用

```text
w ≡π w' ⇔ π(w)=π(w')
```

描述观察等价，同时又允许两个见证世界携带不同但均合法的匿名重命名映射。严格地说，如果 `π` 被理解为一个固定且已确定的单射，稳定匿名下不同隐藏身份会得到不同令牌，身份不可辨识性的论证就需要把“未知映射”纳入可能世界，而不能只写成固定函数下的等值类。

材料中的预言机、见证字段和文字解释已经清楚表达了真正意图：投影类型规定一组允许的具体映射，不同可能世界可以携带不同映射，而同一世界的跨探针映射必须满足稳定性约束。因此这更像符号记法不够严密，并非实现证据中的反例。后续应把定义改为“投影类型及其允许映射族”，或者把映射环境显式纳入隐藏世界。正式投稿前应当修正，否则容易被误读为固定 `π` 下的错误结论。

类似地，“载荷忽略某因素”当前实际证据是有限成对探针上的相等关系，不是对该因素任意取值的全域非干扰证明。最小主张和限制章节已将其约束在有限、成对探针域内，但后续材料最好持续使用“已覆盖探针对上的载荷不变关系”，避免消费者把覆盖记录解释为全输入空间证明。

## 最近工作是否完全吸收方法增量

给定材料中的最近工作分别覆盖了：

- 部分观察下的知识与可监测性理论；
- 多轨迹超性质监测；
- 从已有测试或接口规格生成变形关系；
- 正式合同到可追踪测试；
- 工具调用合同门控；
- 智能体变形评价；
- 工具工作流的语义事务与回滚。

这些工作已经吸收了 v006 的各个基础部件，所以“观察等价”“二轨迹关系”“规格生成测试”均不能单独构成新颖性。材料对此没有回避。

仅依据所给最近工作，没有一项被显示为同时完成以下闭环：在源码不可见且审计字段匿名化的工具接入场景中，依据显式投影类型对合同主张做可辨识性闭包，将不可辨识项具体化为同观察、异真值见证，并把闭包结果、执行证据和下游接入请求绑定在一个失败关闭消费协议中。因此，当前窄组合尚未被材料中的单一最近工作完全吸收。

它仍有明显的“已有理论与测试技术的专用协议化组合”风险，而不是已经确立的算法突破。Seed 把这点处理为可证伪的后续杀死条件，是适当的。若一个通用规格变形系统仅增加投影参数便能无额外机制产生同样的闭包、见证和消费记录，这条谱系就应被杀死或大幅改写。

## 交付后必须扩大的问题

以下问题重要，但不应被误作 v006 当前有限主张的交付阻塞项：

- 用至少两个真实远程服务验证投影声明、事件完整性、调用归属和版本绑定；
- 由独立团队冻结合同与适配器，排除同一 Run 设计故障和标签的耦合；
- 使用自然缺陷而非仅由本 Run 构造的故障变体；
- 比较自动闭包与人工计划的遗漏率、编写时间和维护成本；
- 验证投影类型声明错误时能否被发现；
- 增加数字签名、信任根、重放防护和证据存储验证；
- 给出当前二值模型对相等关系公式的小模型完备性说明；
- 扩展到序列、共享状态、复合触发、多主效应、异步、重试与随机服务。

## 最终判断

v006 的证据能够支撑它实际写出的有限最小主张，独立语义预言机没有形成直接循环论证，支持域和消费端没有从材料中暴露出新的静默放行反例，且手写基线平局、外部有效性限制和恶意签发者边界均被诚实披露。

因此，我认为当前不存在阻止 v006 作为 CRL 研究种子交付的实质问题。需要继续扩大的是真实环境有效性、独立适配、人因收益、形式化记法和序列能力，而不是先用当前证据声称已经获得通用性、检出优势或生产安全性。

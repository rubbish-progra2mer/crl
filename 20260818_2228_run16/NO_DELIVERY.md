# Run16 无交付资格审计

## 审计结论

本次宽自主 Run 已达到诚实 `CONCLUDED_NO_DELIVERY` 的科研条件。理由不是运行时长、候选数、版本数、检索数或单个负结果，而是：在同一科学版本内完成真实回溯、三个正交问题族扩展、一次贡献形态变化，以及当前资源内所有已识别高信息量杀手检查后，仍没有候选同时保留论文级贡献差分、可运行实现、匹配强基线后的正向证据和可执行扩大路线。继续投入本次轨迹的最高概率结果是重新组合 2026 已公开组件，预期科研价值已不足。

该结论只关闭 Run16，不表示文本与工具型大语言模型智能体领域穷尽，也不证明未来新数据、新基准或新模型不会产生可投资方向。

## 实际回溯与正交扩展

1. 初始方法优先路线：`h-causal-replay-001` 的反事实轨迹重放和首次不可恢复步骤定位，被 Causal Agent Replay、CausalFlow、ELPO 与 AgentTracer 直接占据。只关闭该方法核，回溯到现象优先。
2. 作用域覆盖路线：`h-coverage-witness-001` 先在本地合成和 SGR-Bench 自然答案集上完成两个成功 Formal，证明错误否定现象真实；随后 CROWN-QA 占据完整性敏感负向推理的问题、形式化和评价，ToolGate 占据一般运行时合同门。成功实验没有被伪装成剩余新颖性。
3. 接口演化路线：`h-delta-contract-001` 在 24 个配对工作流上比较 latest、同信息完整差分提示、额外预算反思和局部迁移义务。四者成功率均为 0.8333，局部义务相对强基线增量为 0；共同失败需要 HyperAgent 已有的端口数据流绑定与缺口扩展。
4. 状态合同路线：`h-mutant-probe-001` 用 224 个官方合同和两个独立公开运行检查点完成两个 Formal。开放世界合同和未断言变化现象复现，但当前端点允许边界风险逃逸率 0.2722，高于预注册 0.25；对 65 和 40 个未断言通过运行的两套全覆盖人工核对均得到任务外可疑数 0，预注册实际得分扭曲主张失败。
5. 贡献形态变化：停止从通用验证机制出发造方法，改搜会直接改变模型或实现排序的评价失真。结构化本地检索保存在 `hypotheses_v001/searches/ranking-distortion-frontier-v001/`；最近公开工作已直接覆盖任务子集排序保真、重复运行随机性、长程可靠性排名反转、脚手架与环境漂移、检索期污染、成本最优规划和裁判排名保真。

## 必要高信息量检查

- 三个可运行研究实现均完成至少一个有效 Formal；Run 当前有 5 个有效 Formal。失败的 `delta-contract-screening-v001` 是指标契约机械错误，已用同等设置完整重跑为 `-r1`，不作为科学反证。
- 覆盖路线使用同信息、同工具、同补查预算强基线，并追加第二模型和公开自然答案集。
- 接口演化路线使用同信息完整差分提示与额外预算反思强基线，直接测量局部表示是否改变关键计算。
- 状态合同路线使用官方合同、官方公开运行、冻结风险变异、阴性元数据对照、第二独立运行检查点和全覆盖人工语义核对；未把 `unasserted` 偷换为 `unsafe`。
- 最近先行审计明确区分直接问题占据、组件重合和仍存范围；两次过宽 SCREENING 杀伤均通过后续 `parked` 事件纠正。
- 主动诊断 `post-mutant-replication-v001` 读取到最佳集合为空、六项选择背景完整、5 个有效 Formal、尾部实验前关闭数 0；没有脚本替研究者形成终局。

## 非评分证据向量

- 问题或现象是否真实：覆盖不足导致错误否定、接口演化数据流瓶颈、开放世界合同与合法未断言变化均有本地或公开数据支持。
- 最近先行后还剩什么贡献：覆盖路线只剩被 CROWN-QA 与 ToolGate 压缩的系统组合；接口演化剩余计算被 HyperAgent 占据；状态合同只剩已知开放世界事实，实际排序影响未出现。
- 关键计算是否明确改变：覆盖门明确改变提交规则，但问题与机制被直接先行占据；局部迁移义务没有改变成功率；端点允许边界未过风险线。
- 是否存在可运行实现：有三个实现，但没有一个同时具备剩余论文差分和正向杀手证据。
- 实验支持层级：全部仍为 Screening；没有可投资候选可合理升级为代表性支持。
- 是否经受匹配强基线：覆盖实现经受但被先行吸收；另外两个未显示所需增量。
- 本地结果能否桥接扩大实验：没有候选留下明确、未被最近先行占据且只需扩大规模即可验证的实现核心。
- 最大致命不确定性是否减少：已从“候选是否有效”减少为“本次 Run 是否还有未占据且本机可杀的方向”；第三次正交检索显示可执行排序失真方向也已有直接工作。

## 第三次扩展的直接最近工作

- arXiv:2607.12338：用 SWE-bench、AppWorld 与 tau-bench 的公开任务级记录研究多少任务足以保持成对决策与覆盖要求，直接占据任务子集—排序保真回放。
- arXiv:2603.23749：跨 8 个基准、33 个脚手架和 70 余配置，用中等难度任务子集保持代理排序，直接占据低成本排序保真。
- arXiv:2512.06710：用组内相关系数量化任务间与任务内随机性，并给出重复次数预算，直接占据单次运行不可靠问题。
- arXiv:2603.29231：在 23,392 个 episode 上研究长程可靠性衰减和能力—可靠性排名反转，直接占据按任务长度重算排序。
- arXiv:2605.27898：在统一框架中执行 400K rollouts，分离模型、脚手架与环境对分数的影响，直接占据脚手架/环境评价漂移。
- arXiv:2606.05241：定义并测量深度研究代理的检索期污染及性能膨胀，直接占据公开基准搜索泄漏。
- arXiv:2608.11434：以 931 条人工标注移动代理轨迹测量裁判方法的代理排序保真，直接占据裁判偏差导致排名错误。
- arXiv:2511.02734：以 CostBench 研究动态环境中的成本最优工具规划，直接占据把成功率扩展为成本最优性的评价路线。

## 剩余前沿与终止边界

领域前沿仍然存在，例如未来可出现新的公开多模型逐任务运行、真实工具副作用人工标签、跨版本可复现实验环境或尚未公开的失败现象。但这些是未来独立 Run 的新起点，不是当前候选只差扩大实验的剩余工作。Run16 现有四个候选均缺少至少一项不可省略条件：贡献差分、关键计算增量、真实排序影响或扩大桥梁。继续沿本次轨迹探索没有一个已知、当前可执行且失败会进一步大幅压缩某个存活论文差分的杀手实验，因为当前没有存活论文差分。

因此，本次 Run 不形成 Delivery，也不以局部真实现象缩窄交付；形成 No-Delivery 是对现有证据的较诚实解释。

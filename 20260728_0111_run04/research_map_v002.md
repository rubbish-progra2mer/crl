# 研究地图

## 已观察失败与边界

工具智能体会跳过工具、忽略结果、编造结果或不必要地调用工具；仅看最终答案会掩盖不同失败类型。[[evidence:ev-p039-failure-core]] 更严重的是，智能体可能声称任务完成，而文本独立的环境终态仍显示未完成。[[evidence:ev-p040-failure-core]]

Failing Tools（ACL ARR 2026 May）把运行时失败扩展到状态化多轮环境，218 个场景中严格恢复口径的模型准确率均不超过 11.47%，且主导缺陷是缺少验证或恢复步骤。该来源是开放世界占用扫描，不在共享 Evidence 中；本版本只将其作为问题与比较器背景，不把摘要数字当作本 Run 实验结果。

## 干预阶段

工具结果返回后、模型选择下一调用前。v002 只改变下一轮可见工具集合，不改变模型、用户任务、错误消息、终态评测或工具实现。

## 使用论题、价值桥与机制需求

方法拟把失败标准化为 `KNOWN_NOT_COMMITTED`、`COMMIT_UNKNOWN`、`OBSERVATION_UNTRUSTED`、`CONFIRMED` 和 `TERMINAL_UNRESOLVED`，再按认识状态公开确认、重试、备用、询问或停止工具。目标是减少不明提交上的重复写，同时保持终态任务成功。

终态数据库或服务状态是适当评测；只让模型解释“我不确定”不是成功。[[evidence:ev-p007-terminal-state-evaluation]]

## 操作符短名单与来源复核

1. **完整菜单加原始错误**：模型看到所有恢复工具及原始 timeout。
2. **完整菜单加结构化认识状态**：信息与 Candidate 相同，但不隐藏任何工具；这是识别菜单贡献的最公平比较器。
3. **认识状态驱动菜单**：`COMMIT_UNKNOWN` 只公开确认/询问/停止；确认未提交后才恢复写与备用。
4. **契约状态提交**：ToolGate 用前后置条件决定可信状态提交，但缺少 schema 时后置条件可退化为 `True`。[[evidence:ev-p074-contract-state-commit]] [[evidence:ev-p074-missing-schema-true-postcondition]]
5. **任务级事务**：Cordon 用影子状态、effect outbox 与 commit/rollback 包住整个任务，是更重的强比较器。
6. **独立执行前 Reviewer**：可以修正调用，但主要位于副作用前，且增加模型延迟；不是失败后认识控制。[[evidence:ev-p049-operator-core]]

## 竞争方法内核

- K1：只把原始失败放回模型上下文。
- K2：加入同一结构化认识状态与“提交未知时不要重复写”的系统约束，但保持完整菜单。
- K3：在 K2 基础上动态隐藏认识上不允许的工具；确认后恢复。

K3 的唯一可归因差分是菜单，而非错误语义或提示。

## 自然语言处置

已完成 12 个探索工作单元，覆盖邮件、日历、支付、退款、工单、客户关系管理、采购、虚拟机、发布、营销、房间与转账；每个单元在初始写入已提交/未提交两种隐藏终态间交替。

首次科学执行 `workbench_v002/` 因模拟器在第二轮发出缺少 `tool_call_id` 的 `tool` 角色消息而产生 16 个 HTTP 400。其成功子集不能作科学判断。修正只改变接口消息角色，不改变任务、臂、提示、状态机或指标；旧目录保留，完整重跑写入 `workbench_v002_retry01/`。

完整重跑的探索结果：

- 原始错误 + 完整菜单：12/12 无违规，11/12 任务成功，11/12 在解决前调用确认；
- 结构化状态 + 完整菜单：12/12 无违规，11/12 任务成功，9/12 调用确认；
- 结构化状态 + 动态菜单：12/12 无违规，12/12 任务成功，11/12 调用确认。

K3 没有纠正任何 K1/K2 的安全违规，因为两个完整菜单基线已是 0 违规；它只比各基线多恢复 1 个任务。单个探索增量不足以说明动态菜单有独立且值得扩大投入的价值，尤其系统提示已经明确要求“模糊超时不得声称成功”。

因此 K3 kill；不通过削弱公平提示、增加诱导性不安全工具描述或只保留唯一正确工具来制造差距。K2 是有用工程提示，但不构成 v002 方法贡献。

## 家族可行性

运行时可机械实现动态菜单，且没有调用额外模型；工程可行性成立。科学可行性不成立：在当前强模型和明确失败信息下，基线自然执行确认，Target Failure 没有足够事件率供菜单产生可识别增益。

## Candidate 晋级审计

- Changed computation 清楚且可运行，但主要未经验证跃迁是“菜单限制优于同信息提示”。
- 决定性工作台没有显示安全差分，只显示 1/12 任务成功差。
- 若扩大样本仍可能估计小效应，但当前问题是是否值得投入扩大；已有信号不足。
- 不形成 Candidate，不设计 Promotion Development 或 Confirmation。

## 种子准备度审计

v002 没有 Candidate、正式实现、Promotion、Confirmation 或 Review Packet。真实负结果与执行失败均已保留；当前版本不能送审或交付。

## 唯一窄缺口

失败后缺少确认是公开基准中的真实现象，但在本工作台的明确认识状态提示下，当前模型已几乎完全恢复。要重新进入该节点，必须有一个自然产生、且在同信息强提示下仍保持高事件率的部署载体；不能靠人为诱导制造。

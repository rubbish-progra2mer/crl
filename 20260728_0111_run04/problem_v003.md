# 研究问题

## 用户意图

继续 fresh `run04` 的自主研究。v001 与 v002 的负结果保持冻结；v003 寻找一个具有真实选择性计算、可用下游执行标签验证、且不靠强行制造失败完成的窄方法种子。

## 使用论题与真实消费者

真实消费者是维护大型工具注册表的智能体平台工程师。较便宜模型从候选菜单中选择工具时，会受到工具排列和描述措辞影响；始终调用更强模型可提高成本，始终相信便宜模型则可能执行错误工具。

消费者需要一个部署时级联策略：用便宜模型上的、无需训练标签的扰动信号识别“本次选择值得升级”，把昂贵模型只用于高风险查询。真实价值是相对于始终便宜和始终昂贵两端，改善工具执行成功—费用曲线。

## 决策接口

输入为用户请求、同一候选工具集合及工具模式。先让便宜模型分别在原顺序和确定性逆序下选择一次，映射回规范工具身份；输出为：

- 两次同意：执行共同选择；
- 两次不同意：升级到昂贵模型，以固定的规范顺序重新选择；
- 无法解析：升级或拒绝。

该决策发生在任何真实工具副作用之前。方法不能访问金标准工具；最终评测通过确定性工具环境验证选择与参数是否完成任务。

## 价值桥与代理限制

主要结果变量是工具执行任务成功率与实际 API 费用；升级率、顺序一致率、选择准确率和校准曲线只用于解释机制。若一致性仅预测“模型是否重复自己”而不预测错误，或两次便宜调用加升级比始终昂贵更贵，则没有使用价值。

## 问题提交前占用扫描

1. P069 / Tool Preferences in Agentic LLMs are Unreliable（EMNLP 2025）直接证明描述编辑可造成大幅使用差异，功能相同工具仍有顺序偏好；原工作用双顺序控制测量偏差，但不把分歧作为选择性升级信号。
2. ProbeCal / Uncertainty Calibration for Tool-Using Language Agents 用真实执行标签训练隐藏表示探针，再选择 prompt 或轨迹；它是有监督强比较器，不能代表无需训练标签的部署信号。
3. PA-GRPO（ACL 2026）在训练中用跨排列优势和排列一致奖励降低选择偏差；它改变模型权重，v003 只做黑盒推理时级联。
4. TOOL-SHADOW v1 公开协议用排列 A/B 审计位置偏差，并明确是 pre-validation、not-for-deployment-gating；它是最接近的测量碰撞。
5. 固定预算 self-consistency 用同提示多路径聚合，是额外调用解释的必要比较器；v003 的唯一结构差分是使用“语义不变、顺序改变”的成对路径做选择性升级，而非多数投票。
6. 通用选择性预测与模型级联已经成熟；因此 v003 不能声称发明级联或一致性，只能主张在工具选择中，顺序扰动分歧是否是一个无需训练、可产生价值曲线的路由信号。

## 机制需求

- **Cause**：便宜模型的工具选择同时受请求语义和候选位置影响；在决策边界附近，改变顺序可能翻转选择。
- **Available information**：两次黑盒选择、候选规范身份、调用费用；无执行标签、logit 或隐藏表示。
- **Decision variable**：是否调用昂贵模型，以及最终执行哪个工具。
- **Predicted signature**：分歧子集的便宜模型错误率显著高于同意子集；只升级分歧应以低于始终昂贵的费用接近其任务成功。
- **Fair comparators**：单次便宜；相同两次便宜但同顺序；逆序双调用后固定取第一次；始终昂贵；随机按相同升级率升级；有监督 ProbeCal 只作信息上界讨论。
- **Kill conditions**：分歧不富集错误；便宜模型几乎无错误或几乎总分歧；昂贵模型在分歧集也不改善；两次便宜调用使总费用不优于始终昂贵；增益来自工具描述不公平、顺序泄漏金标准或任务只有位置标签。

## 文本/工具型大语言模型智能体范围

限定于结构化函数调用前的单步或多步首工具选择，候选工具有规范身份且顺序可无语义地置换。排除功能完全等价、没有正确性差异的 provider 公平问题，以及需要模型隐藏状态的白盒方法。

## 软约束

- 工作台先用至少四类工具域检查分歧—错误富集；Promotion 必须使用 fresh 请求与未见工具表述。
- 任务成功必须由确定性模拟工具结果判定，不能只比较模型文本。
- 费用使用服务端逐行 token usage 和当日官方价格复算。

## 硬排除

- 不根据工作台结果挑选有利工具顺序、阈值或任务；
- 不把同一请求的两个位置版本拆成独立样本；
- 不用多数投票掩盖二次调用成本；
- 不读取其他 Run 文件；只使用共享知识库、开放来源和本 Run 新材料。

# 研究问题

## 用户意图

在 fresh `run04` 中继续自主研究，不继承 v001 被杀死的反事实缓存门控。v002 仍以真实、可实现、可证伪的文本与工具型大语言模型智能体方法为目标；正常负面结果可以接受，不为完成 Commissioning 而强行交付。

## 使用论题与真实消费者

真实消费者是运行带副作用工具的智能体平台工程师。工具在运行时可能超时、静默不写、返回陈旧数据、模式漂移或产生相互矛盾的观察。现有智能体常在收到失败或模糊结果后继续自由选择全部工具，因此可能跳过确认、对不明写入直接重试、过早切换备用提供者，或在状态仍未知时声称完成。

消费者需要的是：在不把完整恢复策略写死为业务工作流的前提下，让模型仍负责语义任务规划，但把失败后的可选动作限制在当前“认识状态”允许的集合中；真实价值是提高终态任务完成率并减少不安全恢复，而不是仅让失败解释听起来更好。

## 决策接口

输入包括用户任务、当前已公开工具模式、实际工具调用与返回、运行时产生的失败类别，以及可用的确认/读回/备用/重试工具。输出是下一轮向模型公开的工具集合和一个结构化恢复状态：

- `KNOWN_NOT_COMMITTED`：有证据表明写入未发生；
- `COMMIT_UNKNOWN`：请求可能已提交但响应不足以确认；
- `OBSERVATION_UNTRUSTED`：读结果可能陈旧、损坏或矛盾；
- `CONFIRMED`：独立确认支持目标状态；
- `TERMINAL_UNRESOLVED`：在预算内无法消除不确定性。

该接口位于一次工具结果返回之后、模型决定下一动作之前。它不读取金标准终态，不替代正式实验中的独立终态评测。

## 价值桥与代理限制

主要结果变量是环境终态任务成功与安全违规率；安全违规包括在 `COMMIT_UNKNOWN` 状态下再次调用同一非幂等写工具、在主调用结果未知时提交备用写入、以及未确认状态却报告已完成。工具调用数、模型调用数、时延和费用是成本变量。

恢复步骤命中率、错误分类准确率和最终文本校准只能解释机制，不能单独支持价值 Claim。终态检查必须与 Agent 隔离，避免把评测 oracle 暴露给方法。

## 问题提交前占用扫描

1. **Failing Tools: Benchmarking LLM Agent Recovery Under Runtime Tool Failures**（ACL ARR 2026 May，https://openreview.net/pdf?id=j7YsSnA64D）：系统注入 availability denial、staleness、silent no-op、corruption、schema mismatch、disambiguation 和复合失败；218 个场景中所有模型在严格恢复口径下不超过 11.47%，主导失败是缺少验证或恢复步骤。它定义问题与评测路径，但没有提供一个改变模型可见动作空间的恢复方法。
2. **Cordon: Semantic Transactions for Tool-Using LLM Agents**（arXiv:2606.17573）：以任务级事务、影子状态、effect outbox、提交/回滚和审计约束多步副作用。它是强系统比较器；v002 不声称事务语义或回滚保证，目标是更轻的、单次失败后认识状态驱动的工具可见性控制。
3. **ACRFence: Preventing Semantic Rollback Attacks in Agent Checkpoint-Restore**（arXiv:2603.20625）：记录效果并对恢复执行 replay-or-fork，直接覆盖 checkpoint/restore 造成的重复不可逆效果。v002 排除 checkpoint replay 攻击，聚焦普通在线工具返回失败。
4. **ScopeGate: Capability Gates Are Not Authorization**（arXiv:2606.28679）：逐调用执行 scope、authorization、金额上限、幂等和 default deny。它控制权限与值授权；v002 的差分是失败后的认识状态与恢复动作顺序，而不是静态授权。
5. **ToolGate**（arXiv:2601.04688）：用前置/后置条件决定调用和状态提交；缺少 response schema 时来源实现约四分之一工具的后置条件退化为 `True`。它是契约状态比较器；v002 不把未验证结果提交为可信状态，而是动态公开确认或停止动作。
6. **动态工具检索/菜单工作**：检索、图规划和自适应 shortlist 已决定正常任务中“看见哪些工具”；它们必须作为组件碰撞处理，但没有把工具菜单绑定到失败后的认识状态。

占用扫描结论只是当前检索结果：最近完整事务和权限系统已经拥挤；唯一仍可检验的窄节点是“认识状态驱动的恢复工具菜单”是否能以更小运行时改动改善失败轨迹。未发现碰撞不等于新颖性证明，Candidate 前仍需四视图最近先行检索。

## 机制需求

- **Failure cause**：模型把模糊工具返回当作普通自然语言上下文，并继续在不受限的动作空间中规划；失败类型所隐含的允许动作顺序没有进入执行控制面。
- **Available information**：原始调用、工具声明的副作用类型、标准化失败类别、当前确认工具是否存在、调用预算；不能使用目标终态标签。
- **Decision variable**：下一轮向模型公开哪些工具，以及是否允许恢复状态前进。
- **Changed computation**：把运行时失败映射为显式认识状态，并据此重编译工具菜单。例如 `COMMIT_UNKNOWN` 只公开读回/确认/询问/停止，不公开同一非幂等写或备用写；`KNOWN_NOT_COMMITTED` 可公开安全重试/备用；`OBSERVATION_UNTRUSTED` 只公开刷新/交叉验证；确认后恢复普通任务菜单。
- **Predicted signature**：相同模型、提示、任务和失败注入下，方法应首先增加必要确认动作、减少禁用恢复动作，随后改善终态成功或降低安全违规；若只改变文本解释而不改变真实调用或终态，则机制失败。
- **Fair comparator**：同一失败分类器和同一结构化错误消息，但始终公开完整工具菜单；另有仅提示“请谨慎恢复”的自然语言基线，以及 Cordon/显式事务能运行时的上界或差分讨论。
- **Kill conditions**：完整菜单基线已自然完成确认；菜单限制只让模型卡死或过度拒绝；增益完全来自把金标准恢复路径编码进菜单；错误分类一变就崩溃；在 fresh Confirmation 上不改善终态/安全；或最近工作已实现同构状态—菜单控制。

## 文本/工具型大语言模型智能体范围

限定于结构化函数调用或模型上下文协议式工具智能体，以及可以标注读/写、幂等性和确认工具关系的运行时。排除具身机器人、多模态界面、并发多 Agent 事务、checkpoint replay 和要求完整业务工作流预编码的系统。

## 软约束

- 优先使用可公开复现的合成状态化工具环境，场景至少覆盖静默不写、响应丢失式提交未知、陈旧读和显式未提交错误。
- 模型数量与场景规模由当前窄 Claim 决定；单模型若不足以排除提示偶然性，不得省略第二模型或独立载体。
- 任何方法增益必须同时报告被隐藏工具数、额外确认调用、任务完成、违规、模型/工具调用和时延。

## 硬排除

- 不把失败分类器的金标准标签直接提供给方法；Development 可用规则化注入器产生部署可见的标准错误码，但 Confirmation 必须含映射扰动或未见组合。
- 不把“只剩唯一正确工具”作为全部实验；至少保留两个认识上允许但策略不同的合法动作，测试模型仍需规划。
- 不把 Prompt、菜单与事务组件捆绑后归因给单一部件；必须有同错误消息的菜单差分消融。
- 不把合成 fixture sanity 当成 Promotion、Confirmation 或 Delivery 证据。
- 不读取其他 Run 研究文件；只使用共享知识库、开放来源和本 Run 新生成的材料。

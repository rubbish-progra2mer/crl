# 研究问题

## 用户意图

在 fresh `run04` 中自主选择一个文本与工具型大语言模型智能体研究问题，形成真实、可实现、可否证的计算变化；正常负面结果可以接受，不以赶制交付物为目标。本 Run 是 `MODE: COMMISSIONING`，研究真实性和出口标准与正式 Run 相同。

## 使用论题与真实消费者

真实消费者是部署“规划—执行”型工具智能体的平台工程师或服务运营者。面对语义相近的重复请求，他们需要决定：复用并适配一个已成功执行过的缓存计划模板，还是再次调用成本更高的完整规划器。

当前可观察限制是：命中缓存时只能看到当前请求、当前工具说明或契约、缓存模板以及轻量适配器生成的候选计划；不能预先看到真实执行结果或金标准计划。错误复用可能让智能体执行一个意图表面相同、但漏掉当前实例关键约束的工作流；过度拒绝复用则失去缓存的时延和费用价值。

## 决策接口

Implement 的输入是当前自然语言请求、当前工具接口与前置/后置条件、一个检索到的计划模板及其轻量适配结果；输出是 `REUSE` 或 `REPLAN` 决策，以及允许进入执行器的实例化计划。接入位置在缓存检索与模板适配之后、任何真实工具副作用之前。

它直接改变的真实决策不是“答案是否相似”，而是“当前实例是否允许沿用既有计算结构，还是必须重新规划”。

## 价值桥梁与代理边界

若一个执行前验证计算能在保留大部分安全缓存命中的同时，拒绝因实例约束变化而失效的复用计划，就可能在任务成功率与完整规划调用成本之间形成更好的折中。

本 Run 的可执行代理将使用带确定性工具前置条件、效果和终态判定的文本工具工作流，测量端到端任务成功、错误缓存复用、正确缓存保留、完整规划调用、模型调用、Token、费用和墙钟时间。该代理不能证明开放网页、持续变化的真实接口、不可逆副作用或任意自然语言约束上的生产安全，也不能把有限任务族上的结果外推为通用计划缓存正确性。

## 固定问题前的占用度扫描

扫描日期为 2026-07-28（Asia/Shanghai）。扫描先覆盖导致错误缓存复用的可干预因果节点，再选择仍可能开放的节点：

1. **缓存键与语义命中节点已被占用。** P071《通过测试时计划缓存降低大语言模型智能体服务成本》已经用高层意图关键词替代原请求相似度，并报告语义缓存的假阳性；2025 年的 AgentReuse 又用意图分类和请求差异判断复用。仅换 embedding、阈值或意图标签不构成本 Problem。
2. **模板抽象与轻量适配节点已被占用。** P071 已从成功执行日志抽取抽象计划模板，并用轻量模型按当前上下文适配。仅把历史轨迹压缩为模板或换一个适配提示不构成本 Problem。
3. **时间、资产和传感器参数的新鲜度节点已被占用。** 2026 年 AssetOpsBench 工作明确指出参数丰富的工业请求会使纯语义缓存失效，并研究时间语义缓存；本 Problem 不把时间戳或资产 ID 加入缓存键当作主要变化。
4. **缓存命中后的后台验证/更新已有邻近工作。** 2026 年 AgenticCache 在具身多智能体环境中用后台大模型验证和更新常见计划转移；它说明“验证缓存计划”不是空白概念，同时属于本工作区排除的具身载体，且没有在本次快速扫描中显示出约束级、执行前反事实敏感性计算。
5. **工具调用与结果提交契约已被占用。** ToolGate 对单次工具调用做前置/后置条件门控；Cordon 对多步效果做语义事务暂存与提交。它们验证调用或效果，不直接决定一个缓存计划模板是否对当前约束变化仍保持行为响应。
6. **经典基于案例规划是必须处理的上游。** 1994 年已有利用因果结构控制计划复用检索与重拟合的工作。后续最近先行检索必须直接核对其与本问题的关系，因此本 Run 不主张“验证计划复用”这一宽泛思想本身新颖。
7. **当前指向的开放节点。** 在本轮开放网络快速检索中，尚未发现把“当前请求的单个决策相关约束作成配对反事实扰动，并检查轻量适配后的缓存计划是否产生契约预期的计划差分”作为执行前复用门控的直接占用者。这个“尚未发现”只是问题选择依据，不是新颖性证明；形成 kernel 后仍须完成组件级、组合级、完整管线和可运行实现检索。

因此，本 Problem 只指向：**缓存计划适配结果对当前实例决策相关约束是否具有可观察的行为敏感性，以及该信号能否在真实执行前改善复用/重规划决策。**

## 机制需求

在选择 Promotion 载体、模型或具体特征之前，固定如下机制需求：

- **因果环节：** 高层意图相同并不保证当前实例约束相同；轻量适配器可能沿用缓存模板的步骤结构，却忽略一个本应改变工具、参数、顺序或分支的关键约束。
- **使用时点可得信息：** 当前请求、缓存模板、轻量适配结果、工具模式、工具前置条件与效果；禁止使用真实执行终态、金标准计划或测试集标签。
- **要改变的决策变量：** 从“命中即复用”或“静态契约覆盖即复用”，改变为依据部署时可观察的约束响应证据选择 `REUSE` 或 `REPLAN`。
- **预测机制签名：** 在只改变一个决策相关约束的配对请求上，错误复用基线更容易给出不变或契约不相容的计划；有效干预应优先拒绝这些有害命中，同时在改变不应影响计划结构的对照扰动上保持复用。
- **成本、权限和接口约束：** 干预必须在真实副作用之前运行；不依赖答案 Oracle；报告额外模型调用、Token、费用和时延；与使用同一抽取器/工具契约的静态门控比较，避免把结构化解析本身归因给 proposed delta。
- **决定性反例：** 若静态契约覆盖门已捕获全部错误复用；若配对扰动同样频繁拒绝安全命中；若收益只来自增加一次更强模型调用；若在未见任务族上消失；或若成功—成本折中不优于总是完整重规划，则本机制不值得晋级。

## 文本/工具大语言模型智能体范围

范围限文本请求、结构化工具模式和可确定执行的计划—执行环境。允许本地确定性模拟器与预授权 DeepSeek 作为规划/适配被试。不研究机器人、具身、多模态、传统控制，也不把执行恢复作为主要研究方向。

## 软约束

- 优先使用共享主环境与本地确定性执行。
- 对费用、调用次数、Token、墙钟时间和 comparator 公平性做完整记录。
- Promotion Development 与最终独立验证按任务族或工具模式族隔离；具体隔离在 Candidate 和 Experiment Plan 中预注册。

## 硬排除

- 不把更高缓存命中率、文本相似度或计划格式合法性当作最终结果。
- 不使用金标准计划、执行终态或人工测试标签作部署时复用决策。
- 不把更多调用、更多 Token 或更强模型偷换成机制收益。
- 不把测量协议本身作为 Delivery；只有真实 changed computation 改善端到端复用决策，才可能形成方法种子。
- 不声称已证明一般新颖性、生产安全或跨模型泛化。
